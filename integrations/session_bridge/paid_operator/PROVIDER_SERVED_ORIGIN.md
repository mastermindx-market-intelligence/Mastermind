# Served-origin metadata boundary in the incumbent runner

`provider_outcome.retained_origin_projection(provider_raw, process_raw, original=...)`
is a pure capture-correlation validator for the incumbent capability owner. It
does not authorize a read, authenticate a caller dictionary, invoke a worker,
or attest a served participant. Its `authorization` always remains
`REQUIRES_INCUMBENT_OWNER`; `authenticated` and `scientific_admission` are false.

The real owner must first authenticate its current private capability, qualify
the immutable same child/root/actual parent and pre-dispatch binding, and obtain
the exact settled result and original retained capture through its existing
qualified stable/private reader. It must check those joins again before
disclosure. This function supplies neither an alternative reader nor a generic
filesystem or historical-operation endpoint. Missing/unreadable capture must
not cause a retry or a different reader.

The closed `original` context contains root, parent, run_id, lease_id, account,
host, provider, requested_model, controller_attempt (one), support_sha256,
input_sha256/input_bytes and result_sha256/result_bytes. These remain facts
qualified by the real owner, not a caller's authentication assertion. The
projection checks the actual incumbent normal owned-process receipt and v1
provider receipt, exact selected scope, result digest/count and complete capture.
Its returned context digest permits exact outer-owner comparison; a digest
does not authenticate a supplied parent, study assignment or provider identity.
No process PID or input/result body is returned.

Even valid v1 receipts produce `UNAVAILABLE` with
`PROVIDER_TRANSPORT_FIELDS_NOT_RETAINED_V1`. Their model/provider are function
arguments and account is selected environment. Current canonical shim code
receives upstream headers/model/id, but its nonstream translator replaces the
model with the requested model and generates a new response id. The model-only
client then retains only assistant output text. Existing CLI diagnostics and
these translated values therefore cannot authenticate a provider response,
served model, provider account or provider turn. Assistant-text claims, extra
v1 authority-looking fields, launch attempts, an absent return code and caller
flags cannot upgrade this protocol.

A future, separately qualified producer must retain actual authenticated
provider response id, provider-reported served model, provider-authenticated
principal (only where the provider genuinely exposes it), original provider
attempt reference, submitted-input digest and captured-result digest. That
producer belongs at the incumbent authenticated transport owner, bound to the
same original operation/source generation, not a model self-report, new
registry, signer, scheduler or Runtime label. No missing field may be filled
from the requested selection. An unavailable account identity remains
unavailable even if server model metadata eventually exists.

Memory's closed blinded input/recipient-view owner and retained-disagreement
owner are separate contracts. This component does not implement or override
either, and does not change any of the five Memory verification flags, current
grant, admission, original operation, lease or retry rule. It has no install,
selection, live provider/study action or original-effect reconciliation.
