# Original-owner launch evidence — source integration

This uninstalled source extends the existing Fabric controller reservation,
process capture and authenticated bridge. `integrations/session_bridge/bound_launch_capture/fabric_attended_backend.py`
supplies the fixed original-owner Backend composition. The shared protocol stays
in `control_plane.executive_fabric_bridge_broker`; the existing service receives
the concrete backend by injection. Control/common do not import integrations. It does not enroll
production resources or arm Executive submission. Existing accepted runs and
records are unchanged. The sections below retain the earlier component history;
the current integrated source contract is described next.

## Current fixed Backend composition

The existing service receives independently qualified, typed owner resources.
Only its authenticated Control command can construct the single assignment
Backend, before original reservation and lease acquisition. It uses the same
process handle, canonical parser, immutable capture and exact cancellation owner.

keep its bytes and timestamp. Nonempty validation plans refuse before launch.

changed or partially released lease remains excluded; ACK alone is not release.
The source includes the actual interrupted-release self-lock correction.

The default factory remains closed unless the existing composition owner supplies
real Linux issuer, supported attended realm/profile, independently pinned binary,
finite HOME/TMP, isolation/canary, Capacity and dedicated assignment resources.
No JSON, environment selector or digest-shaped record creates that authority.
The existing original shutdown owner also needs qualification with the lane's
signal handler. No second dispatcher, registry, lifecycle or retry is added.
Source/inert verification and paid reviews do not prove production installation,
idle Wake or authenticated external-worker acceptance by the original Desktop.

## Original controller invocation component

`fabric_reserved_attended_launch.py` checks the complete original request against
its reserved Runtime/Fabric identities and canonical digest. It uses the existing
broker decoder and finite Claude preparer, preserves exact stdin and a closed
environment, and retains immutable validation commands only from the owner's
fixed allowlist. Its output remains preparation, not admission.

The executor patch factors the existing process/capture/cleanup block into one
shared function. The private `_run_reserved_attended_under_lease` component uses
that same function under the original controller's existing lease. It does not
acquire a second lease, add a registry, retry an operation or release custody.
It rechecks the existing in-process `ControlStartAuthority` after preparation
and owner checks, immediately before entering the process runner. Uncertain
cleanup retains the original reconciliation hold; proven exec failure keeps
the original errno/return-code behavior. Finite commands bypass the legacy
inherited environment and PATH augmentation.

The private owner-check callback is a composition/test seam, **not an admission
producer**. A callable or boolean establishes no realm, attendance, canary,
binary, schema or isolation evidence. No production factory or public CLI/RPC
selects this function. The original credential boundary now invokes the fixed
loader only after fresh Control, typed realm and physical-config checks, and
scrubs its transient parent mapping after launch. Authenticated remote owner
composition and actual realm/secret-canary producers remain necessary. The public bound path stays refused until those obligations have
an actual qualified implementation. Control authority is not serialized to an
ordinary SSH principal.

Finite Claude uses `run_dir/home` as its execution HOME. Its actual home
attestation must name that path. The fixed physical route's `provider_home`
continues to identify the credential realm and is checked separately through
the original exact v2 MiniMax canary. The exception cannot be selected by a
bare `passed:true`, a different realm/profile or an unbound home path. Legacy
fixed-home contracts retain their prior semantics.

### Original-handle invocation and once-only START retention

The original runner retains its actual argv, cwd, shell setting, environment
key set, prompt digest, non-secret environment projection digest, original
Popen timestamp and one owner-minted nonce. Credential values are neither
retained nor hashed. The private reserved begin seam binds the exact prepared
descriptor, original request/physical digests and a fixed START filename beside
the original terminal carrier before returning its same live handle. Existing
START bytes refuse before spawn; they do not establish positive first use.

`retain_owned_start_bytes` is a publication mechanic for an already validated
complete result. It checks the live original handle, generation, nonce, start
time and actual invocation against the supplied record. It also checks the
prepared non-secret environment controls, so unchanged key names cannot hide
a changed endpoint, model, HOME or TMP. It uses the existing owner-private
directory check and no-replace immutable inode publication, then fsyncs and
reads back the exact bytes. The early PRE_EXEC receipt keeps its schema and
8 KiB bound; complete retention has a separate 64 KiB bound and filename.

The first attempt consumes the live handle's publication opportunity, including
on failure. A failure holds the original lease for reconciliation, leaves the
same process/collector/finisher untouched and never resends. A successful
publication does not release that lease or assignment exclusion; the concrete
Backend must retain both through Control seal, actual worker denial and durable
Supervisor ACK. A worker-owned file is observation, not restart authority.

This delta does not assemble an attestation or authenticate evidence. The
actual producer must still invoke both complete START validators using a fresh
original-handle image, an independently pinned binary and actual qualified
realm/attendance/Capacity/workspace/HOME/TMP/isolation/canary/assignment inputs.
The runner reserves fixed private stdout/stderr/result files on the original
handle before spawn. START requires their live FD, path, inode, principal,
mode and single-link identity; caller filenames alone cannot satisfy it.
No factory, public bound CLI, profile, installed service or provider is enabled.

### Fixed original-owner capture and cancellation

`_begin_reserved_attended_under_lease(owned_capture=True, **kwargs)` takes the
run directory and result schema from the exact prepared descriptor. Its

and fixed BrokerPolicy: Control-owned run/store roots, actual WorkerGID and
pinned device/inode/mode/principal. This mapping is correlation and filesystem
observation; it cannot serialize or replace ControlStartAuthority. The public

The same collector threads tee to exclusive 0600, nofollow, single-link files
under pinned private logs/output directories. The original finisher proves
EOF and joins, full-stream byte count/digest, file fsync/readback, parent fsync
and FD closure. It calls the existing supported-Claude `_parse_cli_result`
and canonical schema validator by lazy import. Missing canonical code refuses
before spawn when capture is enabled. Invalid output stays invalid; failed
result bytes are preserved. Live writers, overflow, changed identity, close or
durability uncertainty remain unqualified and retain the original lease.

`owned_capture_collection(owner)` returns defensive mappings plus immutable

`stdout`, `stderr`, `capture`, `returncode`, `timed_out`, `finished_at`,

`stream_bytes`, `stream_sha256`, `file_bytes`, `file_sha256`, completeness and
error facts; `capture.files` retains the original file and parent identities.
This is an observation for a canonical result projection, not WorkerResult,
Git/artifact validation, UID sweep or assignment ACK.

`cancel_exact_owned_process` returns the unchanged raw group cleanup fields
and separate `cancel_receipt` with exact `run_id`, original `reason`, actual

Reason validation matches the real bridge and preserves whitespace exactly;
only the log label is normalized. One original cancellation entry is consumed
before signaling. The same successful request returns its retained observation
without signaling again; a changed reason or uncertain attempt refuses.
Completed-owner cleanup comes from its retained private record.
If the original child naturally exited before the finisher joins, a retained
already-exited/no-signal observation with passing original group cleanup does
not suppress its valid result. The cancellation request remains consumed.
Signaled, missing or uncertain observations still suppress result publication.

Assembly entry and durable publication have separate once-only fences. A

Successful capture/group settlement does not authorize the Backend to release
