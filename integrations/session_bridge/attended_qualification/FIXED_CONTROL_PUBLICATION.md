The canonical installed Control wrapper now calls `serve_installed_control`
after its existing sentinel exec and live process attestation. That entry uses
the existing `_serve_from_config` and Supervisor. No launchd target, argv,
socket owner, registry or lifecycle is replaced. The ordinary service CLI and
disarmed staging retain an empty attended tuple.

The fixed source tuple selects only `minimax.attended`, binding
`minimax-token-plan.claude-code-anthropic`, and proposed quota selector
`minimax-finite-read`. It restricts the original operation
`fabric-parent-native-operator-proof-01a11e90-v1` to normalized arguments digest
`36678c742b06b0ce04aa2b6acc46cb8aba9eba82c322ca960611e2cbb2580f56`.
The quota name is a source proposal, not an existing or admitted Runtime row.
The host must join its actual worker/account/quota through the existing Runtime
registry before claiming eligibility. Root and immediate parent remain
`01a11e90-4b5d-7f53-b966-8aaaad38701f`; neither is a Runtime Job ID or grant.

The sole host owns actual secondary/bootstrap/binary/realm receipts and the
existing `build_finite_worker_artifacts` call. After that call has returned the
exact qualified installed-generation artifacts, the Control delta is produced
by this existing source module:

```python
from ops.executive_os.attended_worker_definition import build_finite_control_delta

delta = build_finite_control_delta(
    definition_dir="/Library/Application Support/MastermindExecutive/config/fabric-minimax-finite-01",
    worker_artifacts=actual_artifacts,
)
```

`actual_artifacts` means the actual worker producer's returned bytes after
host qualification. It is intentionally not rendered here with substitute
release, manifest, binary, realm, definition or host digests. The delta contains
only `fabric_bindings_path`, the digest of those exact bindings bytes,
`fabric_attended_probe.worker_config_path`, and `fabric_bridge_armed=false`.
It enforces one `minimax-finite-01` owner and the exact socket
`/var/run/mastermind-executive/fabric-minimax-finite-01.sock`.

The renderer requires the completed exact installation and its actual manifest
and binary receipts. Therefore the installer's embedded `--control-config`
publisher cannot publish this later-produced delta during that first install.
Do not rerun the whole installation to solve this ordering dependency.

After the actual finite artifacts exist, the existing global configuration
transaction owner exposes a fixed staging operation:

```text
autonomy_control.py finite-control-stage --expected-sha <installed-release-M> --expected-control-sha256 <actual-current-Control-digest>
```

This operation checks the exact installed release, stopped services, Runtime and
UID quiescence, root-protected definition bytes, actual isolated principal and
matching manifest. It derives just the four fields above and uses the existing
global transaction, Control validator, atomic publisher and exact readback.
Primary worker bytes and all disarmed flags remain unchanged. An existing
different finite selection refuses replacement. No service, credential or
Runtime registration effect occurs here; no arm receipt is issued.

An uncertain publication retains its original transaction. The companion
`finite-control-stage-reconcile --expected-sha <M>` can prove an already-written
exact target from the existing archived preimage; it does not replay a write,
clear an unresolved effect or adopt another operation's transaction.

Stage with the existing autonomy/submit flags disarmed. The actual activation
entry remains `ops/executive_os/autonomy_control.py arm --foreground-only`
through its existing request parser, `execute_arm`, and `derive_candidate_configs`.
That owner requires current exact-install, acceptance, Gate B, provider readiness,
credential lifetime, stopped services and quiescence. It derives armed bytes,
publishes them in its existing transaction and produces the receipt that binds
their exact Control digest and release. Do not manufacture an ARMED receipt or
set `coo_foreground_only=true` on a disarmed candidate. CEO Submit has its own
existing admission operation; this source change does not grant it.
