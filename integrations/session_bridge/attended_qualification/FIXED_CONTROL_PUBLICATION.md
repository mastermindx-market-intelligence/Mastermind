after its existing sentinel exec and live process attestation. That entry uses
the existing `_serve_from_config` and Supervisor. No launchd target, argv,
socket owner, registry or lifecycle is replaced. The ordinary service CLI and
disarmed staging retain an empty attended tuple.

The fixed source tuple selects only `minimax.attended`, binding
`minimax-token-plan.claude-code-anthropic`, and proposed quota selector
`minimax-finite-read`. It restricts the original operation
`fabric-parent-native-operator-proof-01a11e90-v1` to normalized arguments digest
`36678c742b06b0ce04aa2b6acc46cb8aba9eba82c322ca960611e2cbb2580f56`.
The quota name is a source proposal, not an existing or admitted Runtime row.
The host must join its actual worker/account/quota through the existing Runtime

`01a11e90-4b5d-7f53-b966-8aaaad38701f`; neither is a Runtime Job ID or grant.

The sole host owns actual secondary/bootstrap/binary/realm receipts and the
existing `build_finite_worker_artifacts` call. After that call has returned the
exact qualified installed-generation artifacts, the Control delta is produced
by this existing source module:

```python

    definition_dir="/Library/Application Support/MastermindExecutive/config/fabric-minimax-finite-01",
```

`actual_artifacts` means the actual worker producer's returned bytes after
host qualification. It is intentionally not rendered here with substitute
release, manifest, binary, realm, definition or host digests. The delta contains
only `fabric_bindings_path`, the digest of those exact bindings bytes,
`fabric_attended_probe.worker_config_path`, and `fabric_bridge_armed=false`.
It enforces one `minimax-finite-01` owner and the exact socket
`/var/run/mastermind-executive/fabric-minimax-finite-01.sock`.

The publication entry remains the existing root-owned Control-config publisher
in `ops/executive_os/install.sh` (the `--control-config` source path), used only
