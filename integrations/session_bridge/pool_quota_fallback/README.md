# Quota-aware fallback within the existing Fabric router

The installed router uses weekly Grok Build first when Grok is selected, then
Cursor's exact `cursor-grok-4.6-high` alias after confirmed Grok exhaustion,
then an otherwise eligible model. Cursor Composer is a different model family.
Ordinary automatic routing keeps earlier economical candidates in their existing
positions; this does not make every task prefer Grok.

These exact-preimage patches archive the three already-installed repairs.
`native_remote.py` passes the qualified Cursor alias to the real harness;
`pick.py` preserves capability, quality, independence, role and budget gates;
`support_bundle.py` calls the existing policy reconciliation owner only for the
exact critical-policy mismatch. Active incompatible policy remains refused.

The live original operation `fabric-cursor-grok-native-seam-review-01a11e90-v1`
selected Cursor Grok on Ubuntu1, produced an actual START and complete rc0
terminal capture, and proved zero residual processes. The original assigning
Codex parent consumed its 4044-byte result and accepted the useful review once.
Per-run usage is UNKNOWN. Exact source, installation, test, result and acceptance
receipts are bound in `SOURCE_QUALIFICATION.json`.

This is prestart pool/model selection. A worker that has already started is not
silently moved: original settlement, retained checkpoint and a supported owner
continuation are still required. The separate advisory failover planner remains
uninstalled. No frozen operation, authentication refusal, uncertain effect,
credential, account or installed return-hook definition was changed.
