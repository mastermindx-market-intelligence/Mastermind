# L4 Slice 3 — Executive & Workspace Session Lifecycle Design

Revisions: installed `5420bb17` vs trunk `8d4e24d12` (`5420bb17` / `8d4e24d12` where lines shift; identical otherwise).

## Lifecycle facts
- **Resources & audiences**: `Resource::Acquisition` (`https://mcp.mastermind-x.com/workspace/read`), `Content` (`.../workspace/window/current`), `Executive` (`.../os/executive`, `auth.rs:34,59-83`). `read_programs` (`GET /workspace/programs/current`) uses `Resource::Acquisition` (`auth.rs:1169,1235-1244`), NOT `Executive`.
- **Lifetime decoding**: `parse_token` (`auth.rs:702-712`) bounds `/oauth/token` `expires_in` to `1..=604_800`s and sets `expires = Instant::now() + d` and `wall_expires = SystemTime::now() + d`. Auth0 API server-side TTL is `UNKNOWN` from repo source.
- **Persistence gate**: `Resource::persistent(self)` (`auth.rs:73-75`) is `self != Self::Executive && crate::native_refresh::enabled()` (`option_env!("MM_NATIVE_REFRESH_ENABLED") == Some("1")`, `native_refresh.rs:8-10`). Default builds keep all three resources in-memory only; `Executive` never requests `offline_access` (`auth.rs:463-467`).
- **What happens at `Executive` expiry**: `schedule_expiration` (`auth.rs:955-997`) sleeps to `min(expires, wall_expires)`. Because `Executive.persistent()` is `false`, it skips `refresh_one` (`auth.rs:846,967`), calls `inner.expire_executive()` (`auth.rs:217-221,985`), clears `inner.executive = None`, sets `executive_reason = "EXPIRED"`, increments `executive_generation`, and emits `mastermind-executive-auth-state` (`{available:false, generation}`, `auth.rs:306-318,987`). `Inner::status()` (`auth.rs:169-214`) inspects only `acquisition`/`content`, so `AuthState.status` stays `"signed_in"`.
- **Two expiry/401 bugs**: (1) `expire_executive` (`auth.rs:218`) checks `t.expires <= Instant::now()` without `t.wall_expires <= SystemTime::now()`, unlike `Inner::token` (`auth.rs:162-165`), so macOS sleep leaves `inner.executive = Some(expired)` on wake until a command runs. (2) Upstream HTTP `401` in `read` (`auth.rs:1100,1185-1188`) returns `Err("AUTHENTICATION_REQUIRED")` and records `ProgramsRead::response(401, None)` (`HTTP_FAILURE`), but NEVER clears `inner.acquisition` or emits `mastermind-auth-state`; likewise `executive_post_with_dispatch` (`auth.rs:2911-2912` / `2977-2978`) returns `Err("EXECUTIVE_AUTH_REQUIRED")` on `401` without clearing `inner.executive`.

## Design (a) sign-in-again
- **Rust (`app/mastermind_os/src-tauri/src/auth.rs`)**:
  1. In `Inner::expire_executive` (`auth.rs:218`), check `t.expires <= Instant::now() || t.wall_expires <= SystemTime::now()` so wall-clock expiry clears `self.executive = None` and enables `work_authorization` (`ELIGIBLE`, `auth.rs:256`).
  2. In `read` (`auth.rs:1170-1188`), when `inner.token(resource)` is `None` (`auth.rs:1170`) or HTTP status is `401` (`auth.rs:1186`), clear the rejected workspace token (`inner.acquisition = None` / `inner.content = None`), set `inner.reason = Some("NATIVE_TOKEN_EXPIRED")`, bump `inner.generation`, and call `emit(&app)` before returning `Err("AUTHENTICATION_REQUIRED")`.
  3. In `executive_post_with_dispatch` (`auth.rs:2911-2912` / `2977-2978`), on HTTP `401`, lock `state` and call `inner.clear_executive_with_reason("EXPIRED")` (`auth.rs:320-326`) so `executive_context`'s existing `if result.is_err() { emit(&app); }` (`auth.rs:3000` / `3066`) broadcasts `available: false` and unlocks `Sign in for work` (`NativeWorkAuthorizationControl.tsx:25`).
- **UI (`app/mastermind_os/src/projects/archive/ArchiveProjectsView.tsx` + `App.tsx`)**:
  - When both workspace tokens are cleared, `privateEntryState` (`App.tsx:5995-6011` / `6002-6018`) automatically renders `<AuthEntry>` with `"Your app access has expired."` (`native-partial-auth-presentation.ts:5,52`) and the working `Sign in` button (`auth_sign_in`).
  - For partial/in-view `programsReadReason === "AUTHENTICATION_REQUIRED"` in `ArchiveProjectsView.tsx:248-256` (wired from `App.tsx:5711-5714` / `5717-5720`), replace the generic `"Refresh Projects..."` hint with `"Your workspace session expired. Sign in again to load current projects."` and a `<button onClick={onSignIn}>Sign in again</button>` invoking `client.signIn()` (`auth_sign_in`, `App.tsx:3717` / `3722`).

## Design (b) persistence-if-allowed
- **Why `MM_NATIVE_REFRESH_ENABLED=1` broke sign-in**: When enabled, `Acquisition`/`Content.persistent()` is `true` (`auth.rs:73-75`), so `authorization_url_for_audience` appends `offline_access` (`auth.rs:463-467`) and `callback` (`auth.rs:755-758`) hard-requires `v.get("refresh_token").and_then(Value::as_str).ok_or("REFRESH_TOKEN_NOT_ISSUED")?`. If the Auth0 API or client lacks refresh-token issuance, `/oauth/token` omits `refresh_token` and step 1 of sign-in aborts with `"REFRESH_TOKEN_NOT_ISSUED"` -> `"TOKEN_EXCHANGE_FAILED"` (`auth.rs:621,795`). Also `native_refresh::finish_rotation` (`native_refresh.rs:26-28,122`) rejects unrotated tokens (`"REFRESH_TOKEN_NOT_ROTATED"`).
- **Concrete Auth0 tenant verification step (no secrets printed)**:
  1. Inspect Auth0 APIs (`https://mcp.mastermind-x.com/workspace/read`, `.../workspace/window/current`, and if Executive persistence is desired `.../os/executive`) via Auth0 Management API / CLI (`gh/curl` to `GET /api/v2/resource-servers/{id}` piped to `jq '{identifier, allow_offline_access, token_lifetime}'`): verify `.allow_offline_access == true`.
  2. Inspect the native client (`MM_NATIVE_CLIENT_ID`) via `GET /api/v2/clients/{client_id} | jq '{app_type, oidc_conformant, grant_types, refresh_token: {rotation_type, expiration_type}}'`: verify `grant_types` contains `"authorization_code"` and `"refresh_token"`, and `.refresh_token.rotation_type == "rotating"`.
  3. Live non-secret PKCE smoke check: run the `/authorize` -> `/oauth/token` exchange with `scope="mastermind.workspace.read offline_access"` and inspect only `jq '{has_access: (.access_token != null), has_refresh: (.refresh_token != null), scope, expires_in}'` (`has_refresh == true`).
- **Feature-gate & graceful-fallback shape**: Keep `MM_NATIVE_REFRESH_ENABLED` default-off (`option_env!("MM_NATIVE_REFRESH_ENABLED") == Some("1")`, `native_refresh.rs:8-10`); gate `Executive` separately behind `option_env!("MM_NATIVE_EXECUTIVE_REFRESH_ENABLED") == Some("1")` in `Resource::persistent` (`auth.rs:73-75`). In `callback` (`auth.rs:755-765`), if `refresh_token` is absent when `persistent()` is true, fall back to in-memory `token` (skip `native_refresh::store`) instead of returning `Err("REFRESH_TOKEN_NOT_ISSUED")`, so tenant misconfiguration never breaks sign-in.
