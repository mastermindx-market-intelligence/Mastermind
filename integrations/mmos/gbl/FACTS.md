| A9 | Usage/plan: weekly usage grant, "resets weekly", metered on the Cursor account; "Grok Bot usage draws from the same weekly pool as Cursor and the Grok apps"; on-demand overflow only if enabled; "A bot already working can finish past the monthly limit"; grants do **not** stack ("Grok Bot uses whichever one grants more weekly usage"). | **observed** (cursor.com/help/grok-bot/plans) | Cost ceiling = that Cursor account's weekly pool, shared with everything else on it. | A10 | Identity: "A Bot has no identity of own and cannot hold more access than the signed-in member." | A11 | No documented signature on outbound bot requests: nothing in the docs lets a third party verify a request came from Grok Bot (only Enterprise "inference hooks" are signed, and those verify model inputs to your own server). | **observed (silence)** (security-faq) | Inbound calls from Grok must authenticate with credentials *we* issue (OAuth principal / scoped token on our MCP edge). | A12 | Bot-to-bot: "They can pass context through direct messages, group chats, and shared files"; a primary bot "coordinates work with your other Bots." | **observed** (docs.x.ai/grok-bot/bots; overview) | The Chairman's "Secretary delegates to any bot" journey is natively supported *inside* Grok Bot. Our link only needs the Grok-side Secretary to reach Mastermind OS; Grok-internal routing is theirs. |
| A13 | Model selection managed by Cursor, not configurable per bot. | **observed 2026-09-14** (docs.x.ai/grok-bot/settings-and-notifications, per the foreman design §8) | No model routing decisions in our design. |
| A14 | Long-running custom MCP tool calls: timeout/behavior of a slow tool call inside a Grok Bot run. | **unverified** — docs silent.
