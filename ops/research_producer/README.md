# Pinned Research producer

The existing workflow invokes `launch.py` from a verified source archive. Its
default mode only checks configuration and placement; `--execute` reserves one
private directory for the original GitHub run and attempt and waits for that
run's isolated producer child. Existing run directories are permanent collision
fences. A new workflow attempt does not authorize recovering an older run.

The launcher needs qualified source archives, the prepared dependency runtime,
private original-host retention, and the existing owner's all-writer transition
before production activation. A valid manifest or process-result file grants
none of those permissions.

## Supported original-parent continuation

When its own child exits unsuccessfully with exactly one closed evidence
capture, the still-present parent may commission one isolated continuation.
Both source archives are checked again. The closed journal must describe an
acknowledged and observed BUILDING publication; unsupported or uncertain cuts
refuse before constructing a Store. The continuation then uses the pinned
Macro engine's live checks and single-attempt write transport.

Only previously unissued receipts may be created. The existing producer's fresh
census and exact-predecessor catalog compare-and-swap complete the same epoch.
The original journal and original exit code remain unchanged. A separate,
exclusive continuation journal binds the original capture, and the parent waits
for this child too. No manual resume command, saved process receipt, caller
boolean, replacement epoch, or recursive continuation is supported. Losing the
parent, a lost write acknowledgement, a conflict, or an interrupted continuation
requires same-operation reconciliation; it must never trigger replay.

After a successful tail, the child projects the public catalog and excerpts
from the bound private corpus. A local mirror failure remains a failing workflow
even if the remote catalog was completed. The continuation capture is retained
but grants no retry. No private journal, source PDF, or generation record is
published in that mirror.

COMPLETE describes the generation protocol, not full-text coverage. A receipt
recovered after the original full-text pass may leave a truthfully classified
missing derivative. The existing consumer coverage and freshness checks still
apply; this path does not waive them or materialize extra derivatives.
