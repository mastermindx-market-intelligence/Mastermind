# Same-operation private provider diagnostics

This prospective source path exports a closed diagnostic projection from one
producer-retained private Claude/GLM capture. It neither returns a worker result
nor accepts work. The existing `collect` and `result` contracts remain unchanged.
The command is explicit; normal status/result consumption never invokes it.

**Already-cleaned historical operations remain unavailable.** Earlier transport
cleanup removed their original packet, RC and remote process receipt. A remaining
capture basename/hash is insufficient. This implementation does not reconstruct,
backfill, adopt or retrieve those operations. Source delivery grants no historical
retrieval, installation, activation, retry or replacement authority.

An original owner with an actual current grant may use the incumbent binding
format and the new command after a separately qualified installation:

```text
fabric_task.py provider-diagnostics <original-run-id> \
  --root <verified-original-root> --parent <verified-original-assigning-parent> \
  --binding <original-delivery-binding.json> --destination <new-evidence-directory>
```

The source does not run this example or change any live operation. Caller labels
and the original-root environment check correlate custody; they do not authenticate
a user, transfer a lease or grant a new read. The existing original-reader source
qualification, verified account/SSH host, OS/tool grants and original commission
remain necessary. The initial implementation admits only its already-qualified
producer-bound ordinary GLM/plain lineage. Older missing lineage stays refused.

Before transport, the controller verifies its original source packet/log/support
pins, root/parent binding, exact released broker lease, terminal native lineage,
complete matching process/provider receipts and absence of an active/hold marker.
On the worker, the incumbent original reader revalidates the parent-bound contract,
original packet and published support generation, then reads the exact original
RC/process/provider/capture metadata/capture files. No path argument chooses a
capture. All private files require owner UID, mode 0600, regular type, single link,
complete size/hash and stable inode/path identity. Original process proof and
active/hold absence are rechecked around projection. Controller source and custody
are rechecked before and during exclusive receipt publication.

Only closed error enums, a closed DNS code, bounded HTTP status/turn counts,
booleans and unknown/null values cross transport. Prompts, message/tool content,
arbitrary error strings, raw environment, endpoint URLs, credentials and raw capture
bytes remain private. Typed `model_not_found` plus explicit HTTP 400/404 is reported
as typed evidence, never endpoint authentication. Prose alone establishes neither
DNS classification nor model refusal. Missing API status and initial-rejection
fields remain null. Reported initial rejection must satisfy the incumbent safe-event
predicate; it still does not establish absence of startup/MCP/provider effects.

Every diagnostic failure uses a fixed reason. Untrusted responses, SSH stderr,
parser exception text and raw diagnostic content are not published on refusal.
A diagnostic receipt records `acceptance=NOT_RECORDED` and
`producer_root_authenticated=false`.

For future failed operations only, the normal cleanup branch evaluates an internal
same-operation predicate against the physical private capture and original
process/provider receipts. A complete hash/size-qualified failure retains the
existing packet/RC/process proof beside the existing capture. Success, missing,
malformed, truncated, unsafe or active/held captures follow normal cleanup.
No lease, budget, routing, provider, account, qualification or retry rule changes.
