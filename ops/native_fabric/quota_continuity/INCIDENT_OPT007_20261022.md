Operation: `fabric-launch-reliability-20261022-c3`.
Chairman mandate: diagnose the supplied long-running native-session screenshots,

## Evidence and distinctions

The screenshot's R2 launcher exit 4 was a caller-side host-capacity hold before
launch, not a crashed provider worker. A subsequent read of the existing host
picker found ubuntu0 eligible. Its safety thresholds were not changed.

The original controller later launched `oi-opt007r2-20261022` on ubuntu0 at
2026-10-22 08:25:52 UTC. The retained launch log identifies the custom
`gate_wait_launch_r2.sh` watcher and four gate reads. The watcher checks every
120 seconds with a three-hour bound, then calls the existing `pool remote` path.
Its packet binds an existing workspace and forbids PR, label and merge actions.
This repair did not replay, cancel, move or modify that attempt or its workspace.
The observation is historical evidence, not a claim about its present state.

The old parser classified any nonempty `permission_denials` list as a terminal
permission failure. Its wrapper then changed a zero exit into rc 1 for any
non-success classification. The retained old outcome overwrites `command_rc`
with that wrapper exit; it does **not** independently preserve the original CLI
process exit. Therefore these records prove successful terminal events and the
misclassification, but do not retrospectively prove the original OS exit code.
The regression reproduces the zero-to-one conversion with an actual wrapper
subprocess and an explicit zero input exit.

A successful CLI terminal event is not proof that the task was correct. R1's
returned text described a pushed artifact and repeated unmerged blocks, while its
commission forbade the worker from performing the release actions. Parent review,
repair requests, holds and acceptance remain independently authoritative.

The project settings on the original worker workspace invoke Macro's SessionStart,
PreToolUse and Stop/hold guards. Current protected Macro already separates newly
minted `lane/<run>` workers from principal delivery sessions, but that distinction
does not cover a bounded repair in an existing linked `claude/*` lane. The companion
Macro repair addresses that completion-scope gap without changing tool admission.

## Repairs in this source operation

`candidate/provider_outcome.py` now treats denied requests as historical only
when a complete capture has exactly one final result, that result is last, the
original CLI exit is exactly zero, the terminal fields explicitly report success,
and there is no structured provider/terminal error. Ambiguous captures, actual
nonzero exits, authentication/billing failures, failing Stop hooks and malformed
denial data retain fail-closed behavior.

The existing outcome receipt includes bounded diagnostic fields:
`cli_command_rc`, `cli_subtype`, `cli_terminal_reason`,
`permission_denial_count`, and `permission_denials_role`. It never emits denied
commands, tool inputs, private reasoning or credential values. The original CLI
exit and the wrapper exit are now distinguishable.

There is no automatic acceptance, new retry condition, quota fallback, scheduler,
queue, lease change or permission expansion. Historical permission evidence stays
available for the parent's review even when the CLI completed successfully.

Companion source operation `fabric-worker-scope-20261022-c3` in Macro extends the
existing completion guard, not its source/tool admission. It recognizes bounded
C0/C1/C2 repairs only in existing linked host lanes with matching native executor
run, usage, outcome-path, lease and root metadata. SessionStart records that scope
in the existing guard state. Stop revalidates the same scope and source admission,
then returns the commission without requiring parent-owned PR/merge/deployment
work. The hold wrapper delegates to the same guard decision before probing a stale
unmerged hold. Missing/mismatched scope and principal/operator sessions retain the
normal delivery chain. This metadata is not an authentication mechanism.

## Prevention and acceptance criteria

1. Preserve the distinction between a host hold, absent launch proof, running work,
   CLI completion, result delivery, parent acceptance, merge and production proof.
2. Keep bounded workers on their commission's return boundary. Principal release
   obligations must not be injected into a worker forbidden to perform them.
3. Prefer existing typed request/status/result owners with frozen packet and actual
   root/parent identities. Do not author per-task watcher services or infer a safe
   host migration merely because another host is idle.
4. Use existing commission deadlines and explicit worker turn envelopes; natural
   language limits alone are not enforcement. Do not raise or lower fleet-wide
   budgets as an incidental incident fix.
5. A repeated unchanged refusal requires a material diagnosis or independent lane,
   not another frontier-model polling cycle. Host safety gates remain enforced.
6. Production acceptance needs the merged bytes, selected generation/source
   readback, a bounded real-entrypoint return check, and no mutation of original
   attempts. Do not estimate dollars saved or claim fleet-wide perfection from
   screenshot elapsed time, CLI token estimates or offline tests.

## Review correction: bounded derived diagnostics

Independent GitHub review `PRR_kwDOTotz3c8AAAABToyfBQ` identified that the newly
persisted `cli_subtype` and `cli_terminal_reason` strings were copied verbatim
from provider events. An oversized synthetic terminal field could therefore
inflate the derived provider receipt and include private event text even though
stdout remained clean. This is a derived-record boundary defect, not a reason to
relax classification or release requirements.

The corrected projection persists only recognized fixed labels, `other`, or null.
Raw values still drive the same classification logic and remain in the original
private failure capture. New actual-wrapper regressions test each field at both
zero/nonzero original CLI exits, require derived receipts below 4096 bytes with
no synthetic private marker, and verify byte-identical raw retention at mode0600.
The existing historical-denial success and real-failure cases remain unchanged.
The top-level repository test wrapper includes this regression in normal CI.

The original auto-merge request was disabled before source repair. The blocking
review is not dismissed or replaced; the original reviewer must consume the
correction and exact-head protected checks remain mandatory. No runtime release,
selector movement or historical attempt replay is part of this correction.
