# Pinned-account head-of-line repair

Source candidate only. Apply after the request-local waiter amendment in the
same complete broker composition. The helper ignores blocking demand only when
its explicit account is uniquely observed grantable and its total capacity is
already occupied. It never drops demand, changes a pin, frees a lease, creates
another capacity grant or treats absent observations as proof of saturation.

Both priority/FIFO and below-fair-share borrowing use the same predicate. Demand
re-enters both calculations as soon as capacity is available. Root fair-share
accounting, pool/account/model caps, native retention and actual claim stay with
the existing owners. Unknown, unpinned and model-only constrained requests remain
blocking; this is not a complete solution to every model/host head-of-line case.

The focused source-method discriminator is 16 passed, versus four failures and
12 passes on the before-methods. The actual published patch is applied in that
suite. The separate five-case complete-broker suite checks the method reference
against the full composed protected source, then tests real temporary-SQLite
acquisition, sibling retention, idle borrowing, restored eligibility, unpinned
priority and preserved native-uncertain capacity. Its behavioral result is not
claimed before execution. No provider or native host is contacted.
