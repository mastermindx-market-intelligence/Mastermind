# Resources & systems — bounded source composition

`ResourcesSystemsPanel` uses the authenticated App-owned `ControlRoomState` and
`ResourcesWorkState` observations. It acquires nothing and makes no placement,
reservation, admission, host, provider or lifecycle call. The shell owns auth epoch
invalidation and clears these observations when the current owner changes.

Mount it in Fleet & Capacity with `controlRoom={currentControlRoom}`,
`work={workState}` and `locale={locale}`, followed by the existing
`AttendedFabricWorkspace`. `onReviewSources` opens the existing Sources/Connections
landing. `onOpenWork`, if the shell can resolve the exact returned root, navigates
to that work; omit the callback when exact navigation is unavailable.

The visible Paper LCJ-0 and MO4-0 references define the resource/role, readiness,
work/pressure columns and inspection pane. The labels and sample hosts in Paper
do not supply operational evidence. The implementation keeps these dimensions
separate. Installed provider capabilities are not host admission, serviceability,
live bindings, protected assignments or available worker slots. Nulls and absent
capability keys remain unknown. Exact work capacity evidence keeps its source and
bounded/truncated coverage. It is never summed into fleet utilisation.

Dark uses the existing neutral panel/raised aliases. Light uses the existing light
aliases, white panels, an even selected border and a controlled panel shadow.
Mobile stacks resource cards and moves source depth into disclosures; the shared
shell owns outer gutters. EN and ZH use the same source and uncertainty semantics.
This is source and component-test evidence, not rendered or authenticated proof.

## Host telemetry contract and unfinished producer

The optional `capacity` prop consumes **already qualified retained evidence** from
`control_plane/executive_host_capacity.py::project_native_host_capacity`:
`mastermind.native_host_capacity_read/v1`. `decodeHostCapacityRead` validates the
closed wire, exact metric names/units, safe integers, physical bounds, null reason
and unknown-field parity, and observation-only/no-placement semantics.
`qualifyHostCapacityRead` additionally compares an independently trusted expected
binding and checks age from the oldest observation window. Neither pure function
authenticates an origin or creates a grant. Native int64 values beyond JavaScript's
safe integer range are refused to avoid silently rounded metric evidence.

The actual server must derive expected host, boot, capacity pool, source generation,
execution scope, namespace and ancestry from existing qualified Runtime/collector
ownership. It must apply its existing clock/age policy and read only an actual
authorized retained source. Do not derive expectations from the received body,
browser selection, user-supplied metrics, a path, or an arbitrary host name.

As of this source slice, no authenticated retained Workspace reader for this source
has been established. The current backend owner found no telemetry in the existing
Control Room, Mission, plan ceilings or host status document. This is a bounded
source finding, not proof of global absence. `NativeCapacitySource.acquire` runs
live acquisition and is outside this source-only commission. No host method,
endpoint, grant, sampler or placeholder reader has been added.

The telemetry consumer is therefore built but unbound. The fleet producer closes
only when the fixed authenticated reader composes an actual retained qualified
source with revocation/identity/age tests and the real installed journey passes.
Missing telemetry remains an engineering obligation, not product acceptance.

`research/evidence/native-capacity-owner-projection.json` (repository root) is an inert fixture generated by
the actual Python producer and its existing deterministic test inputs:
`tests/test_executive_native_host_capacity.py::project(snapshot())`.
Its synthetic clock/identity are test data and provide no live host evidence.

## Historical provider evidence: implemented source

This is a different source from host telemetry. The original successful Runtime
`JOB_CLAIMED` Event already retains `mastermind.finite_initial_claim/v1` with a
qualified `mastermind.provider_capacity.v2` snapshot. No new acquisition or store
is needed to read that historical receipt.

The implemented internal source API is:

```python
with runtime.observe_bounded_read() as observation:
    snapshot = observation.read_retained_capacity_bounded(root_id, job_id, attempt_id)
body = project_capacity_source(
    snapshot, observation.receipt,
    work_ref=work_ref, root_job_id=root_id, job_id=job_id,
    attempt_id=attempt_id, now_ms=runtime.store.now_ms(),
)
```

`project_capacity_source` is in `control_plane/workspace_resource_capacity.py`.
It requires the finalized SAME receipt, exact per-read source identity and
independently qualified workstream/root/job/current-Attempt tuple. Its response
budget is 16,384 bytes. The source acquisition verifies claim/BEGIN metadata
before reading bounded payloads; the safe projector binds the immutable BEGIN
aggregate, command, receipt and boot-qualified commitments to the original claim.
Historical snapshot validity uses the original claim clock. Current read time
only determines receipt age; it cannot refresh quota or grant eligibility.

The fixed authenticated source join is implemented on the accepted READ freeze:
`GET /workspace/resources/capacity/current` with exactly `work_ref`, `root_job_id`,
`job_id` and `attempt_id`; frame `mastermind.workspace_resource_capacity_read.v1`,
operation `resource_capacity`, result `mastermind.workspace_resource_capacity_result.v1`.
It uses the existing Acquisition READ principal and independently enrolled original
COO workstream membership. Generic Workspace login alone is insufficient. Permission,
membership and source publication/currentness are rechecked around the bounded
read; socket/HTTP/client budgets are 16,384 bytes including the socket envelope/LF.
The edge validates the closed body and returns no-store. Missing or ambiguous
capacity evidence is unavailable, never zero capacity or idle.

`MissionHost.readResourceCapacity` decodes only the same selected four-field body
after auth/source epoch and reader-identity fences. Web and native clients use
only that fixed GET with the existing Acquisition bearer. The explicit
`ResourceCapacityRead` component takes `host`, `selection` (the qualified current
work/Attempt tuple), and optional `locale`; it reads only on click and clears
receipts on selection/owner/auth changes. App composition remains with the sole
App author. No source reader accepts host, metric, binding, path or clock fields,
and the internal raw `RetainedCapacitySnapshot` is never a public response.

This is tested source composition, not an installed authenticated journey or
rendered Paper acceptance. The runtime/install/capture holds remain independent.

`retained-provider-owner-projection.json` is generated from an actual inert
Runtime/SQLite claim, bound observation close and safe Python projector, using
synthetic source fixtures. The TypeScript consumer test reads those exact bytes.
It provides source compatibility evidence, not a live provider/account claim.

Multiple capability rows on the same host/boot remain a closed unavailable result:
the retained claim does not carry a separately qualified selected-capability proof
for a positive historical join. The reader never guesses a row or substitutes
changed current worker metadata for missing original evidence.
