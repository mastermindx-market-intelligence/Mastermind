# Model and delegation decision for Cursor

## First classify the labor
- C0: mechanical deterministic transform. Prefer an ordinary tool or local test, no subagent.
- C1: routine bounded code or structured research. Prefer the least scarce qualified Fabric worker **when the current Cursor principal is admitted**; otherwise work directly in the permitted source lane.
- C2: bounded complex coding, investigation or independent adversarial review. Use the best actually available qualified route without buying extra principal reasoning merely to relay prompts.
- C3: ambiguity/architecture/judgment. Retain principal control, justify frontier witness and preserve separate reviewer capacity.

## Native Cursor versus external Fabric
- Cursor native Task uses built-in Explore or the reviewed project role if the effective hook permits it. Native Task child != Executive Job/Attempt, and a plan/capability file grants no child execution permission.
- External Fabric requires verified current session authorization, exact typed `fabric_capabilities`, `fabric_request`, `fabric_status`, `fabric_wait`, `fabric_result`, `fabric_accept`, and `fabric_controller_output`. A catalog can prove exposure, but only an admitted typed call and runtime receipts can prove starts/results.
- Never run an alternative raw adapter, spawn another provider through shell, copy tokens, broaden MCP permissions or silently replace the original carrier after denial/timeout.

## Model selection and evidence
- Query the available Cursor CLI catalog (e.g. `agent --list-models`) when needed. Prefer documented `model: inherit` for owner-dependent judgment, and a specific observed supported model for narrow roles where that economizes work.
- Frontmatter `model` pins a desired model. Cursor or plan restrictions can select another. Require the actual Task trace/model receipt before asserting which model was charged or that paid model quota was used.
- Prefer deterministic read-only probes; live paid test executions need current authorization. Keep report fields: requested model, observed model if available, actual tool carrier, work class, result and verification; unknown is not zero.

Return one recommended route and the reason why it is cheaper *without* sacrificing the contract or independent proof.
