# Mastermind Native Fabric Routing

## Work inside the current assignment

Reuse the verified Mastermind source pin and applicable repository instructions; do
not restart full bootstrap for each observation. This method supplies no runtime,
tool grant, release approval or trade authority. Keep denied actions denied and
EFFECT_UNKNOWN on the original operation and carrier. Continue independent safe
work instead of widening access or retrying an uncertain effect. Use existing
Executive/Fabric, Agent OS, source, browser and deployment owners, not replacements.

## Use the existing routing owner

Treat this compatibility skill as method only. Read the current assigned role from
the protected mastermind-fabric-orchestration package and the installed adapter's
actual help/schema. Do not copy a remembered shell path, provider command, account
count, reset date, promotional price or capacity limit from an old skill.

The ModelRouter/Capacity/Fabric owners determine eligibility, account, model, host,
quota and admission. Current owner observations outrank historical examples. Do
not force a provider to increase utilization, work around a denial, or use a second
root to reset a shared budget. An unknown quota is not unlimited capacity.

## Prepare one useful bounded outcome

Identify the objective, source/workspace, allowed effects, acceptance evidence,
original root, actual parent and return path. Use the existing Worker Bootstrap
and one Craft role when supplied. Preserve true ancestry and attenuated grants;
never invent a root from a process ID or pretend a native session ID is a Runtime
Job. A leaf worker remains a leaf unless an exact existing helper grant applies.

Classify the child's actual task complexity rather than the parent's prestige.
Use mechanical/census/extract for genuinely mechanical work; reserve frontier
judgment for an explicit ambiguity or consequence. Delegation must save end-to-end
work including review and repair; do not manufacture tasks to burn quota.

## Observe before fan-out

Where these commands are actually installed and authorized, use the current
read-only interface, adapting only to its observed help:

```sh
pool --help
pool plan --class <actual-task-class> --need <useful-independent-outcome-count>
pool pick <actual-task-class>
```

A plan or pick is not a launch, a lease or future capacity guarantee. Use the
returned current admission rather than a static provider table. The existing
launcher/broker acquires and releases execution leases; do not emulate that
lifecycle in the skill. Preserve runtime-provided root, parent and orchestrator
identity. Never open a credential file to learn quota or print account secrets.

## Submit and consume through the assigned native adapter

Use only the already-authorized installed native Fabric adapter and its actual
schema for submission. Web sessions use their surfaced Executive/Fabric client;
this native skill does not authorize a Web shell handoff or bypass a missing tool.
Do not invoke a raw provider CLI, unrestricted SSH, new queue or native Agent/Task
tree as an alternative to denied or uncertain Fabric execution.

Choose one stable child identity before submission. Inspect it through the same
owner if present; do not replay it. Retain the submission/controller identity,
separate START evidence, exact result, validation and acceptance disposition.
Reserve review/repair capacity before widening builders. For independent review,
preserve author/provider provenance and the owner's independence constraints.

Treat missing tools, authentication failure, capacity wait, policy denial and
EFFECT_UNKNOWN as different facts. Missing Fabric does not authorize native leaf
spawning; perform independent permitted work or return that exact limitation.
Never cancel or replace another operation merely because a provider is exhausted.

Read [routing cases](references/cases.md) for stale-guidance and failure examples.

## Evaluate useful outcomes

Consume retained results, check the actual artifact and either accept with evidence
or return a bounded repair through the original owner. Process exit is not quality
acceptance. Compare provider quality only on outcomes with actual quality verdicts;
report coverage and small-sample limitations. This skill stores no live quota,
provider status, account inventory, credentials, scheduler or global memory.
