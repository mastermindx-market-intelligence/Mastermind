# Product-path proof cases

## Research modal
Input: accepted Paper intent and an implemented Research Desk modal.
Check opening from its real entry, focus containment, Escape/close, scroll at
390px, dismissal return, readable evidence, loading/denied/error states and both
applicable themes/languages. A Paper screenshot does not establish any of these.

## Canonical watchlist save
Input: the UI reports save success.
Check the expected item through the authorized persistence owner and reload the
journey. A 200 response, toast or locally updated array is insufficient alone.
Never mutate a real portfolio or trading account to demonstrate a UI test.

## Stale options data
Input: fetched payload is structurally valid but its last observation is stale.
Keep the stale label and original timestamp visible. Do not fill missing open
interest with zero or hide the banner for a cleaner screenshot.

## Evidence missing
Input: source compiles; the browser tool is absent or permission denied.
Report source checks performed and browser proof not performed. Do not switch to
a user browser profile or claim visual parity based on CSS inspection.
