# Select and analyze a Fabric graph

Use the smallest capable shape that retains original acceptance, review, custody and inherited bounds. Choose `direct` for cohesive work, `pipeline` for real prerequisites, `fanout_join` for independent branches plus an acceptance-bearing join, `hierarchical` for useful delegated domain ownership, or `custom` for another valid DAG. Model, harness, account pool and organizational role remain separate choices.

Use `python -m scripts.fabric_graph_plan catalog` and `plan <candidate.json> --root-job-id <original-root> --plan-attempt-id <actual-attempt> --method <method>` from an approved checkout. Supply a normal incumbent ExecutionPlan. Templates preserve identities, authorities, scopes, review, placement and delegation; dependency transforms only add edges. For nested v5 candidates also supply the declared inherited coordinator depth, descendant limit and maximum depth. These inputs are never authenticated grants.

Inspect the candidate, findings and reservation breakdown before returning it through the existing planner-result path. The prospective analysis does not replay an admitted root's policy. Under the current source policy a reviewed leaf reserves nine descendants, the planner one, and the total limit is sixteen. Two reviewed steps demand nineteen even in sequence. Do not remove required review, widen grants or reset roots to fit. Capacity fit and policy compatibility are separate.

Treat `fanout_join` as a structural transform: the caller must supply a competent join with original validation/acceptance obligations. Dependency layers and width cover immediate supplied steps only; child subplans remain unexpanded. Live admission, source custody, reviewer independence and product acceptance are still the incumbent owners' work.

Keep task context bounded to exact artifacts, relevant decisions and acceptance falsifiers. Reserve review and integration before widening builders. Return evidence and unresolved defects without replaying parent transcripts. Compare total framing, execution, review, repair and integration cost per independently accepted outcome.

Use `python -m scripts.fabric_graph_plan resources --root <existing-eval-store> --experiment-id <actual-id>` for observed EVAL resource coverage. Unknown is not zero; validity is not acceptance; the report is not a provider billing reconciliation or a route promotion.

Read `docs/FABRIC_GRAPH_ENGINEERING.md` in the same approved source checkout for examples, method tradeoffs, evaluation design and source/installed/runtime proof boundaries. Repository publication alone does not install this reference or prove a future session loaded it.
