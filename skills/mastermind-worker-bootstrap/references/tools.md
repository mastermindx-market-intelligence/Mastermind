# Tool requirements by job

Require a capability because the task needs an action, not because an impressive plugin
catalog exists. Use installed native tools instead of redundant plugins where appropriate.

| Task | Core | Conditional |
|---|---|---|
| Code worker | Exact checkout, scoped edits, Git diff, real toolchain/tests | GitHub branch/PR access, relevant developer docs |
| Research worker | Primary-source retrieval, citations, scoped files | Approved data API, PDF/table tools, context reader |
| Data scientist | Versioned licensed data, deterministic transforms and tests | Approved compute, charting, existing experiment tracker |
| Designer/frontend | Exact design target and references, build/render tools | Granted Paper/Figma edits and isolated browser |
| Reviewer/verifier | Frozen source, requirements and evidence | CI logs, test environment, read-only browser/API |
| Domain operator | Complete brief, dependencies and result consumption | Admitted Executive child tools and bound company dialogue |

GitHub owns source/PR/CI. Agent OS owns organizational context. Executive owns lifecycle.
Linear is projection and Slack transport. Studio read does not imply general shell or
Slack/GitHub/Linear. Company dialogue does not imply an unrestricted Slack client.

Web connector authentication is not native-worker enrollment. Never copy Web OAuth tokens,
provider cookies, broad personal credentials or environment secrets into worker prompts.
Use the existing service's explicit native enrollment and exact scope. Authentication/admin
consent can be a real human gate. Do not create a new client to bypass a denied enrollment.

The doctor only proves its exact harmless reads on that process/host. Unprobed writes,
child dispatch, browser control and authentication remain unknown. A native tool error must
be returned honestly; a method naming a tool cannot make it exist.
