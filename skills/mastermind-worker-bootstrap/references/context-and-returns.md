# Context and continuity

On the controlling host, use `pool context --workstream <existing-key> --output <new-file>`
when the launch helper is installed. It passes through the existing owner unchanged.
Otherwise prefer a named workstream using the existing Macro Agent OS reader:

```bash
python3 scripts/agentos.py compile-context --workstream <existing-key> --json --budget <bounded-budget>
```

This command reads and cites; it is not a task allocator. Preserve its actual no-answer,
degraded, excluded and omitted fields. Free-text resolution may be unavailable. Do not
invent a workstream or silently select an unrelated project. Always-included constraints
may exceed a requested budget: raise the allocation or stop, never drop required law.

A launch carries selected source facts, not a new canonical memory. Include the project's
objective, applicable decisions, interface/data contracts, existing implementation, known
blockers, exact source/artifact revisions, what must not be redone and next action. Keep
unrelated company state, private conversations, raw logs and secrets out.

Run-local scratch belongs in the assigned artifact directory. Reusable methods belong in
source-controlled skills. Durable decisions/lessons go through the existing Agent OS owner
with references and supersession, not an autonomous global MEMORY.md in every provider home.

Compaction preserves objective, scope, current source/decision refs, mandatory constraints,
outstanding effects, child/return obligations and next action. Optional omissions are named.
The launch tool does not add a compaction daemon, session store or retry controller.

Return: artifact and revision; verified behavior; commands/tests actually executed; context
and method refs consumed; uncertainty and unmet acceptance; unresolved effects; exact next
action. Use the existing result schema and owner. Delivery, parent consumption and acceptance
are different facts. Never forge an ACK/START/RETURN/STOP for another actor or operation.
