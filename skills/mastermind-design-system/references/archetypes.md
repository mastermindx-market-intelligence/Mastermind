# Canonical A–I page archetypes

Choose the archetype from the user's primary question. A route may vary inside its job; it may not invent a tenth visual language.

| ID | Registry id | Archetype | Primary question | Canonical order / mobile reduction |
|---|---|---|---|---|
| A | `command_center` | Command Center | What changed / what now? | Verdict → change rows → action → deep links. Mobile: answer + top change + action first. |
| B | `discovery_board` | Discovery Board | What deserves attention? | Count ladder → filters → ranked evidence → detail. Mobile: ladder + top candidates; dense tables become counted depth. |
| C | `instrument_analyzer` | Instrument Analyzer | What is happening to this entity? | Decision header → lifecycle/task tabs → evidence → history. Mobile: current read + lifecycle + key evidence; mechanics behind disclosure. |
| D | `regime_dashboard` | Regime Dashboard | What regime are we in? | VerdictHero → what changed → drivers → watching → deep links. Mobile: hero + chips + first driver; extra drivers demoted/swipe. |
| E | `intelligence_desk` | Intelligence Desk | What does the research say? | Brief/claim → evidence packages → implications → source depth. Mobile: lead + implications + receipts first. |
| F | `editorial` | Research / Editorial | What is the argument and evidence? | Title block → measure-limited reading column → pull-stats → TOC rail. Mobile: reading column; TOC becomes disclosure. |
| G | `monitor` | Monitor | What changed since I last looked? | Since stamp → timeline by day → managed list → quiet empty. Mobile: timeline primary; management controls secondary. |
| H | `marketing` | Marketing / Conversion | Why is this worth using? | Proof-first hero → 3-band value → plan/CTA → FAQ. Mobile: proof remains first; one primary CTA; ≤8 screen journey. |
| I | `utility` | Utility | Complete one narrow task | Centered card → one action → outcome. No dashboard vocabulary. |

The Terminal/chart workspace remains separately governed and is not an excuse to copy Terminal pixels into the A–I system.

## Identity devices

Each archetype has a distinctive structural device, not a separate palette:

- A: two-column command layout + change rows
- B: count ladder
- C: decision header + dated lifecycle rail or task tabset
- D: regime VerdictHero + watching band
- E: dated/source-graded brief cards
- F: measure-limited reading column + TOC rail
- G: since-you-were-here timeline
- H: live dated proof as hero / plan claim structure
- I: single-card focus

If the user job does not fit these, stop at product/IA gap rather than inventing an archetype.
