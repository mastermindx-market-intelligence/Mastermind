# Engineering handoff

A complete handoff links the exact design-decision receipt and actor, original
assignment, completion digest and current Paper targets. It maps actual components
and source paths, token names, data fields and null/freshness behavior; it specifies
interaction transitions, responsive reduction, localization, focus/keyboard/touch and
verification. Preserve limitations and unfinished behavior visibly.

The helper refuses formal handoff while evidence or a material revision remains.
Do not fill missing fields with generic optimism to make it pass. An incomplete
artifact may still have useful implementation notes, labeled unaccepted.

For the clock canary: retain the existing page shell, tape, chart/table controls and
all numerical values. Keep `main_map_as_of` distinct from `historical_tape_as_of`.
Render disclosure from actual source metadata, never a hard-coded production date.
Do not imply both datasets are current or comparable across windows. Retain fixture
labeling in design/demo contexts. Source update belongs in the real Sector frontend;
this commission does not ship an unrelated product modification.

Acceptance of an implementation needs the existing browser/consumer path, including
filter → dossier → evidence → return preservation, stale/empty/error states, keyboard
and mobile behavior and actual data provenance. Exported JSX is only an implementation
reference; integrate with current components, routes, state and authorization.

Notification: draft recipient/action/canonical link/return location, then use the
existing authorized channel/thread action once. Record the actual message identity.
A delivered message is not START, design acceptance or production acceptance.
