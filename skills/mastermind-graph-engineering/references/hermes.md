# Hermes: persistent teammates with bounded delivery ownership

Keep existing teammate identities, profiles, memory and conversation return paths. Match the assigned function to the existing profile; do not create another bot roster to make a graph.

## Load through the real profile

Hermes discovers skills from the active profile's `skills` directory and configured search roots. On M2 the default home is `~/.hermes`; teammates also use `~/.hermes/profiles/<profile>`. The installed loader resolves `HERMES_HOME` per call. Use `skills_list` and `skill_view(name="mastermind-graph-engineering")` in the actual profile to verify discovery. Loading the default home proves nothing about a different profile.

Read only relevant role/environment references. Use existing `memories/MEMORY.md` as a short advisory trigger, not a mission ledger. Agent OS/GitHub/Executive remain the durable organizational/source/execution owners.

## Delegate and consume

1. Recover the original room/session, work item, mission, source and admitted root. A display name supplies no authority.
2. Give a qualified lead one domain outcome. It owns decomposition, permitted repairs and integration; send material decisions and accepted results upward.
3. Inspect the configured delegation backend and exposed scope. Use the existing Hermes/Fabric integration. Do not change model, backend, account, credentials or depth settings to manufacture permission.
4. When the operator interface is admitted, inspect `fabric_operator_scope` and use its supported child request/status/result/acknowledge actions. Preserve root, real parent, expiry and remaining budget. Leaves and reviewers cannot recursively spawn simply because a prompt asks them to.
5. Consume exact retained child results in the immediate parent. Delivery acknowledgment is distinct from quality acceptance. Return the integrated result to the original conversation/task through its supported path.

If a backend is absent or scope insufficient, diagnose configuration/capability once. Continue independent permitted work or return a ready packet to the admitted parent. Do not install a second dispatcher or fall back to raw provider calls.

## Memory and continuity

Preserve each teammate's role memory. Add only a compact pointer through the existing memory writer with configured limits, locking and content checks. Never replace role memory with a principal transcript. Prompt snapshots can be frozen at session creation; distinguish disk persistence, fresh loader discovery and observed behavior. Do not restart unrelated gateways/workers to refresh a skill.

Use existing continuation and return owners. A persistent identity does not prove every pending job is active, and skill installation does not establish unattended parent wake.
