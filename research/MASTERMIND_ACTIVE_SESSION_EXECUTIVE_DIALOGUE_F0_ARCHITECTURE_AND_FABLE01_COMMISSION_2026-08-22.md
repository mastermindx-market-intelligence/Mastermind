## 0. Executive ruling

The missing capability is narrower than generic agent dispatch.

Sol increasingly provides high-frequency product, architecture, sequencing and review control because that preserves Chairman intent better than handing an entire ambiguous program to one long-running implementation model. Fable remains the preferred principal builder, but consequential discoveries and decision boundaries occur throughout execution, not only at the final PR.

Today an active Fable session usually returns by changing GitHub state or by asking Chris to carry prose into the matching Sol conversation. Chris has become a biological transport bridge between two already-running cognition surfaces.

The first useful vertical is therefore:

```text
already-active, explicitly commissioned Fable session
        |
        | DECISION_REQUEST / BLOCKED / RESULT
        v
one bound #agent-dispatch Slack thread
        |
        | native Personal-Pro Slack read/write
        v
already-active Sol session
        |
        | RULING / CONTINUE / AMEND / STOP
        v
same Slack thread
        |
        | bounded poll/readback
        v
same active Fable session
```

This capability is **Active-Session Executive Dialogue** (`ASD`).

ASD transports bounded dialogue among sessions that are already active and already share one accepted commission. It may not originate work, assign a session, wake a session, prove runtime visibility merely from Slack delivery, dispatch a Job, close a PR/workstream or create a canonical inbox.

V1 is deliberately asymmetric:

* active Fable/CLI sessions use a least-privilege local Agent Relay tool to send and read one bound Slack thread;
* active Personal-Pro Sol sessions use the existing native Slack connector to read and reply;
* neither side gains unattended background cognition or wake semantics;
* Chris copies zero message bodies.

## 6. One bound thread per commission

Before ASD traffic, one eligible top-level `#agent-dispatch` message binds:

* exact immutable `commission_ref` (`repo@commit:path` plus content hash);

The local relay accepts a thread only when bounded history contains exactly one eligible parent matching the caller's commission context. Zero or multiple matches refuse. No title similarity or newest-message guessing.

## 7. Framed message contract

Every machine-consumable message begins exactly:

```text
MMX/AGENT_DIALOGUE_V1
{"schema":"mastermind.agent_dialogue.v1",...one canonical JSON object...}
```

Those two lines are the canonical payload span. A known Personal-Pro attribution trailer may follow only under exact grammar proven by the ASD carrier canary. It is excluded from fingerprinting and grants no authority. Unknown/additional trailing text refuses. No YAML/Markdown repair, prose extraction or model guessing.

Bounds:

* UTF-8 only;
* one discriminator + one canonical JSON line;
* 4,500 UTF-8 bytes maximum in V1;
* closed keys/enums at every level;
* bounded summaries/options/evidence refs;
* no file contents, logs, diffs, credentials, transcripts or arbitrary commands.

Conceptual shared fields:

```json
{
  "schema": "mastermind.agent_dialogue.v1",
  "message_key": "asd-<stable-id>",
  "message_type": "DECISION_REQUEST",
  "work_ref": "WS:EXAMPLE",
  "commission_ref": {
    "repository": "owner/repo",
    "commit": "<40-hex>",
    "path": "research/...md",
    "content_sha256": "<64-hex>"
  },
  "session_ref": "asd-session-<opaque-id>",
  "seat_ref": "fable",
  "reply_to_message_key": null,
  "applies_to": {
    "repository": "owner/repo",
    "head_sha": "<40-hex-or-null>",
    "pr": "owner/repo#123-or-null"
  },
  "summary": "bounded statement",
  "body": {},
  "evidence_refs": [],
  "requires_response": true,
  "created_at": "<UTC transport time>",
  "fingerprint": "<64-hex>"
}
```

`created_at` is transport evidence and excluded from semantic fingerprint. The final exclusion set must be minimal and mutation-tested.

Closed F0 message types:

**From Fable/COO:** `ACK`, `DECISION_REQUEST`, `BLOCKED`, `PROGRESS`, `RESULT`.  
**From Sol:** `RULING`, `CONTINUE`, `STOP`, `AMENDMENT_AVAILABLE`.

No free-form `command`, argv, write paths, authority list, credentials, provider routing, merge/deploy action or Chairman-decision field may be supplied by Slack.

## 10. Idempotency, ambiguity and correction

`message_key` identifies one logical message.

* same key + same fingerprint → same message / duplicate reconciliation;
* same key + different fingerprint → conflict/refusal;
* changed content → new key.

Slack timestamps are transport evidence, not operation identity.

For effect-unknown post:

1. keep Slack as the same carrier;
2. re-read bounded thread history;
3. exact key+fingerprint found once → return receipt;
4. conflict/multiple → refuse;
5. true not-found after complete read → same send may retry on Slack;
6. incomplete/unavailable history → remain uncertain and fail closed.

Never auto-post a GitHub comment or alternate Slack message.

Edit/delete cannot mutate or cancel dialogue already consumed. Corrections use a new key. Restart is stateless and re-verifies parent/history; incomplete traversal remains `RECONCILIATION_INCOMPLETE` rather than creating a cursor DB.

## 11. Escalation and result law

Fable escalates when a discovery changes thesis/architecture/authority/journey, sources materially disagree, scope/path widening is needed, a frozen assumption is falsified, remedies materially differ, a real test changes feasibility, Chairman/Sol decision is required or a reviewable/terminal result exists.

Do not escalate routine test reruns or mechanical details delegated by commission.

A decision request contains exact question, outcome impact, evidence/revisions, 1–3 options, recommendation, consequence and whether work is safely paused.

Sol replies with ruling, rationale, whether authority changed, canonical ref if required and exact continuation/stop condition.

`RESULT` points to real PR/head/handoff. It cannot merge/approve, close Linear, mark Agent OS done, claim production proof or terminate an Executive Job.
