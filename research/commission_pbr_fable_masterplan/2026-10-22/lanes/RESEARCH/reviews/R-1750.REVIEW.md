## 5. Findings

**F1 — BLOCKER — `brain/facts.py:432` (and :336-368).** Rule (i) lacks the R-1701 F1 event/period identity gate: `_verify_event_date` returns CONTRADICTED whenever *any* primary record's date ≤ decision asof, and `_primary_records` discards period/event identity, so the rule cannot even express the gate. Observed probe: a future-dated FY2026-Q4 catalyst claim (2026-10-22, asof 2026-10-02) plus an unrelated past FY2026-Q3 company release (2026-08-26) → `CONTRADICTED`. Acceptance criterion A3 ("compares an evidence event date only after event/period identity matches the claim") is unmet, and no test covers the unrelated-event case (all current evidence fixtures coincidentally concern the same Q4 event, so the suite passes despite the gap). Aggravating: `_primary_records` additionally admits class-less dated records as primary (facts.py:344-347), widening the false-CONTRADICTED surface; via rule (iii) and the budget's fact factor such a false positive zeroes a name's eligible weight. Smallest fix: carry an identity key (e.g. `period`/`event`) from each evidence record and the fact (fact `period`/claim), require identity agreement before the ≤-asof comparison and before `primary_dates_past_event_differently`, keep MU CONTRADICTED (Q4 evidence vs Q4 claim), and add the different-period regression test.

**F2 — MAJOR — `brain/shadow_risk_budget.py:266` vs `config/pbr_shadow_risk_budget.yml:239-248`.** `evidence_multiplier.unreconciled_fact_factor` is decorative: the code hardcodes `fact_factor = 0.0 if blocking_verdicts else 1.0` and only echoes the config value in the step drivers (:281-283), while the module docstring (:30-32) and the config entry claim the evidence step "multiplies by the configured `unreconciled_fact_factor`". Observed probe: config mutated to 0.5 loads cleanly, yet eligible stays 0.0 — identical to factor 0. A later lane changing that parameter under §4.3's change rule (bump version, seat ruling, re-run suite) would silently see no effect, and the re-run passes vacuously. Smallest fix: `fact_factor = float(_pv(params, "evidence_multiplier.unreconciled_fact_factor")) if blocking_verdicts else 1.0` — or delete the parameter and the docstring claim.

**F3 — MINOR — `brain/facts.py:3`, `brain/thesis_store.py:3`, `config/pbr_shadow_risk_budget.yml:2`.** All three cite `docs/superpowers/specs/2026-10-22-pbr-pm-facts-thesis-risk-budget.md`, which exists in no ref in this repository (specs dir and full-history search checked); the binding spec lives off-repo (PR #1701). A later reader following the citation finds nothing. Smallest fix: cite the program issue / PR #1701 spec provenance, or commit the spec under that path.

**F4 — MINOR — `brain/thesis_store.py:292-300`.** `record_thesis` does not backfill a present-but-`None` `thesis_id` (`setdefault` leaves it), storing a null-id record that is retrievable by episode but cannot be amended and collides on duplicate detection. Observed probe: explicit `thesis_id=None` is stored. Smallest fix: treat a falsy `thesis_id` as absent (`out["thesis_id"] = out.get("thesis_id") or make_thesis_id(...)`).

**F5 — MINOR — `brain/shadow_risk_budget.py:89-112`.** `_check_justifications` only validates leaves written as `{value, justification}` mappings; a bare scalar parameter escapes the justification regime entirely, contradicting the config header's own contract ("A parameter without a justification is invalid"). Observed probe: `smuggled_knob: 0.42` passes `load_params` and is consumable via `_pv`. No current parameter exploits this. Smallest fix: in the recursion, reject non-description Mapping children whose leaves are bare numerics, or require every numeric leaf under the four parameter roots to carry the wrapper.
