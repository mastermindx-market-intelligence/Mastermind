## Findings

**F1 — MINOR — `tests/test_pbr_decision_case_fixtures.py:368` (corpus at `:371`, assertion at `:386`).**
`test_no_original_prose_is_committed_under_fixtures` derives its whole power from `original_prose()`
and never asserts that index is non-empty, so it passes vacuously on a starved input directory:
with present-but-empty `case_rows.jsonl`/`case_fills.jsonl` it was among the 15 passing tests while
its sibling failed. It is the guard for a paid product surface in a public repo, yet it is the one
gated test that can report green while checking nothing. Secondarily, its corpus
(`FIXTURE_DIR.parent.rglob("*")`) covers 7 of the 8 changed files — the test module itself is never
scanned (my independent D3 scan covered it: 0 hits). Smallest fix: before the `assertEqual`, add
`self.assertTrue(originals)` and `self.assertLessEqual({d["sha256"] for …digests…}, set(originals))`,
and append `Path(__file__).read_text(encoding="utf-8")` to `corpus_parts`.

**F2 — MINOR — `tests/test_pbr_decision_case_fixtures.py:38-39` (source at `_build_decision_cases.py:445`).**
The allowlist is named and commented "Builder-authored sections that may keep whitespace-bearing
strings verbatim", but `linkage_note` is not builder-authored: it is copied verbatim from the input
`MANIFEST.json` (`related_links`). It is therefore the only whitespace-bearing committed string that
`original_prose()` does not index and the leak test does not guard, and the allowlist is source-blind
— a future capture whose `related_links` carried narrative would be committed verbatim with no test
failing. Today's three values are structural (ids, dates, share counts, prices, `UNLINKED` markers;
sha256 prefixes `8421af413afe`/283, `e4ebb4bf0fcc`/176, `015b181a6ebe`/137) and
`tests/fixtures/pbr/DECISION_CASES.md:37` correctly discloses the source, so nothing is leaked.
Smallest fix: rename the constant (e.g. `VERBATIM_ALLOWED_SECTIONS`) and extend the comment to state
that `linkage_note` is capture-MANIFEST structural text, not builder prose.

**F3 — MINOR — `tests/fixtures/pbr/decision_cases/_build_decision_cases.py:194-195` (rule text at `:273`; mirror at `tests/test_pbr_decision_case_fixtures.py:91` and `:143`).**
The prose rule is whitespace-only ("a string value is prose when it contains any whitespace
character"), and the test's `has_whitespace`/`original_prose` use the same rule, so redaction and
verification share one blind spot: whitespace-free CJK narrative would be committed verbatim **and**
be invisible to the leak test. This matters because one fixture is a China-book case. Not currently
triggered — I verified all 469 whitespace-bearing non-ASCII input strings were digested and all 27
whitespace-free non-ASCII occurrences (9 distinct) are ≤4-code-point issuer `name` labels. Smallest
fix: in `is_prose`, also treat as prose any string containing CJK/extended characters longer than a
short label bound, or any non-ASCII string whose leaf key is not in an explicit label allowlist
(`name`).

**F4 — MINOR — `tests/fixtures/pbr/decision_cases/_build_decision_cases.py:447-448` (integrity test at `tests/test_pbr_decision_case_fixtures.py:193`).**
