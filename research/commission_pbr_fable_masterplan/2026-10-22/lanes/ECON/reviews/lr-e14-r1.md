## Findings

**F1 — MINOR (mutation-coverage placement; registers UNCAUGHT under the seat's per-file protocol).**
Applying mutation **m7 to `self_directed`** (restore `path.parent.mkdir(parents=True, exist_ok=True)` at the top of `portfolio/self_directed.py:244 _atomic_write_bytes`) and running the module's own invalid-state file (`tests/test_self_directed_invalid_state.py`) leaves the **entire file green (rc=0)** — there is no sd low-level-writer test (paper has A7 `test_low_level_writers_never_create_directories`; sd has none, and B1/B2 arm `_atomic_write_bytes` as a tripwire so the mutation never executes there). The mutation is behaviorally real: on HEAD `sd._atomic_write_bytes(<missing>/account.json)` raises FileNotFoundError and creates nothing; with the mutation it would create the dir and write. However it **is caught** by `tests/test_paper_account_invalid_state.py::test_no_mkdir_outside_the_explicit_bootstrap_helpers` (the S2 AST test walks `portfolio/self_directed.py` too, allowed set = `bootstrap_book_dir` only) — verified by applying m7/sd and running the paper file: exactly that test fails. So the full CI suite pins it; only the per-module placement is weak. If the seat reads "UNCAUGHT" strictly per-file, this is the one candidate; engineering-wise no regression can merge green.

**F2 — MINOR (Q3): `self_directed.mark()` can now raise through its "never raises" contract in a narrow race.**
`mark()` (self_directed.py:935) documents "Best-effort; never raises". If the book dir disappears between `_load_account()` (line 945) and `_save_account(state)` (line 984, reached when stored marks changed), `_save_account` now raises typed `SelfDirectedAccountInvalid` **outside** the `try` at line 990 — the raise escapes `mark()`. On master `_save_account` recreated the dir and succeeded. Behavior is fail-closed and writes nothing (correct per the ruling); only the docstring/contract is now inexact. The reachable non-race cases are fine: dir already missing → `_load_account` raises → caught → returns `None` (verified in R1-sd); dir vanishing after load → `_require_book_dir` at 991 raises inside `except Exception: pass` → computed row returned, HARD_STOP emitted, nothing written.

**F3 — MINOR (Q1): `strict` not forwarded to `_raise_path_invalid`.**
`_raise_for_path_problem` (paper_account.py:536) passes `strict` only to the `unreadable:*` route. A path problem (`dangling_symlink`, `data_dir_*`) met during strict replay (`_load_account_file(strict=True)` at paper_account.py:1677 and :3767) raises with the non-strict message "account state invalid for …". Verified harmless: grep of tests/app/bot/brain/portfolio/loop/control_plane finds matchers of the two strict strings only in `test_paper_account_invalid_state.py::test_strict_load_raises_account_state_invalid_with_legacy_messages`, which covers the byte classes (still routed with `strict`); callers (recovery) dispatch on exception type, and pre-E14 these path classes produced no raise at all (master returned a fresh book). Cosmetic asymmetry.

**F4 — MINOR (Q4): path-invalid HARD_STOP events repeat on every detection.**
`_raise_path_invalid` appends one run_event per raise, with no `already_quarantined`-style suppression (E13 suppresses repeats once the copy exists). A persistent missing dir hammered by the scheduler produces one HARD_STOP per attempt. This matches C2's text ("emits one HARD_STOP run_event" per raise) and keeps the condition visible in governance; noise only.

No BLOCKERs. Everything else conforms — evidence below and in the RETURN block.
