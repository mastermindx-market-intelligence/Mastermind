## 4. Concrete Paperclip inspection: why not fork it wholesale

Inspected [ui/src/pages/OrgChart.tsx at exact pin](https://github.com/paperclipai/paperclip/blob/f2c5e54dcad1ea00ce091cd9ef1d8a56499edef1/ui/src/pages/OrgChart.tsx), lines 1-205; blob `1eb8e35ce6cd9f8ce1bbdf6dc74e6615fbafe36f`.

Useful elements include forest/tree layout, fit-to-viewport and touch gesture helpers, and an embedding interface accepting a supplied organization tree and agent records. However, the page imports company context, navigation, agents API, shared Paperclip types and application-specific display state. Its recursive layout helpers also require bounded, cycle-safe input qualification before reuse in Mastermind.

This is source evidence for **extracting small pure presentation helpers or adapting interactions**, not evidence that the page can be dropped into Mastermind. The inspected slice does not constitute a complete source audit, performance benchmark, accessibility evaluation or security review. Mastermind's own identity, status and source-currentness contracts replace the donor's assumptions.

## 5. Component adoption gate

For each selected dependency or copied component record: exact repository/package and commit/version; original path; license and notice; imported assets; dependency closure; vulnerability/release review; rights restrictions; original hash; local adaptations; test coverage; and removal/upgrade path.

Adopt only when the component improves a named user journey without importing a second authority or forcing a large framework rewrite. Prefer a stable package for graph rendering and small pure donor components for cockpit/inspection UX. Preserve attribution. Do not copy secrets, corpora, branding or paid templates.

A donor proof must exercise the actual local integration, not only its screenshot. The core shortlist is now **React Flow for the renderer, Paperclip for company UX, OpenHands for the operator workspace, and Builderz/Temporal for operating-history interactions**. This is a selection for further component-level evaluation, not a claim that their code has already been imported or production-qualified.

## 6. Unresolved evidence and falsifiers

- Installed Control Room, actual provider reachability and exact action capability: verify through the intended authorized host/service. A successful future ping alone remains insufficient.
- Plural runtime producer: reconcile #508 release and obtain real owner-to-consumer data. Finding a newer protected producer with the required fields supersedes the corresponding dependency, not the no-rebuild rule.
- C3: all seven records plus current source/install proof are needed. One original design file cannot establish the final contract.
- Mac bridge/currentness: run the real WKWebView/client qualification and fixed-target IPC security matrix. A Chrome test cannot satisfy it.
- Source liveness/recovery: prove exact old-writer fencing and successor consumption through existing owners. An updated owner string is not proof.
- OSS: revalidate current chosen package/file licenses and compile/test the actual adapted component. No full donor audit is claimed here.
