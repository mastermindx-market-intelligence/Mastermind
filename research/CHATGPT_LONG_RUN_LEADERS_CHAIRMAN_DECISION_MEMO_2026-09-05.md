# Chairman Decision Memo — ChatGPT Web as a Long-Run Mastermind Leader

**Date:** 2026-09-05  
**Carrier:** Mastermind Draft PR #490  
**Parent operation:** `chatgpt-pro-long-run-leaders-research-20260905-sol-001`  
**Status:** `DECISION_CANDIDATE / RESEARCH_ONLY / NO_RUNTIME_OR_INSTALL_AUTHORITY`

## Decision requested after independent review

Adopt the following company direction:

> Make ChatGPT web a durable **leader** of governed work, not an unrestricted logged-in desktop worker. Give exact, short-lived **operator** sessions Codex-like file/process and optional desktop capabilities through existing Mastermind owners. Treat conversations as replaceable working memory and the responsibility/evidence/execution fabric as persistent.

## Proposed rulings

### 1. Do not install Chat On Steroids defaults into a primary authenticated Chairman environment

Approve only a pinned-source, disposable, non-sensitive evaluation. Do not adopt its prime/worker/session registry, local transcript history, automatic compaction or goal loop as Mastermind lifecycle, memory, authority or continuation.

Selective adoption remains eligible for:

- batched reads and bounded continuations;
- structured patch ergonomics;
- durable process handles;
- separate Core/Desktop discovery surfaces;
- invocation-time permission enforcement;
- observation-bound desktop actions;
- explicit partial and effect-unknown results.

### 2. Preserve one experience with existing federated authority

No new Mastermind control plane is approved.

- Executive OS owns lifecycle and CEO admission.
- Agent OS owns durable organizational work.
- RuntimeBinding/Capacity/Wake own exact surface, placement and attention.
- GitHub owns source and immutable evidence.
- Steward/Control Room compose company reads.
- Code Intelligence owns governed global discovery and exact-worktree semantics.
- Company Dialogue owns bounded worker returns.
- Web-Sol and Worker Browser own exact browser/computer actuation.

The proposed Workbench is a facade over an existing exact Attempt/provider context.

### 3. Separate leader and operator capability profiles

**Leader:** current procedure, company context, evidence, bounded root admission, child state, material returns, review and closeout. No broad filesystem, shell, desktop, clipboard, credential, account or installation authority.

**Operator:** exact host-injected Job/Attempt/worker/workspace/source/path/network/secret binding. May receive bounded file/process tools and, later, optional disposable desktop tools. The model cannot choose privileged identities or roots.

### 4. Finish the existing Business read path before adding Workbench write capability

The first independently useful capability remains:

```text
one selected Business cockpit
→ exact reviewed Sol package/app generation
→ authenticated source-attributed Steward read
→ explicit degraded-state behavior
→ another successful read after access-token expiry/refresh
→ rollback/readback
→ two Personal-Pro controls unchanged
```

This provides a real context advantage while remaining read-only. Do not delay it until every future autonomous action is solved. Do not put Workbench into the first read canary.

### 5. Personal Pro receives leadership parity through governed delegation

Personal Pro does not need unsupported custom-MCP writes to lead difficult programs. Preserve the accepted route through protected source, approved reads, supported Slack/native action, dedicated Relay/CeoIngress, Executive OS, exact external workers, GitHub evidence, Dialogue returns and Web-Sol continuation.

Do not disguise mutation as read/fetch. The parity target is project leadership and acceptance, not identical direct-computer entitlement.

### 6. All autonomous-action claims must cover every reachable mutator

A stale chat refused at a Mastermind endpoint may still possess an independently authorized native GitHub, Slack, Linear, shell, provider or desktop path. Therefore classify every reachable route for the claimed configuration as:

- `ENFORCED`;
- `DENIED`;
- `ATTENDED` and outside the autonomous claim; or
- `UNKNOWN`, which blocks the stronger claim.

Approval prompts are not technical permission revocation. Never prove this by attempting an unauthorized production action.

### 7. Long-running execution and exact ChatGPT wake remain different claims

A worker/process may continue after a reasoning turn. A client may reconnect to a result. Neither proves that the exact inactive ChatGPT leader can be awakened. Preserve durable execution in existing providers/Attempts and return through existing Dialogue/Wake. Exact ChatGPT continuation/rotation remains separately gated by semantic readiness and RuntimeBinding succession.

### 8. Spend Pro turns on frontier judgment, not polling or mechanical labor

Use the current protected Pro-mode exception law. High-value uses include cross-system architecture, hard diagnosis, adversarial judgment and long-horizon synthesis. Handoffs, ACK/START/STOP, polling, monitoring, routing, simple tests and mechanical edits remain non-Pro work.

Optimize accepted capabilities per scarce reasoning turn, recovery quality, intervention rate, duplicate/unknown effects and real consumer completion—not elapsed turn duration or a raw zero-error metric.

## Release sequence

1. **BSC Read:** one authenticated Steward cockpit with refresh and rollback.
2. **Read-only Workbench falsifier:** one exact synthetic Attempt performs bounded repository/file/symbol/image reads and proves containment/coverage behavior.
3. **Patch/validation:** one prepared and committed synthetic patch plus reviewed validation recipe and lost-response reconciliation.
4. **Durable return:** process outlives leader turn; one material result reaches the exact current leader or wake unavailability is explicit.
5. **Disposable desktop:** observation-bound action with stale-target and partial-effect proof.
6. **Exact succession:** dead predecessor recovery, semantic readiness, RuntimeBinding advancement and stale refusal across every included autonomous route.
7. **Real program:** one consequential capability reaches a real product or machine consumer and durable closeout without Chairman message shuttling.

Every item is a separately scoped existing-owner vertical. No worker receives “build the whole workbench.”
