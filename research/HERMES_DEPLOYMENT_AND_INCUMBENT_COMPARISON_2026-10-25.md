## Ruling and source-vs-proof

**Keep DSH as the Meta-CEO app incumbent until a like-for-like challenge.** The October 24 donor research in #1841 treated Hermes as mostly a pattern donor, but current first-party Hermes documentation indicates a full Desktop app, native Bot Mode, multiple registered remote/Cloud/SSH gateways, a unified Bot roster, isolated profile configuration, built-in MCP filtering, remote OIDC/OAuth, native computer-use drivers and Z.ai integration. Those are meaningful capabilities—not independent performance or security proof. [Desktop](https://hermes-agent.nousresearch.com/docs/user-guide/desktop), [Bot Mode](https://hermes-agent.nousresearch.com/docs/user-guide/bot-mode), [Multi-gateway Desktop](https://hermes-agent.nousresearch.com/docs/user-guide/multi-connection-desktop), [MCP](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp).

**Hermes is the lead *Secretary* candidate and a serious *Meta-CEO* challenger.** Its separate cron, memory, agent delegation, gateway and tool authority cannot become Mastermind company truth. Agent OS remains organizational continuity, Executive OS alone admits Job/Attempt/effect, Model Router/Capacity places models/workers, Dialogue/Wake return decisions, Subagent Fabric executes, and GitHub owns code/review. Hermes profiles/history and visual Bot roster are subordinate UI/runtime data, not independent identities, queues or acceptance. Keep live Grok Secretary until real shadow parity and rollback are proven. Native Project Chat remains a separate full-vision acceptance requirement of R2.

**Preferred updated split after real host qualification:** self-host the **headless Hermes challenger on ubuntu1**, where read-only resource checks show about 54 GiB memory available and 884 GiB free disk, and retain **mini1** as a conditional isolated Mac GUI/computer-use worker. This reduces new hosting spend while preserving source and runtime control. A standalone low-duty Hermes on mini1 is an alternative once installed peak memory and TCC/existing workloads are tested. **Nous Cloud Medium** remains a low-cost managed fallback, not the preferred first deployment. Its procurement eligibility is provisional: actual Nous Cloud BYO existing Z.ai contract, exact build pinning/custom plugins, private Mastermind MCP reach, data terms and snapshot/backup export remain unverified. **FlyHermes is not selected** because its model credit economics, custom tool/code control and policy boundaries are unverified. Do not purchase any option until a real pilot needs it.

## Mini1 conditional host evidence, not accepted release proof

A bounded Fabric worker returned a `TERMINAL` read-only census indicating: macOS Apple Silicon 12-core/16 GiB, about 121 GiB free storage, 91% CPU idle, **only ~319 MiB unused memory**, no swap, active Grok Bot/ChatGPT/Paper/Chrome residents, no Hermes installed and a current GUI session. It reported no direct authorized management path from the controlling host, an indirect fleet hop, unknown screen/accessibility TCC grants and unresolved external-storage placement. **The worker also reported an out-of-scope known-hosts write and sensitive token output contamination.** The worker's content is not cleanly accepted; it must receive a private incident/credential-owner review. Do not copy its token, SSH topology, host key, personal app/account details or leaked data into public Git. These host numbers are preliminary until independently and safely corroborated.

A separate **direct mini1 readback** verified host identity, 16 GiB memory, 121 GiB free disk, no Hermes installed, and `memory_pressure -Q` reporting **69% system-wide memory free**. This demonstrates that a small number of completely unused physical pages did **not** mean the Mac had only 319 MiB available to applications. The compromised earlier census is still not an accepted security proof; the direct readback does not clear the credential incident or TCC/admission gates. Mini1 should not be treated as an agent model inference machine for GLM-5.3 weights. Remote inference may be CPU-light, but an independent 24/7 daemon alongside GUI/browser workloads still requires observed memory high-water, resilience, restricted OS user, local desktop permissions and a network owner-approved control path. Do **not** terminate existing apps or bypass TCC to free capacity.

## Source and role boundaries

- **Chairman UI:** existing Mastermind OS Conversation/MissionHost keeps original human audience and durable request association. Hermes Desktop/web/gateway may act as a replaceable shell; its answer is not an Executive acceptance receipt.
- **Secretary:** GLM-5.3-Flash is a candidate for bounded read/synthesis/draft work. Deterministic event detection and Wake remain outside model polling; no second company inbox.
- **Meta-CEO:** GLM-5.3 is a *candidate* executive reasoner, not a protected default or admitted provider route. Model Router and Capacity must verify account terms, actual quota, model and tool-call behavior. No secret copy into managed hosts by default.
- **Computer use:** prefer native app APIs; GLM-5.3 text reasoning over accessibility trees where enough; GLM-5.3-Flash/DeepSeek multimodal as a whole bounded visual operator when needed, through approved local computer owner and Fabric. The visual agent verifies screenshots/actions and returns narrow evidence. Credential interactions, public posts, financial operations and irreversible changes still obey target-system authority, approval and effect reconciliation.
- **Isolation:** Hermes profiles and OS users are not the same: the default local terminal backend runs under real OS user with no sandbox. Some Desktop plugin surfaces have app-level privilege. No built-in cron, delegation, memory, wildcard toolsets, direct cloud shell or broad MCP writes for the first pilot. First-party [Blank Slate](https://hermes-agent.nousresearch.com/docs/getting-started/quickstart) still enables file and terminal tools by default, so it is not a governance boundary. Enforce authorization at receiving services and verify actual registered tools, not merely YAML.
