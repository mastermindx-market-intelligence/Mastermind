## New load-bearing finding: singular operator is not plural visibility

At the protected source, `ExecutiveStewardSnapshot.get_current_runtime(WS, seat)` filters
RuntimeFacts by responsibility and seat, requires an exact root join, and returns
`REFUSED / ambiguous_runtime_join` whenever more than one candidate remains. It does not
list both workers. A larger binding generation is not a tie-breaker. The method also
returns no current operator for stale joins or `EFFECT_UNKNOWN`.

Source: `control_plane/executive_steward.py`, blob
`90ecd34cdd79ec8685b86f21420519e82ff5e147`, method around lines 765–947.

These are correct safety properties for a singular operator assertion. Do not remove
these checks to make an office dashboard look populated. Simply adding more RuntimeFacts
would make parallel work appear as an ambiguous operator instead of producing a lane list.

The needed addition is a **plural observational read**, owned by the same Steward/Runtime
architecture, which distinguishes a set of authorized lanes from selection of one current
action target. Its precise wire schema and producer contract are a bounded owner task, not
an unreviewed seventh tool appended to a published profile.

with synthetic source facts only. It preserves positive single-worker behavior, parallel

## Plural view: required semantics before its source slice starts

### Identity, membership and lineage

Every managed row needs owner-native work/root/Attempt/Worker identity, current binding
identity and generation, provider-native session reference where lawfully available,
opaque account environment and host identity, and an exact parent relation when it exists.
Do not infer parentage from a process PPID, matching title, nearby timestamp or model name.

A native helper remains an observed child of its owning Attempt unless it is independently
commissioned as an Executive child Job. Never fabricate company Jobs for every helper.
A manually started session may appear as observed/unbound, but discovery cannot register a
Worker, make an assignment, claim a resource, or confer modifying authority.

The plural query must separate legitimate parallel lanes from conflicting records for
one exact lane. It cannot choose a current generation by max(), newest timestamp, account
number or responsiveness. Root/parent mismatch and duplicate identity remain explicit.
Read authorization must apply before disclosing identifiers or child artifacts.

### Observation is not current authority

The view needs independent fields for host reachability, process/session evidence,
execution state, last observed activity, dependency/permission wait, effect uncertainty,
and current action permission. A running process is not proof of progress. Missing activity
is not proof of stopped work. Unknown capacity is not idle or unlimited capacity.

Retain authorized stale and uncertain-effect observations for diagnosis, with their
original owner times and explicit non-actionable status. Do not reclassify them as the
current writer. Existing singular query and action-target/lease checks stay unchanged.
Partial inspection must not hide a lane merely because it is most in need of reconciliation.

Use source-owned observation generations/sequences and existing freshness budgets. A new
HTTP response, dashboard render or summary must not make an old event fresh. Out-of-order,
duplicate, restarted and truncated observations retain their evidence limitations.

### Coverage and privacy

Every inventory response must distinguish known enrollment coverage, inventory completeness,
probe coverage, source failure and truncation. A known-complete zero is different from
unknown or inaccessible. Unobserved accounts/hosts must not be reported as quiet.

Default inspection is metadata, bounded tool-status summaries, approved diffs/artifacts,
and governed messages. No credentials, cookies, raw auth files, environment/argv dumps,
raw private browser stores, hidden reasoning, or bulk cross-account transcript scraping.
Native observation may not type into, resume, interrupt, focus or reassign a session.

### Consumer and interface compatibility

A plural lane source must have a real reader: the accepted Steward-facing read boundary
and a visible existing Control Room/Workroom surface, or an explicitly approved earlier
read-only consumer. Both must use the same source snapshot and attribution; no frontend
status inference or second cache. Existing Control Room top-level schema and B5 validity
ownership are not silently widened.

Keep the accepted first four-read MCP profile unchanged. Freeze any later plural read
profile/version, tool discovery, output schema, scopes and app publication separately.
An installed plugin or a 200 response is not a successful semantic read. Broad CEO visibility
must be explicitly authorized; workers get their permitted responsibility/subtree scope.
