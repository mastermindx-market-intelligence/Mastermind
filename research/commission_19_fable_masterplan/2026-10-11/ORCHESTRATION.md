# Adaptive C19 delegation with optional management layers

## 1. One useful expanded topology, not a mandatory ladder

```text
FABLE PRINCIPAL - one integration responsibility in existing C19
 |
 +-- native Opus O1: time / identity / evidence
 +-- native Opus O2: events / operating mechanism
 +-- native Opus O3: expectations / macro
 +-- native Opus O4: financial / capital / credit
 +-- native Opus O5: holdings / borrow / microstructure
 +-- native Opus O6: physical / operational / regional
 +-- native Opus O7: evaluation science
 +-- native Opus O8: product / consumer / release evidence
       |
       +-- existing Fabric task operator: bounded admitted task
             |
             +-- execute directly when sufficiently bounded
             OR
             +-- eligible optional worker(s): separable authorized subtasks
```

Fable may commission a worker or self-executing operator directly; a native Opus coordinator may commission a worker directly. Keep a domain coordinator only when it owns meaningful integration or decisions. Workers return to their actual assigning parent, which can be Fable, a coordinator or an operator.

Eight logical seats do not require eight simultaneous processes. The graph may have four responsibility levels, but that is not a claim that any particular installed native/Fabric runtime has proven four-level nesting. Every node retains the original root/grant/capacity lineage. Coordinator nesting does not multiply allowances, source writers, or permissions.

## 2. Native Opus setup using existing definitions

Use the existing Macro `.claude/agents/orchestrator.md` with **explicit model `opus`** for each admitted native coordinator. The profile's method requires the **`fable-mode` skill** before substantive work. Use `ROUTE: orchestration` and the literal line-start labels `MISSION:`, `WHY:`, `SCOPE:`, `OUT OF SCOPE:`, `NOT DONE UNLESS:` and `RETURN:`. Current `.claude/agent-routing.json` is the exact native prompt/guard reference. Do not select a generic fork that merely inherits Fable while labeling it Opus. [S16/S17]

Current official Claude documentation describes nested subagents and version-dependent tool filtering. Child requests still consume usage. These facts support a version-aware design, not a guarantee about the selected local installation. [S20/S21]

No new global agent-team system, orchestration service, memory directory, broad permission mode, model default or concurrency/depth setting is required by this plan. Preserve real permissions; an orchestration label does not make unrestricted shell access read-only.

## 3. Observe each important edge before depending on it

Fable records the actual native child ID/model selection, loaded method, relevant tool capabilities and continuation path. The native Opus coordinator discovers the **existing** admitted Fabric worker or operator action and its exact contract, or consumes the principal's already-observed binding. Source docs for an unarmed stage are not evidence that all alternate existing lanes are unavailable, and a working unrelated lane does not prove this task's eligibility.

First use a harmless authorized read or readiness inspection. A dummy write is not a capability probe. A real operator task is admitted only when the exact source scope, available tools, task class, budget and return path are valid. Do not guess provider identifiers, host/account names or launch schemas.

If a native coordinator lacks the necessary modifying Fabric action but the principal has it, the coordinator returns the exact bounded packet; Fable performs the already-authorized dispatch on the single existing carrier and returns its receipt. This is a transparent dispatch relay, not a claim the child itself dispatched and not a new lifecycle owner. If neither has an admitted lane, preserve that exact gate and advance independent permitted source work; do not rebuild Fabric inside C19 or switch providers to evade a refusal.

An operator may spawn workers only through its actually supported admitted mechanism. If it cannot, it executes the bounded task itself. Native or Fabric child capability is never inferred from a model name. Preserve real denial and unknown-effect fences.

## 4. Responsibilities and write ownership

**Fable principal:** product thesis, exact C19 mission, cross-domain rulings, conflict arbitration, scope/priority, scarce-capacity allocation, independent review selection and final acceptance. Keeps a compact whole-program frontier and actively integrates useful returns.

**Native Opus coordinator:** one domain's technical judgment and continuity. Decomposes only after reading the relevant accepted contract, freezes task interfaces, commissions bounded Fabric worker or operator packets, adjudicates bounded returns, preserves domain dependencies and proposes the next useful task. Does not grind bulk census, logs, ordinary implementation or repeated tests in expensive context.

**Fabric operator:** owns an admitted task from exact source inspection through edits/tests and the permitted delivery boundary. Uses isolated source workspace and actual tool/resource grants. Chooses direct execution versus optional workers by separability and economics. An operator must not silently expand into a new program or merge another worker's conflicting changes.

**Optional worker:** narrow task and explicit output/evidence contract. Reads only needed material. No inherited root-level authority, extra budget, unrestricted secrets or independent source publication. Returns to its actual assigning parent; that parent adjudicates and integrates before returning upward.

One writer controls every shared source seam, worktree and final artifact. Fable arbitrates conflicts on composer/auth/CI/release files; disjoint domain workers do not independently edit these shared seams. A reviewer must be independent where required: excluding the builder identity and providing underlying evidence is more meaningful than asking the same model to agree with itself.

## 5. Efficient context routing

The stable core packet is FABLE_START_HERE + the relevant scope/acceptance rules, not all original reports at every level. A coordinator gets its own prompt, domain packages and exact source register entries. An operator gets the frozen task, allowed paths, smallest needed source excerpts, tests, failure semantics and return destination. Workers receive a smaller subset still.

Suggested default return size is 250-600 words plus immutable artifact references; decisive counterexamples or unusual risk may require more. This is a communication preference, not a rule to omit evidence. Keep full logs/results in existing artifacts. Parent summaries distinguish facts, proposed decisions and unresolveds; consensus between agents is not independent verification.

Resume the same exact eligible coordinator for a related continuation when the runtime supports it and custody is unchanged. Send only new source/evidence deltas. Do not recreate a domain agent for each tiny edit, repeatedly re-read unchanged law, run the full suite after an unrelated documentation change, or assign a second operator to duplicate an already-running task.

Operators should execute small, fully specified work directly. Use workers when they isolate meaningful parallel questions, independent review or substantial mechanical labor. A chain of agents restating the same task wastes resources; a worker does not become frontier-complex merely because it is a subagent.

## 6. Budget, capacity and admission

Fable uses observed current capacity and the approved root economic envelope. Do not hardcode provider quotas or treat native depth as a spending authorization. All coordinator, operator and worker consumption is charged to the original mission allowance through existing owners where supported. Explicit resource types remain separate: model/account quota, host CPU/RAM/disk, test runners, browser seats and source-custody constraints.

Start with the smallest useful active set for the ready dependency graph; increase only when operators can execute independently and the parent can review returns. Backpressure from review, shared CI or a single browser may justify fewer live coordinators than domains. Pause or release idle admitted resources through their existing owners; never create a polling daemon to appear continuously busy.

Use the least-scarce qualified operators and workers once the assigning parent has resolved any material ambiguity. C0/C1 mechanical/routine tasks do not deserve Opus merely because C19 is important. Escalate a difficult bounded task on actual counterexample or ambiguity, preserving the same effect/custody rules. Do not route across accounts or providers to get a refused effect through.

## 7. Measure efficiency rather than claim it

Use available telemetry from the current runtime/provider. Keep totals for principal + coordinators + operators + workers, distinguishing input, output, cache reads/writes and money when actually reported. Add accepted output count, review/rework cycles and repeated retrieval burden in existing task evidence. Missing cost data remains unknown; do not estimate invisible usage as zero.

A useful local comparison is a small family of similarly bounded tasks run with direct-operator versus worker-assisted execution under the same acceptance bar, provided it does not duplicate real work or burn scarce capacity solely for benchmarking. Compare total accepted work and rework, not just lower parent-context volume. Do not run a second architecture experiment before useful product work can begin.

Savings are an engineering hypothesis. The hierarchy should lower duplicated frontier reasoning and isolate verbose labor, but more levels can increase coordination cost. Collapse an unproductive layer rather than defending the diagram. It is fine for a capable operator to do the entire task.

## 8. Continuation, effects and returns

Delivery, pickup, started execution, a PR, merge, deployment and product acceptance are different evidence. Every asynchronous/native/Fabric action carries its actual parent/carrier and a real return path. Native UI background execution is not proof it will continue after the provider session ends; external durable execution needs an actual owner.

After an ambiguous modifying reply, freeze the original effect and reconcile its target before retry or rebind. Never create a replacement child/key to escape uncertainty. Preserve original C19 request and custody obligations. A stopped independent child does not self-assign a successor merely because the program remains open.

Checkpoint at coherent milestones, then resume the next safe task while healthy. Fable keeps accepted/rejected work, DO_NOT_REDO, active children, scope, source refs, side effects, uncertainty, gates and next action in existing durable owners. No second memory/lifecycle store. No role treats a clean phase boundary as mission completion.
