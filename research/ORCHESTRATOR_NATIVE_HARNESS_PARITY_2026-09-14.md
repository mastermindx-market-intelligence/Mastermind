## Outcome and recommendation

Every qualified COO should be able to receive adequate current context and tools, request bounded children, wait without unchanged-state reasoning calls, consume exact results, request independent review/repair, resume in the correct session, and return a useful accepted artifact without Chairman message-shuttling. Equal operating capability does not require identical native tool names.

Do not rebuild Claude's runtime and do not make it the company's sole orchestration engine. Extend the **existing `OperatorHarnessAdapter`** for rich operators, retain `WorkerExecutionAdapter` for sealed bounded jobs, and qualify three immediate runtime families: Claude Code, Codex App Server, and ACP with separate Grok/Cursor provider manifests. GLM is a provider/model which can occupy more than one qualified harness; it is not itself a harness. No parallel SessionContinuation service, watcher database, session registry, queue, transcript store, authority plane, or provider broker is needed.

The first reference journey should deliberately have **no Fable/Claude dependency in its execution path**: a managed Codex parent requests lawful child work, yields, receives a real canonical return, obtains independent review/repair, consumes the exact accepted result, and issues the appropriate continuation/STOP. Then prove the same journey with the other harness families. A heterogeneous pair additionally requires the separately admitted child-placement envelope; a work plan cannot widen its own provider authority.

## Native-feature interpretation and previous assumptions to retire

Official current documentation was consulted for Claude, Grok, Cursor, Codex and Z.AI. Treat it as version-sensitive evidence, not permission or proof of effective installed grants. Native primitives should be adopted with their actual limits.

Retire the blanket claim that Claude `--bg --resume` always forks; current behavior depends on version, identifier and copy choice. Likewise, `respawn` is not unconditionally safe continuation when required transcript data is absent. Validate returned identity and recovery state.

Do not confuse local Claude `notify_when_idle`, native subagent completion, an external Channel, a monitor and a recurring model timer. They have different scopes, lifetimes, costs and provider restrictions. A local idle notice is not a successful work result. Separate config homes are not by themselves an OS-user/peer-message security proof.

Provider guide examples can conflict with desired native tools. Specifically, Z.AI's Claude example and Anthropic's Monitor/privacy-setting conditions require effective-profile testing; do not remove privacy controls merely to gain a watcher. Later-version task defaults must not be projected backward onto installed 2.1.259. Native monitors/background commands are not automatically restored after restart.

Grok has its own native subagents/background monitors/session continuity. Its documented hook error behavior can fail open, so a workflow hook is not the sole enforcement boundary for authority or source custody. Cursor ACP requires responses to permission requests and blocking `cursor/ask_question` / `cursor/create_plan`; ignoring them can strand an operator. Cursor's team-dashboard MCP grants do not automatically become ACP grants. Native child model/tool inheritance must be observed, not inferred from marketing or a desktop UI.

### Event-to-continuation contract

```
canonical source transition
 -> source-owned semantic classification
 -> existing durable Wake obligation
 -> exact current action target + RuntimeBinding
 -> provider-native attention input through the current writer
 -> canonical read and explicit consumption
 -> lawful next action / typed blocker / terminal STOP
```

- Derive ordinary child-return attention from the existing parent-child relationship; do not require every model to invent a second watcher.
- Close the registration race: preserve source revision/baseline, establish observation, and recheck a child that may have finished during registration.
- Retain/coalesce attention while the parent is busy. Use exact-turn steering only when actually supported; never start a second writer.
- Preserve one authoritative native event-stream reader. Observability consumes an existing bounded projection and must not steal completion/approval events.
- Provider acceptance, delivery, target consumption, work acceptance and source resolution remain separate. A printed status or native idle callback does not collapse them.
- After possible submission, a lost reply is same-operation effect uncertainty. No blind replay, new-session fallback, account switch or host failover.
- Restart recovers the current binding/profile/source facts. Missing transcript, changed credentials/config or unknown writer state produces a typed boundary, not a replay of the original objective.
- Child STOP removes only that child source from a shared watcher. A stale unremoved source cannot restart terminal work or disable sibling/seat continuity.
