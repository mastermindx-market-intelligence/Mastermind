## 3. Architecture: one evidence-to-learning loop

1. **Observe once.** Land licensed original bytes and immutable source references through existing collectors. Preserve issuer/security/event identities, corporate actions, constituents, source versions and corrections. Keep publication time, acquisition time, economic event time and decision cutoff distinct. Unknown historical availability remains unknown; it is not replaced by a convenient timestamp.
2. **Compile states and episodes.** Extend Market Memory's existing feature/source contracts. Daily and weekly states reference canonical prices, financial facts, expectations where licensed, macro vintages and relationships. Episodes represent sequences, including quiet periods, failed analogues and terminal outcomes. Ordinary days receive structured updates; expensive narrative analysis is change-triggered.
3. **Retrieve time-correct experience.** Filter by as-of eligibility, rights and identity before similarity retrieval. Separate actual operational output from present-day historical reconstruction. Similarity uses pre-outcome features; future success must not determine analogue selection. Return relevant failures and mismatches alongside successes.
4. **Test mechanisms.** Keep observed relationships, associations and causal hypotheses typed separately. A hypothesis names direction, horizon, enabling conditions, alternatives and falsifiers. Theme membership alone is not economic transmission. Independent evidence is counted by original source, not agent agreement.
5. **Estimate and explain.** Domain models produce distributions or abstention under their accepted authority. Compare simple baselines, tabular learners, sequences and graph enrichment before adding complexity. LLMs extract and synthesize evidence; deterministic code owns timestamps, returns, arithmetic and evaluation. An LLM's persuasive confidence is not a calibrated probability.
6. **Grade and revise.** Preserve the frozen information set, source/model/prompt/code hashes, target/horizon, forecast, abstentions and eventual outcome through the existing evaluator/ledger owners. Corrections append; prior forecasts are never rewritten. New model versions are challengers, not self-promoting production replacements.

A pilot integration view needs references to source identity and source revision; known-at clocks and quality; universe and price-basis versions; feature-contract version; historical reconstruction versus actual-output mode; episode selection/eligibility; evaluator/trial reference; model and prompt versions; target and label-maturity clocks; rights and missingness; and outcome review. This is a crosswalk into existing owner schemas, NOT a new universal persistent schema or service. Freeze the crosswalk before changing closed contracts such as event_workspace.v1.

**Storage decision:** retain the accepted Data OS files + Parquet + existing R2 ownership, with existing SQLite derived indices where appropriate. Do not migrate market data to Postgres/DuckDB, add Redis, a feature-store service, a vector database or a message bus without measured evidence and separate architecture acceptance. Embeddings and retrieval indices are replaceable derived artifacts, never evidence authorities. Bulk documents, tensors and checkpoints do not belong in Git. Runtime receives immutable references and compact receipts, not large source handoffs through Studio Direct.

**Physical separation:** production serving reads accepted snapshots; backfills cannot consume its full CPU, memory or API budget. Research reads immutable snapshots and owns no live-data writer. Each shard has one admitted writer and idempotent output identity; interrupted effects reconcile through the existing owner. Publication switches only after complete validated output, never midway through a shard. Backups need a tested restore and independent failure domain; another directory on the same SSD is not a backup.

## 5. Capacity and economics: hypotheses, not promises

`python3 research/market_experience_capacity.py` is a pure, tested arithmetic calculator. It makes no provider calls and grants no budget. All scenarios use constant covered slots, not a verified historical constituent census. Full coverage and terminal events need actual membership manifests. Decimal GB below means 1e9 bytes; installed RAM is reported in GiB.

| Workload assumption | Pilot | Expanded daily/weekly target |
|---|---:|---:|
| Issuer slots / years / sessions per year | 50 / 5 / 252 | 500 / 30 / 252 |
| Stock-day rows | 63,000 | 3,780,000 |
| Quarterly event opportunities (not verified eligible events) | 1,000 | 60,000 |
| Unique core documents, assumed 8 per issuer-year | 2,000 | 120,000 |
| Dense 512-feature float32 values only | 0.129 GB | 7.741 GB |
| Text input/output per single pass | 24M / 2M tokens | 1.44B / 120M tokens |

The dense-feature number excludes identifiers, masks, revisions, intermediate arrays, source bytes, text, embeddings and replicas. Plan a measured 4-10x working-set sensitivity rather than claiming 8 GB is the complete system. One-minute data multiplies rows by about 390 under a regular-session-only assumption: roughly 1.47B bars in the larger scenario. Options surfaces, ticks and order books are separate licensed and benchmarked expansions, not included in this budget.

Current official reference rates, observed 2026-09-24 (USD per million input/output tokens): GLM-5.3-Flash 0.15/0.50; Grok 4.3 1.25/2.50; GLM-5.3 1.40/4.40. These are price comparisons, NOT proof of equal quality, approved route availability or adequate quota. Assumed 12,000 input and 1,000 billed output tokens per document must be replaced by measured token distributions, including billed reasoning. No cache, batch or free-tier savings assumed.

With a 3x processing allowance for additional passes, review and repair, the pilot core-document token scenarios cost $13.80 / $105 / $127.20; the expanded core-document scenarios cost $828 / $6,300 / $7,632 respectively. This allowance is cost sensitivity, never automatic retry authority. Repeating the same analysis on every stock-day instead would cost $26,082 / $198,450 / $240,408 in the larger case. That 31.5x ratio follows from these selected document/row assumptions, not a measured optimization result. None includes data licenses, engineering, human review, search calls, taxes, training, electricity or the broader news/tick/options corpus. A failed cheap extractor can be more expensive per accepted record than a stronger one.

An optional broader incremental workload of 20,000 documents/month at those lengths and 3x processing implies $138 / $1,050 / $1,272 in token costs. This is a scenario, not a measurement of current traffic. Rate limits, long-tail latency, retries, document length and acceptance rates determine throughput. Required fleet throughput = admitted work / processing window; scale only from measured end-to-end accepted records per second.

**Storage:** use 0.1-0.5 TB pilot working allowance and 1-5 TB broad daily/weekly archive allowance as unmeasured capacity targets, then revise from actual bytes per admitted source and retention policy. R2 Standard lists $0.015/GB-month, so 1-5 decimal TB is about $15-$75/month for storage before applicable free allowance, requests and other services. Replicas/backups and restore tests are additional obligations. Long contexts, replicated corpora and fine-grained objects can dominate inference/request cost; deduplicate originals and batch appropriate derived partitions.

**Training:** no new foundation model or permanent GPU fleet is required to start. Begin with deterministic features, retrieval, simple baselines and CPU-friendly tabular models. Reserve 100-500 CPU-core-hours as an initial experimental envelope, not a forecast of consumption. Benchmark first; trial counts remain preregistered. For a later admitted sequence/graph experiment, 100-1,000 GPU-hours is a sensitivity band, not a requirement or spend approval. Official Lambda single-instance examples are A6000 48 GB at $1.09/hour and H100 SXM 80 GB at $4.29/hour, implying $109-$4,290 across those illustrative combinations before tax and other charges. Do not mix multi-GPU per-GPU pricing with single-instance pricing. Rent a bounded accelerator experiment only if it addresses a measured limitation; no purchase is justified yet.

**Live hardware observations in this session:** m2studio reported 192 GiB RAM and 24 CPU cores. Each of mini1, mini2 and mini3 reported 16 GiB and 12 CPU cores; their available local data volumes were approximately 153/110/130 GiB. These are installed resources, not admitted spare capacity. The Studio's shared external volume previously reported about 1 TiB available. CPU/GPU throughput and PC accelerator inventory are NOT benchmarked here. Three 16 GiB machines are not a single 48 GiB accelerator; placement and memory remain per-host constraints.

Proposed starting placement profile: one medium CPU shard per 16 GiB mini, capped initially around 4 cores and 6 GiB, or smaller light shards inside the same total envelope; retain OS/CI headroom and small disposable caches. Large joins belong on an admitted high-memory host, not duplicated on every mini. Training runs in a reserved batch lane; production and CI retain their existing guarantees. These are recommendations to the existing Capacity owner, not host assignments or changes to the other session's load-balancing work.

Initial recommendation is to use owned CPU capacity and an incremental API pilot ceiling of $250, with zero new GPU or data-contract commitments until F0 has measured costs and checked entitlements. This is a proposed envelope for approval/admission, not spending performed here. Larger licenses, redistribution/ML rights and recurring commitments require explicit quotations and authority. Marginal energy = measured incremental kWh times the applicable tariff; no electricity price is assumed.

## 6. Learning and acceptance

Memory accumulation is not gradient training. Retain facts, sequences and errors first; use retrieval and deterministic reconstruction before fine-tuning. Unsupported model explanations are not training truth. Version extraction, prompts, retrieval policies and numerical models separately. Curriculum: data/time correctness; earnings/expectation changes; persistence versus failed follow-through; peer relationships; rotations; cross-asset propagation; advanced sequence/graph learning after simpler baselines.

Freeze source-stratified gold and chronological holdouts before inspection. Zero critical temporal/identity violations in the registered test set is a data-admission requirement, not proof of general perfection. Measure extraction precision, coverage and typed refusal separately. Test revised data, survivorship, overlapping labels, fitted-on-test preprocessing and LLM parametric foreknowledge. Once inspected, a holdout becomes development evidence for successors. Replaying a crisis does not create independent crises.

Register experiment families and failed variants through existing owners. Compare no-memory, no-graph and no-LLM ablations at identical cutoffs. Fix minimum useful effect, power plan, target and primary horizon before results; use time/event-clustered uncertainty. Evaluate calibration, incremental proper scoring, useful lead time, false alerts, accepted-record cost and real user workflow completion. Economic utility and trading promotion remain separate. Graph size, token use and narrative fluency are not acceptance measures.
