## 3. Autonomy V1 definition of done

Autonomy V1 is complete only when the Chairman can run the primary journey below on the real production path with no manual prompt carriage between agents and no hidden terminal babysitting after the initial intent.

### 3.1 Primary Chairman journey

1. Chairman gives one bounded outcome to a Personal-Pro Sol surface.
2. Sol has fresh runtime state and can submit/reconcile one typed CEO request through the accepted Personal-Pro ingress path.
3. Executive OS admits exactly one canonical root Job and owns all downstream lifecycle state.

10. Executive OS reconciles/terminalizes the operation and exposes the real result/exception; GitHub and Agent OS receive the durable implementation/outcome records; Control Room projects enough state that the Chairman can see what is running, blocked, waiting for attention and why.

## 8. Speed laws / barrier removal

### 8.1 Infrastructure CI is not a redesign trigger

If a semantic CI pack dies before tests because checkout/runner infrastructure fails while sister packs are green, rerun only the failed jobs on the same exact head. Do not rewrite code, re-run independent design work, or spawn a replacement branch merely because infrastructure dropped an evidence fragment.

### 8.2 High-churn Macro main does not create an infinite rebase treadmill

For source-law/material-grounded PRs:

1. identify the exact material authority/source set;
2. check whether those paths/decisions moved;
3. unrelated render/data churn does not invalidate semantic implementation proof;
4. do one release-time current-main reconciliation if needed for mergeability;
5. rerun only proof invalidated by the resulting candidate head;
6. if current main moves again only on unrelated paths while the carrier remains mergeable/current under repository rules, do not restart the cycle.

Material source or authority movement still forces a real return to Sol.

### 8.3 No serial mega-session

A long-running session may coordinate its own bounded subagents, but it may not reserve future dependent waves simply to keep context warm. Fresh operator sessions should pick up frozen source law and one carrier.

### 8.4 No repeated Chairman permission asks

The current Chairman mandate authorizes ordinary implementation, review, merge/release decisions within accepted architecture, production canaries, host installation, routing/fan-out enablement and provider expansion needed for this program.

Return to Chairman only for a genuinely external/privileged decision that cannot be safely delegated, including:

- passwords, OTPs, device-confirmation or provider account-selection interactions that require human presence;
- purchases/plan changes or material commercial spend policy not already accepted;
- rights/legal/business decisions not recoverable from durable source law;
- a proposal that materially changes the Chairman's product outcome or expands authority beyond this program.

### 8.5 Proof once, reuse honestly

Do not rerun a completed proof unless a named state change invalidates the receipt. A changed implementation head may invalidate code/CI proof; an unrelated repository render commit does not automatically invalidate a provider account canary; a credential change does invalidate readiness; a service restart may invalidate a PID-bound boot canary.

### 8.6 PRs remain vertical

One independently useful capability per PR. Parallelization happens through multiple disjoint carriers, not through one giant merge bomb.
