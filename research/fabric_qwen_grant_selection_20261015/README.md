# Select the exact broker-granted Qwen account

A remote Qwen launcher asked the host-local key picker for a soft `--prefer Kris`. When Kris was unavailable, the picker reserved Ryan; the existing outer-lease equality guard then correctly stopped before credential export or model execution. Two retained terminal75 failures establish this handoff defect. Their results do not establish whether Kris was missing, cooling, excluded or at local capacity, and neither failed operation is retried or replaced.

The launcher now passes `--require` for an outer lease. The existing picker restricts candidates under its existing lock to that exact account and reports a fixed, nonsecret reason if unavailable: `not_configured`, `excluded`, `cooldown` or `at_capacity`. It never reserves a different account. The post-selection equality guard stays in place, including protection against an old or misbehaving helper. Unleased soft preference, existing 429 soft-cap rules, other cooldowns, capacities, provider/account credentials, model selection, broker ownership and result acceptance are unchanged.

This is a prospective selection/diagnostic repair, not credential provisioning or a claim that every host has the granted account. The broker's existing Bailian gate observes controller-local capacity/cooldown; it does not have GLM's host/account readiness filter. A real host availability mismatch still needs its original supported observation/owner path. No historical account mapping is inferred or fabricated.
