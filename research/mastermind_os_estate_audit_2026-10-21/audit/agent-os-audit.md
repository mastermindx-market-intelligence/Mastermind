### Delegation contract

Each Fabric task should include the parent operation/carrier, exact source SHA and target paths, existing owner, bounded question or allowed patch surface, explicit forbidden effects, expected artifact/return schema, meaningful acceptance test and escalation trigger. Opus should fan out independent investigations or disjoint paths, keep one writer for an owned carrier, and bring repair rounds back to the same child. Agent count is a capacity decision, not evidence of progress.

Fable retains programme architecture, prioritization across lanes, authority/ownership conflicts, experiment identity and final outcome acceptance. Opus retains security-sensitive integration, ambiguous source custody, original-effect reconciliation, cross-owner composition and difficult debugging. Fabric handles bounded source census, exact diffs, tests, parser adapters, deterministic fixtures, evidence packaging and other work whose correctness can be independently checked. Fable and Opus may implement hard tasks where transferring the task would lose the necessary judgment or create excessive integration risk.

Do not respawn the existing off-TCP suborchestrator, original native review, held OL-V1 effect, or another historical operation merely because its old chat is unavailable. The current authorized receiver recovers its canonical effect state and continues through its owner. An unresolved operation is neither a live worker nor a free slot to replay.

2. **In parallel, finish source-only follow-ons with disjoint ownership.** Context source-disposition reconciliation, Atlas JS/TS, compiler packet quality and prospective evaluation design can progress without starting the host or touching credentials.
3. **Qualify real integration and selected native consumers.** Context owner composition/auth and combined native candidate acceptance converge; preserve original uncertainty and source custody.
4. **Run the Context benchmark/production journeys after the actual path exists.** Only accepted evidence unlocks protected cold-start enrollment.
5. **Run real E1 and OL-V1 when their separate design and Executive gates permit.** Do not make records/parser work wait for credentials, and do not use unrelated source progress to imply readiness for effects.
6. **Close only the achieved scopes.** Mark source accepted, installed, exercised, and owner-accepted separately; publish exact results to existing Agent OS records and existing PR/issue carriers. The parent handles consistent Linear projection and whole-estate completion.
