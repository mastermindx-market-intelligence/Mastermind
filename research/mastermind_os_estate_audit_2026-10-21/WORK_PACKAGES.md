# Bounded completion work packages

**43 planning references, not 43 admitted Jobs.** These packages decompose the existing programme. They do not create a dispatch queue, assign fresh roots, grant production effects or replace incumbent branches. Current owner law and the actual assignment control. Source IDs resolve in `SOURCE_REGISTER.md`; exact candidate heads are in `PLAN_AND_PR_CROSSWALK.md` and `audit/pr-snapshot.json`.

## How to use

Fable owns the integrated outcome and O1–O6 own domain integration. For each ready package, the Opus owner narrows its proposed path areas to exact files and actual custody, resolves the real root/parent/grant/host, and splits routine labor into small paid Fabric tasks. C0/C1 leaf work should use the least-scarce qualified worker; C2 work remains bounded and independently tested; unresolved C3 questions stay with Fable/Opus. Direct principal implementation is available for genuinely hard tasks or unique authorized access, with independent review.

**Priority:** P0 controls correctness or the next acceptance path; P1 is still required adopted scope, not optional polish. **Stage** indicates the main acceptance phase. Dependencies govern acceptance/effects; safe disjoint source preparation can proceed earlier unless a specific source gate forbids it. A gate on one lane does not stop the other ready lanes.

The proposed directory scopes below are planning bounds, not blanket write permission. Before dispatch, name exact files and current writer/lease. No worker may edit shared runtime migration files, `App.tsx`, `host.ts`, auth glue or plugin installation paths concurrently with another owner. Bind finite task/elapsed budgets and preserve review/repair reserves.
