## 2. Execution and evidence contract

### Owners and independent judgment

- **O1:** Executive release/runtime; actual existing host/release owner performs privileged effects.
- **O2:** Fabric hierarchy, capacity, quota and economics.
- **O3:** Mastermind OS product, web/native clients and distribution.
- **O4:** Agent OS, Context, continuity and semantic projection composition.
- **O5:** Principal authority, native adoption, Dialogue/Wake and role packages.
- **O6:** Independent integrated acceptance and learning. Appoint a qualified reviewer who did not author the consequential change; assign a different reviewer if O6 authored it.
- **Fable:** original-intent interpretation, cross-domain decisions and final outcome acceptance. Fable/Opus may perform difficult work; that does not replace required independent review of their changes.

Each table names accountable domains, not already running workers. Bind the actual executor/reviewer identities and scope at admission. Fabric can collect evidence, exercise bounded cases or implement isolated test adapters. Security decisions, ambiguous effects, schema composition, full-product judgment and reserved decisions stay with the appropriate Opus/Fable owner. Review and repair capacity counts against the actual root budget.

### Every executed case must return

1. **Case and claim:** case IDs, intended milestone, original requirement, exact positive and adverse conditions, expected outcome and observed outcome.
2. **Identity and provenance:** protected/candidate revisions; per-component build/release/config/installed/selected/accepted generations; timestamp; surface/host/viewport; nonsecret principal, audience, role, account/provider/mode facts that were actually observable.
3. **Original operation:** work reference, root, true immediate parent, child/Attempt, grant/policy revision, lease where applicable, original request/pointer and relevant intent/draft/decision revision. Preserve original uncertain operations.
4. **Connected evidence:** bounded network/owner event references, full retained-result identity/digest, exact reviewer disposition and original-parent consumption event/read. Link large artifacts rather than copying logs or credentials. UI capture demonstrates presentation, not authority or backend consumption by itself.
5. **Effect accounting:** before/after observation of the actual owner; effect/refusal/recovery/cleanup outcome; explicit absence of a second publication, submit, Job or effect where required. A completed child, delivered event, queued message or `parentConsumed=false` receipt cannot be labeled parent consumption.
6. **Verdict and limitation:** PASS, FAIL, BLOCKED, UNEXECUTED, or SCOPE_DECISION_REQUIRED; exact affected scope; independent reviewer; material invalidators; next action. No generic “all green” without these fields.

Use focused source tests and isolated/staging failure injection before admitted live proof. Never disrupt an unrelated production worker to demonstrate a failure. A denial test uses an approved harmless controlled case; it does not retry an existing disputed production action. Reconcile original denial receipts and current applicability without rerouting an actual denial or unknown effect. A meaningful live journey is still needed after fixtures pass.

Evidence reuse is materiality-based. A changed auth, parent, schema, release or result boundary invalidates the affected proof. An unrelated protected-master movement does not automatically require every suite and campaign to restart. O6 records the affected-case decision; historical receipts retain their original dates/revisions.
