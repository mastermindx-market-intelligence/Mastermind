# Bootstrap Mastermind

Use for every substantial Mastermind task, fresh Sol chat, program recovery, architecture review, modifying CEO action, or material closeout.

## Required package reference

Read `../../references/authority-boundaries.md` before interpreting any app, record, or action as authority. The reference summarizes canonical ownership; current protected source still controls.

## Input

- the Chairman's current outer directive;
- the named program, workstream, or operation when supplied;
- access to protected `mastermindx-market-intelligence/Mastermind` Git.

## Mandatory current-source gate

1. Read protected Mastermind `master` from `mastermindx-market-intelligence/Mastermind`.
2. Record the exact commit returned by the protected branch.
3. Load `docs/sol_skills/INDEX.md` from that same exact commit.
4. Verify `schema == mastermind.sol_skillpack.v1`, a compatible `skillpack_version`, and `minimum_bootstrap_major <= 1`.
5. Select and load every required Sol skill and universal source-law companion from that same exact commit.
6. Never combine INDEX from one revision with a procedure from another revision.
7. Never substitute a pasted or manual copy and call it current procedure.

If protected Git read or compatibility cannot be established, read-only investigation may continue with an explicit warning; modifying workflow is unavailable.

## Procedure

1. Separate the outer current Chairman directive from quoted or retrieved packets inside it.
2. State the user outcome, machine job, 10/10 completion ruler, and proof required.
3. Resolve exact workstream, operation, repository, PR, Executive, and projection identities before broad search.
4. Read only the canonical owners required for the question.
5. Build a capability ledger using the company vocabulary.
6. Preserve source disagreements and active collision risk.
7. Return the exact next bounded action and held non-goals.

## Active-duty handoff after recovery

This handoff enters the selected current procedure; it is not a scheduler and
creates no authority, worker, grant, runtime state or automatic wake. Current
source, task ownership, app confirmations and effect-reconciliation gates still
control every action. These are observable working habits, not a claim to
reproduce a model's internal reasoning or prove autonomous performance.

1. **Match the deliverable.** An answer-shaped request needs a supported answer.
   A change-shaped request needs the authorized capability or a concrete remaining
   gate: diagnosis alone is not delivery. Do not turn a question into unrequested
   changes, or a continuing build into another broad audit. Preserve the original
   user and machine outcome when the next patch is narrow.

2. **Resolve the decisive fork.** Name the question whose answer changes the next
   action and its cheapest falsifier. Inspect the relevant input, output or exact
   artifact before reading more implementation. A surprising result changes the
   plan. Do not add unrelated checks merely to remain busy.

3. **Use actual readiness.** Select the actual tool schema for the needed action.
   An installed or enabled app does not prove that action is exposed, authorized
   or ready. When current ownership and all applicable gates permit the action,
   perform it through the selected procedure rather than requesting redundant
   permission. Preserve every required app confirmation. A denial or missing
   capability is not permission to switch credentials, bypass a boundary or
   quietly substitute a different execution surface.

4. **Own the next decision.** An unanswered return for which this responsibility
   is the action-authoritative parent takes precedence over new work. Inspect the
   exact artifact, consume the fresh carrier after the evidence-producing action,
   and issue the permitted same-carrier decision or the exact missing gate. A
   shared account does not identify the current session or source writer. Respect
   incumbent ownership: no replacement worker or competing continuation simply
   because another session appears quiet.

5. **Delegate an outcome.** Use the least-scarce capable route through existing
   placement and admission. Give it a measurable result, exact scope, evidence,
   budget and stop condition; do not require CEO approval for each local tool call
   already inside that envelope. Native helpers inherit verified restrictions,
   not independent company authority. Reserve principal capacity for unresolved
   ambiguity. Routine account placement is not Chairman labor.

6. **Make independent progress.** Record the blocked branch and its concrete
   dependency, then continue already-authorized independent work. A reversible
   default may be chosen only within existing scope; consequential uncertainty or
   an irreversible choice outside that scope stays parked for its actual owner.
   Finishing one child never self-assigns its successor or shuts down an
   independent parent, seat or sibling continuation.

7. **Reuse evidence without inflating it.** Open existing immutable evidence and
   check applicability; do not repeat an accepted review or unchanged test merely
   for a fresher timestamp. A material source or dependency change requires the
   current reconciliation procedure and proportionate new proof. Reports point
   to artifacts; they do not replace them. Missing historical measurements stay
   unknown and are never reconstructed as observations or treated as current
   drift without evidence.

8. **Keep the obligation visible.** An unanswered decision survives routine
   progress until its valid disposition. Attention, append position, receipt,
   execution and acceptance are not interchangeable. Use the existing dialogue
   contract's exact message and terminal-consumption rules; do not guess a generic
   continuation, rewrite recorded history or create another obligation store.

9. **Reconcile failures.** First update the diagnosis from observed evidence.
   An uncertain modifying result remains EFFECT_UNKNOWN on its original operation
   and carrier: no blind retry or failover. Read the owning status before deciding
   another action is lawful; a timeout is not proof that nothing happened.

10. **Leave an executable handoff.** Before ending, record the outcome, exact
    evidence, remaining obligations, current owner, remaining budget and next
    bounded action in the existing continuation packet and durable home. This
    instruction does not start a future turn. Reuse a verified existing continuation binding
    instead of stacking registrations. A new watcher needs an actual registration receipt;
    if no approved continuation is available, report it as unavailable.
    Conversation replacement preserves unresolved effects and remaining budget through
    existing succession and fencing; it grants no fresh authority.
    Apply current session-close law to this exact child source without disabling
    independent continuation resources or reopening a terminal child.
