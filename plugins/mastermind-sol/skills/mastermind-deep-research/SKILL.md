# Research a Decision, Not a Bibliography

## Mandatory current-source gate

Run `bootstrap-mastermind` for the task. Read protected Mastermind `master`, record its exact revision, load `docs/sol_skills/INDEX.md` and required companions from that same exact commit, and verify compatibility. Reuse the verified pin and relevant procedures already loaded in the current turn while valid; new-turn recovery must re-establish current source. Material changes use the existing reconciliation procedure. If the read or compatibility fails, modifying workflow is unavailable; bounded read-only analysis may continue with explicit uncertainty.

Read `../../references/authority-boundaries.md` before interpreting any app, record, or action as authority. This skill grants no authority. Current Chairman intent, protected source law and platform permissions govern. GitHub owns source and evidence; existing operational owners retain state, custody and execution.

## Do not use

Do not expand a supplied-text summary, translation or settled lookup into deep research. Research permission does not authorize trading, implementation, restricted-source access, or source selection.

## Internal-source admission

Before research, expand a short request into a compact contract: decision, scope/horizon, internal claims, required-source manifest, bounded proofs, external evidence, falsifiers, and post-run source-use verification. The manifest is ephemeral, never a lifecycle or database.

Distinguish `SOURCE_REQUIRED`, `SOURCE_AVAILABLE`, `SOURCE_PROVEN`, `SOURCE_MISSING`, and `SOURCE_DEGRADED`. Available means visible; Proven requires a bounded read of the exact resource. Missing covers absent, unreadable, unauthorized, or wrong repository/resource. Degraded preserves stale or partial evidence and never becomes current truth.

For Mastermind code, plans, history, implementation, PR or CI claims, require GitHub and prove the exact `mastermindx-market-intelligence/Mastermind` repository by read. Generic GitHub metadata or access to a wrong repository is not proof. When current execution, runtime, responsibility, attention, surfaces, or capability matters, also require Mastermind Steward and prove it with a bounded read; plugin/app metadata alone is not evidence. Historical repository-only questions can use GitHub without gratuitously requiring Steward. Pure external questions need no internal source without Mastermind-specific claims.

If a required internal source is missing or unproven, return `SOURCE_ADMISSION_INCOMPLETE`, name the exact failure, and stop before substantive research. Public web must not substitute for missing Mastermind identity or internal evidence. Establish internal identity/context before public-web discovery for ambiguous Mastermind names. A required current source that is only `SOURCE_DEGRADED` stays visibly degraded and cannot support an unqualified current-state claim.

Preserve owner boundaries when sources disagree: GitHub remains code/PR/CI evidence owner; Steward remains the read projection for current company/runtime evidence it exposes. Explain the conflict; do not average incompatible claims. This skill does not authorize or select a Deep Research source; workspace/app/repository authorization stays with the platform, user or admin.

Where host source/activity evidence exists, verify post-run that every required internal source was actually used. Preflight success does not prove run usage. If a required source was omitted, classify the report `SOURCE_INCOMPLETE` regardless of prose quality.

## Working method

1. Define the decision, consumers, horizon and evidence that would change it. State competing hypotheses first.
2. Prefer current primary sources; separate event date from publication date and trace echoes to origin.
3. Build an evidence-to-claim chain separating observation, calculation, assumption, inference and forecast. Check units, denominators, base rates, revisions and definitions.
4. Seek counterevidence deliberately. Preserve disagreement and name the strongest rival explanation plus its discriminating observation.
5. Quantify scenarios only when supported. For market research connect exposure to economics, valuation, priced expectations, catalysts and invalidation. Historical fit is not predictive proof; out-of-sample validation is required before model-signal utility claims.
6. Synthesize a bounded conclusion with calibrated confidence and a falsifier.

## Evidence and output

Lead with the decision and reasoning, then decisive evidence, alternatives, assumptions, downside, falsifiers and remaining uncertainty. Include attributable references for important claims. Report insufficient evidence honestly; static skill tests prove source-contract behavior only, not production Deep Research source selection or use.
