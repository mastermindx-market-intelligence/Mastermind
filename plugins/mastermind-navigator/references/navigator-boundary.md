# Navigator boundary

`mastermind-navigator` is a read-only orientation and routing package. It projects evidence supplied by existing owners; it does not become one of those owners.

## Hard boundaries

- No truth database.
- No lifecycle.
- No capability registry.
- No permission authority.
- No session registry.
- No static liveness list.
- No omnipotent Mastermind MCP.
- No connector, browser, shell, deployment, data, design, or communications authority by virtue of package presence.
- No claim that installed means enabled, connected, callable, authorized, or `PROVEN_LIVE`.

## Owner-preserving rules

Executive OS remains lifecycle owner. Agent OS remains organizational-continuity owner. GitHub remains source, PR, review, and CI owner. Workbench remains selected-project owner. Studio Direct and the existing Fleet/Capacity lineage remain host/process owners. Worker Browser remains its browser owner. Web-Sol and RuntimeBinding remain exact ChatGPT target owners. Domain systems retain their own deployment, data, design, and communications effects.

The package may read current owner-native observations, normalize them into the closed health envelope, filter them for one explicit role, and recommend the smallest owner-native probe. The recommendation grants no new authority and must be rechecked at the effect boundary.

`UNKNOWN` is not upgraded by a plugin name, a connector listing, a stale boot packet, or confident model prose. `EFFECT_UNKNOWN` stays on the same carrier and owner-native reconciliation path with no blind retry or failover.

## Installation ceiling

The package-local catalog fragment is integration material only. Repository source, shared-catalog admission, workspace installation, enablement, authentication, callability, organizational authorization, and a real canary are separate states and must be reported separately.
