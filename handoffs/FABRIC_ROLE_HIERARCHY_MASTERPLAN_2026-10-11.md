## Findings established so far

1. The intended four-role hierarchy is a useful optional structure, not a reason to impose all four layers on every task. The optimization target is verified accepted outcomes per total cost and scarce capacity, including briefing, verification and repair.
2. Protected routing law already separates topology, task complexity, business impact, execution risk, ambiguity and capabilities. It explicitly rejects automatic model promotion because a task is a subagent.
3. Accepted subscription profiles map GLM routine/fast/subagent to GLM-5.3-Flash and hard to GLM-5.3; Qwen routine/fast/subagent to qwen3.8-flash and hard to qwen3.8-max; all configured MiniMax classes to MiniMax-M3. Those are model classes, not responsibility roles.
4. The accepted sealed Claude subscription worker denies shell, native child spawning, Skill, web and MCP tools. Its subagent-model environment variable does not prove recursive execution ability.
5. The installed attended M2 pool is a distinct observed execution path. Its task/tier vocabulary includes executor/labor, operator/review and orchestration, plus separate complexity checks. Exact precedence, prompt contents and descendant permissions are being traced.

It shares 16 total descendant Jobs across planners, coordinators, work, review and repair. It is unmerged source, not installed/live proof.

A native Opus agent can use an admitted external Fabric tool without further native nesting. Actual client version, effective settings and installed tool availability must be proved separately.

## Current working decision

Separate:
- responsibility role: principal, sub-orchestrator, operator, worker;
- existing orchestration phase: plan, work, review, repair, aggregation;
- bounded task complexity and ambiguity;
- model preference/profile and exact resolved model;
- provider-supported effort;
- effective scoped capabilities;
- inherited delegation allowance and original-root identity;
- evidence and return obligations.

Use one native Opus layer when it earns its integration cost. Let an operator execute a coherent task directly or delegate useful bounded portions. Give workers the full capabilities their assignments require within admitted scope; a cheaper model must not imply an unusable harness.
