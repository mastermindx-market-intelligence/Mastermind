# Product acceptance review host composition

The existing Control `coo_principal_dialogue_armed` selection now supplies the
same host-owned `ceo_ingress_app_macro_root` to each actual `ExecutiveSupervisor`:
both the primary worker owner and the independently bound Fabric worker owners.
The root is frozen at service construction. A later mutation of the caller's
configuration mapping cannot redirect a supervisor's acceptance source.

No new configuration flag or source-path input is introduced. Absent or false
R2 selection keeps the previous review behavior. The source
reader and review owner retain the original intent and complete expected proof
set before reviewer launch; the existing supervisor uses that retained input in
its review schema and prompt. Construction itself reads no source basis and
launches no review. Missing or unqualified source remains the existing reader's
closed refusal rather than a fallback to another checkout.

The selection requires the same validated COO principal, sealed
`CooInstalledSource` and complete App binding used by the dialogue host. Direct
composition rejects incomplete configuration with `ServiceError`, including a
missing Macro root or a dialogue selection whose principal is disabled. The
existing Workspace factory is still required before service construction can
complete. Selecting review source does not arm App admission or worker dispatch.

Qualification uses the real host supervisor factory with a disposable Runtime
and deterministic source fixtures. The schema test substitutes `Runtime.at`,
uses a synthetic effective grant and a disposable schema directory, and writes
with the test process's actual group. It checks production schema/prompt
functions and retained input identity; it does not qualify lease admission,
production group separation, installed source acquisition or provider execution.
The retargeting check is a regression guard. The initial red evidence covers
the four selection cases only; it does not establish a red phase for every test.
The ordinary-review control verifies that a review without declared acceptance
criteria reads no acceptance basis and retains no acceptance record.

The host now supplies its exact existing Workspace collector, as described in
PRODUCT_ACCEPTANCE_SEALED_CONTEXT.md. Installed selection remains on hold
pending qualified Context acquisition. The
uncomposed reader refuses isolated/no-site Control with
`CONTEXT_RUNTIME_UNQUALIFIED`; its workstream CLI also depends on the protected
Context owner's source. If selected before those prerequisites exist, a review
with declared criteria fails before provider launch and its attempt is marked
failed by the existing supervisor. A dialogue-armed incumbent must therefore
not install this selection alone. Do not remove isolation, select an alternate
interpreter, or waive the reader's refusal to make it run.

The assigning-parent Company Dialogue request/qualified-ruling consumer remains
a separate host connection. Neither this selection nor an ordinary principal
RULING establishes that ingress or final parent consumption. The current review
selection must be composed at the incumbent owner's next qualified source
interval, independently reviewed, protected-landed and installed before a live
original-intent review is claimed. Existing runtime, principal, worker, scope,
source-custody and uncertain-effect controls remain the receiving owners' gates.
