# Remaining native origin join

## Decision

The frozen typed-binding repair is executable and qualified. An Executive-dispatch provider callback cannot yet be composed honestly under the observed enrollment. Two existing-owner joins remain: carry the originating native invocation's retained MCP binding through the host callback, and supply a real enrolled native-source verifier at Control. Adding an advertised tool or generic `_meta` passthrough now would not close either join.

A correctly enrolled T3 MCP caller can use existing submit/status operations as its authenticated COO API principal, subject to its actual current mission, frozen selected target and admission arms. That route requires no native-origin assertion. The new explicit result acknowledgment also remains API-principal-only and requires its matching new catalogue/action/profile grant; the currently implemented native registration profile is Hermes and must not be relabeled as T3 enrollment. Source readiness does not establish installation.

The current host forwarding API does not expose that retained binding. [`McpServerToolCallParams`](https://github.com/openai/codex/blob/086ccc833bc9cf01024ad2dd6af7dbd421b6bf9a/codex-rs/app-server-protocol/src/protocol/v2/mcp.rs), blob `824d770f503a934351318d51dd0efbbd8594ced1`, has only thread/server/tool/arguments/`_meta`. The [request processor](https://github.com/openai/codex/blob/086ccc833bc9cf01024ad2dd6af7dbd421b6bf9a/codex-rs/app-server/src/request_processors/mcp_processor.rs), blob `7bee469285d95e0029937451b085c6a237827fa5`, loads the thread and forwards by server alias. [`CodexThread::call_mcp_tool`](https://github.com/openai/codex/blob/086ccc833bc9cf01024ad2dd6af7dbd421b6bf9a/codex-rs/core/src/codex_thread.rs), blob `a8d5865e7cbf148e63636eee137cdee8f826c8c3`, refreshes dirty configuration and calls `mcp_runtime.latest_call_tool`. Capturing T3's provider client object therefore does not pin its original downstream MCP connection.

The smallest native extension is to retain the original invocation's existing binding and immutable call evidence alongside its current pending dynamic response, then expose a closed original-call forwarding operation through the existing app-server request owner. A call/turn reference is a locator, never caller-supplied proof: the native owner must resolve it against that pending entry, verify the thread and fixed allowed target, and dispatch through its retained `PreparedMcpCall`. No latest-step fallback, fresh alias resolution, new connection registry or second pending-operation ledger is needed. A duplicate pending call ID must conflict rather than overwrite origin evidence. Completion/cancellation removes the same entry; lost responses recover the original Executive command rather than resubmitting.

`McpBinding::prepare_call` deliberately permits only model-visible tools. A future host-private attester path must be explicitly admitted by the existing connection owner; do not remove that filter or relabel a Control server as the privileged host-owned Codex Apps server.

It supplies no native host instance/release or process/provider custody.

The required receiver extension belongs in those same installed source/currentness and App binding owners: an optional fixed native-source verifier, supplied only by an actually authorized enrollment, must verify the native host/connection and exact original call before constructing the closed ingress frame. This is a proposed owner interface, not an existing grant. The underlying credential/connection custody must establish that ordinary generic callers cannot mint native-origin statements; another profile label, scope or permission digest alone does not do that. No signer or independent identity store is justified by the current evidence.

Qualification must cover actual provider callback → retained native binding → authenticated existing App/Control ingress → original selected child → WorkerBroker custody/result. Negative cases include generic COO `_meta` masquerade, changed native thread/turn/call/target, stale or settled callbacks, catalog/auth replacement, revocation, duplicate/conflicting callbacks, cancellation and lost replies. Existing original-request/result ownership and API-principal acknowledgment stay separate from native parent consumption.

Actual prerequisites remain: establish the enrolled native-source/credential-custody contract; qualify the native original-call forwarding API; obtain an authorized source publication path for the required native changes; and perform a separately authorized isolated build/activation and real original-operation canary under the existing app/profile holds. Both inspected T3 fork identities currently have pull-only access. No such grant, publication, runtime activation or real native callback was fabricated or performed by this work.
