## Implementation consequence

Preserve the ordinary finite session and OMH owners. Do not switch all Paperclip profiles to the native harness, replace OMH with `agentos`, reuse a Secretary enrollment for other teammates, or reinterpret Paperclip run credentials as Executive OAuth authority.

The next Paperclip source integration needs a **real finite-run consumer call site** on the existing native plugin/tool lifecycle, plus explicit role-appropriate enrollment for the existing authenticated Executive read API. The private run owner must retain the actual finite admission/session/profile and original connection, and the host must qualify the current work, adopted source-plan bytes and original root using its existing owners. A model-supplied work/root selector, plugin metadata or matching display name is insufficient. Broader selected-child execution still requires the actual existing admission and delegated grants; context/help discovery supplies neither.

A source feature can be disabled by default and independently qualified through a disposable actual API factory. That would prove source/API behavior only. Installed acceptance must exercise the existing Paperclip adapter, original finite native admission, real configured API enrollment, actual prefetch/tool result delivery and task return under the original carrier. Proof should include wrong profile/run/root, revoked grant, stale plan, original connection retirement and bounded fresh-run retrieval. No automatic consumption or execution acceptance follows from a successful context read.
