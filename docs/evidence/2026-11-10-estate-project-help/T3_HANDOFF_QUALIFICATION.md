source reference. The reference must equal the team's existing
`MissionBrief.source_ref`. The shared `context_matches_source_plan` validates
work reference, repository, commit, path, actual content digest and parsed
contract digest. The emitted selector is precisely
`executive_project_help({"work_ref": ...})`; no caller-selected root is added.

The incumbent `ProjectTeamClient.launch`, `launch_request`, `brief`, `check`
and generated manual project actions pass this expectation through. The CLI
reads the actual assigned Markdown file through the existing bounded
`project_task_context.load_context` owner. A partial selection, stale digest,
source mismatch or symlink does not yield a dispatch request. Existing native
receipt and uncertain-effect behavior remain with `T3CliClient`.

The handoff tells the native session to use its actually advertised and
explicitly enrolled COO tool, require exact returned source equality, obtain
the original Executive root only from that current authenticated owner, and
report unavailable help when those facts are absent. A syntactically valid
GitHub URL does not authenticate remote bytes. A dictionary or pasted result
does not become a reader. Addressability, teammate relationships, capacity,
placement, permission and consumption remain distinct.

No source-plan arguments preserves the original handoff bytes. The isolated

## Composition dependencies and limits

The project-help lead owns these shared dependencies; they are deliberately
not duplicated in this patch:

- `common/coo_project_help_contract.py`: the new v6 wire/source comparison.
- `common/project_task_contract.py`: unchanged pure parser functions extracted
  from the existing session context owner.
- `integrations/session_bridge/project_task_context.py`: existing public API
  re-exporting the canonical parser.
- `common/workspace_project_plan_contract.py`: existing pure selector contract.

The project-help lead also owns the composed proof in which this actual
prepared handoff supplies the selector to a real authenticated
`CooApp`/`ClientSession` v6 read backed by actual Workspace/Mission/source-plan
owners. That proof is pending at this six-file freeze. Its disposable source
grant is an actual Hermes v6 fixture; it can establish API-wire compatibility
but cannot establish a live T3 enrollment or native T3 origin.

Publication, package installation and explicit correct COO profile/source-plan
enrollment remain separate. No native fork changes, runtime services, model
sessions, OAuth grants, profiles, source publication or live dispatch were
performed. The native-origin attester join remains held independently. The
ordinary API-principal read can be used when its actual contract and mission
scope have been enrolled; this source patch does not make that grant.
