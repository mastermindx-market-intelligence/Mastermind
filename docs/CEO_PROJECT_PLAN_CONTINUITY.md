## Purpose and scope

Every assigned CEO/orchestrator must recover accepted work after conversation loss:
**recoverable work, not immortal chat sessions**. Apply to multiple phases,
dependent deliverables, children, consequential revisions or expected continuation.
Trivial answers need no project artifact. Exploration may do minimum safe scoping,
then save before substantial execution/delegation; no planning ritual delays work.

Protected `docs/sol_skills/INDEX.md`, current responsibility, grants and effect
fences govern. This creates no lifecycle, project/task registry, queue, memory,
lease, admission, GitHub permission or Slack/Linear writer.

## Product scope survives every component completion

Use the existing master plan and latest handoff, not another registry. Retain the
original customer outcomes and design references as the parent completion boundary.
For each unfinished outcome, keep its original ID/reference, missing user behavior,
current evidence layer, next integration action and exact held effect if any. Reuse
existing acceptance rows; do not create one issue or receipt per field. A component
can be accepted without accepting its parent. Accepted task counts are not product
completion percentages. Empty or wholly accepted local buffers do not prove full
coverage, wave completion or absence of remaining work.

Choose the nearest complete useful journey, joining the existing producer, consumer,
persistence and return path. Paper/design parity, real data meaning, responsive
behavior and degraded states remain part of that journey where commissioned. A
layout test with empty inputs, an uncoupled API, a preview and a local fixture prove
only their actual layer. Preserve scientific and access limits without hiding
independent implementation inside a broad blocked task.

On resume and after a material integration or release, compare the remaining
original outcomes with the buffered tasks. Recover missing outcomes into the same
plan; preserve IDs, accepted work, live writers and effects. Do not redeclare the
whole programme complete from a source-only slice. Exporters and resume prompts
must preserve unresolved acceptance and unrepresented scope, never infer it away.
A plan change narrows the original outcome only through an explicit scoped decision.

Operations consumes ordinary returns and restores continuation. Astra reviews the
remaining product gaps and decides cross-project scope or integration conflicts.
Repeated source, CI or installation milestones without a completed journey require
a causal intervention, not another broad audit or a generic keep-working message.
Necessary infrastructure work names its blocked consumer and runs alongside ready
product work. No new approval, mandatory management layer or scheduler is created.

## B. Master-plan record: compact header, arbitrarily deep tasks

Versioned human-readable Markdown is a content contract, not a Runtime API.
Header: existing WS/operation, owning repo/path, pin, objective/`DONE_WHEN`, own Git
revision and recorded-at time. Acceptance is a WS/decision fact, not an `accepted`
header boolean. Stable IDs (`P1`, `P1.T2`, `P1.T2.S3` or incumbent), parent/dependencies,
objective/acceptance, source-bound inputs/outputs, risk/reversibility, lane/review/
priority direct bounded execution; these are not wave/Job IDs.

Cite exact PR/SHA/tests/user-path proof; checkboxes are not acceptance. Notes hold
tree assumptions, constraints, hypotheses/falsifiers and rationale; decisions and
discoveries go to Agent OS. Do not copy conversation, wave status, `do_not_redo`,
live children or effects into the tree. Point to WS/latest handoff: next action
stays in WS `next_action` / handoff `next_actions`; children/effects in `control_plane`.

Only the repo-plan writer sets these nonautomatic editorial labels; `blocked` may
apply from any nonterminal label. None changes a wave, handoff or Job.

| Label | Node meaning | Does not mean |
|---|---|---|
| `proposed` | Scoped, not yet offerable | WS `proposed` or admission |
| `ready` | Dependencies/evidence permit offering a bounded slice | Wave `todo`/`in_progress`, Job or Executive ready flag |
| `blocked` | Named dependency/missing proof | WS `blocked` (requires `blocked_by`) or lease hold |
| `in_progress` | Owner editing source/evidence | Wave state, Job `RUNNING` or START |
| `implementation_complete` | Cited artifact exists | Reviewed/merged/accepted or Job `COMPLETED` |
| `reviewed` | Named artifact verdict | Production acceptance or merge |
| `accepted` | Source/decision owner admitted evidence to plan | Protected merge, user acceptance or Job parent consumption |
| `superseded` | Named successor; do not execute | Wave `dropped`; do not copy label |

Wave enums: `todo`, `in_progress`, `awaiting_ci`, `done`, `dropped`.
WS enums: `proposed`, `active`, `blocked`, `awaiting_ci`, `awaiting_review`, `done`,
`parked`, `killed`. Handoff `ended_because`: `complete`, `ci_handoff`, `blocked`,
`context_budget`, `crashed`. Jobs/Attempts remain Executive facts. Same words in
separate planes do not merge their meanings. Issues/Linear are selected navigation,
not one issue per tiny substep or Job truth.
