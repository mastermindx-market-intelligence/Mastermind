## B. Master-plan record: compact header, arbitrarily deep tasks

Versioned human-readable Markdown, not Runtime API:
- Header: existing WS/operation, owning repo/path, pin, objective/`DONE_WHEN`, own Git
  revision/recorded-at time. Acceptance: WS/decision fact, not `accepted` boolean.
- Nodes guide bounded execution: stable IDs (`P1`, `P1.T2`, `P1.T2.S3` or incumbent),
  parent/dependencies, objective/acceptance, source-bound inputs/outputs, risk/
  reversibility, lane/review/priority; not wave/Job IDs.

Evidence: exact PR/SHA/tests/user-path proof, never checkbox acceptance. Notes:
assumptions/constraints/hypotheses/falsifiers/rationale; decisions/discoveries: Agent OS.
Tree excludes conversation/wave status/`do_not_redo`/live children/effects. Next action:
WS `next_action`/latest handoff `next_actions`; children/effects: `control_plane`.

Repo-plan writer alone sets nonautomatic labels; any nonterminal may become `blocked`.
Labels never change wave/handoff/Job or imply WS/Job/Executive state, admission, lease
hold, START, protected merge, production/user acceptance or Job parent consumption.
WS `blocked` requires `blocked_by`; never copy labels to waves (`superseded` ≠ `dropped`).

| Label | Editorial meaning |
|---|---|
| `proposed` | Scoped, not offerable |
| `ready` | Dependencies/evidence permit bounded offer |
| `blocked` | Named dependency/missing proof |
| `in_progress` | Source/evidence editing |
| `implementation_complete` | Cited artifact; not reviewed/merged/accepted |
| `reviewed` | Named artifact verdict |
| `accepted` | Source/decision owner admitted plan evidence |
| `superseded` | Named successor; do not execute |

Wave enums: `todo`, `in_progress`, `awaiting_ci`, `done`, `dropped`.
WS enums: `proposed`, `active`, `blocked`, `awaiting_ci`, `awaiting_review`, `done`,
`parked`, `killed`. Handoff `ended_because`: `complete`, `ci_handoff`, `blocked`,
`context_budget`, `crashed`. Issues/Linear navigate selected work, never per-substep or Job truth.
