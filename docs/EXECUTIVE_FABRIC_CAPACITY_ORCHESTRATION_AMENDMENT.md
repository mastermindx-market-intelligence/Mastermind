# Capacity-conserving heterogeneous orchestration amendment

Status: source amendment, effective only as accepted protected-master source. Branch and PR #1247 copies are review candidates. Runtime admission and installation remain separate gates. It responds to the Chairman's 2026-10-04 direction to increase economical delegation and native orchestration throughput.

Authority baseline: Mastermind `5b244a2bbe4c2a94ec25a887eb4a0d8fafe1ea2f`, especially `docs/EXECUTIVE_WORKER_ROUTING_CHAIRMAN_ADDENDUM.md`, `docs/sol_skills/ACTIVE_EXECUTION.md`, `docs/sol_skills/SESSION_RELIABILITY.md`, and `docs/sol_skills/WEB_CEO_DELEGATION.md`. Existing cognition-route, metered-budget, source-custody, human-approval, confidentiality and effect gates remain unchanged. No new account, spending, provider activation or permission is authorized by a model/role choice.

## 1. Outcome and ownership

The optimization target is accepted, independently verified consumer outcomes per constrained resource, not agent count, generated tokens or number of PRs. Frontier attention should resolve ambiguity, architecture, difficult integration and acceptance rather than repeat deterministic worker labor.

Executive OS remains the only runtime/admission/claim/hierarchy/return owner. Agent OS remains durable organizational continuity. Model Router determines the first lawful suitability tier; Provider Control owns normalized quota and economics; Capacity owns placement and capacity admission. GitHub owns source and evidence; Slack remains transport. Native Codex/Claude clients are consumers of these owners, not additional organizational schedulers.

The legacy native broker and newer Executive path must not independently promise the same capacity. Before cutover, the incumbent owners must establish one authoritative admission path and account for all still-active legacy holds. A mirror, projection, MCP connection or imported configuration is not a second lease authority. Preserve original lease/attempt lineage and uncertain effects; do not restart or abandon workers to simplify migration.

## 2. Role allocation without model prestige

Existing C0-C3 complexity, ambiguity, execution risk and business impact remain distinct. The following role intent extends economical decomposition; it does not replace suitability tests or concrete runtime bindings.

| Responsibility | Preferred use when qualified and admitted | What does not justify it |
| --- | --- | --- |
| Principal architecture and unresolved cross-system judgment | Astra, Fable or Sol as the mission requires | Program size, idle frontier capacity or a generic orchestrator label |
| Bounded domain orchestration and integration | Sol, Opus, full GLM or Grok when their measured task fit and admitted surface support the role | Merely supervising a trivial worker packet |
| Bounded implementation, tests, extraction and routine repairs | GLM Flash, MiniMax, Qwen, or another less-scarce qualified existing worker | A cheap price overriding failed quality or usage-policy gates |
| Independent consequential review | A qualified separate worker, often cross-model where useful and permitted; frontier only for actual judgment | The builder approving its own evidence or an automatic second frontier pass on every edit |

Model IDs, plan availability and reasoning effort are current capability facts, not constants in this law. Keep the existing profile aliases and bind them to observed serving evidence. Unknown actual model or billing remains UNKNOWN, not the alias's advertised identity. MiniMax, Qwen and GLM Flash are candidates, not an assertion of equal coding quality. Use bounded cohort results to decide which work each can reliably perform.

A parent may execute a tiny local check rather than pay delegation, context-transfer and integration overhead. Conversely, a ready independent implementation packet should not stay with a frontier parent simply because that parent can do it. Record a brief task-fit reason for exceptional frontier execution in the existing operation evidence, not a new audit database.

## 3. One bounded hierarchy, one conserved root budget

Use the existing root -> domain -> worker/independent-reviewer structure where its source and installed runtime are qualified. The incumbent #1041 draft describes a two-edge hierarchy, but a draft does not alter deployed depth. Use the minimum of accepted policy, actual harness capability and current attenuated grant. Deeper nesting requires an explicit existing-owner policy change and real-path qualification, not recursively spawning around the leaf boundary.

Every descendant retains the original root and immediate parent references. New child names, sessions, provider aliases and domains do not create fresh root allowances, fair-share identities or credits. Domain grants only attenuate their ancestor's rights, paths, budgets and effect scope. A parent remains responsible for children and returns after its own reasoning turn finishes.

Count orchestrator inference, builders, reviewers, repair attempts, resumed agents, native helper work and final-result delivery in the applicable budgets. Reserve enough completion capacity before starting a wave; do not spend the last allowance on builders and strand review or the final return. Reservations are maintained by the existing owner, not calculated again by each child.

The parent and domain may delegate separable ready work concurrently. Avoid all-to-all agent conversations: children return compact typed evidence to their owner, with artifact references for detail. Keep dependency ordering explicit, and do not launch mutually dependent edits into one shared worktree.

## 4. Capacity is a vector, not one agent number

Keep these dimensions separate: provider request concurrency, shared subscription/account concurrency, model-specific limits, local harness thread limits, physical-host compute/memory/storage, rate limits, quota windows, root/ancestor/operation budgets, and review/return capacity. A provider agent allowance does not prove how many simultaneous API requests a tool may make. A provider request slot does not prove host capacity for another compiler.

The immediate wave is bounded by the minimum of ready independent work and every applicable concurrency ceiling. Total new starts are separately bounded by every applicable quota-window and ancestry budget after outstanding commitments. When several candidates share a root, account, host or reviewer pool, their projected headroom is not additive: only the canonical transactional claim can allocate it.

Quotas in requests, tokens, credits, wall time and currency cannot be summed or treated as interchangeable. Provider Control normalizes native-unit costs for the exact workload cohort, model and reasoning mode. Account for remaining work of running and unresolved attempts as well as future review/repair/return. A larger advertised model cap never overrides a smaller shared-account cap.

Snapshots distinguish configured ceilings, measured current headroom, and forecasts. Freshness policy comes from the existing caller/owner. Missing, stale, malformed or contradictory mandatory facts cannot yield positive new admission. A safe non-mutating diagnostic or independent available lane may continue; there is no global mission halt solely because one provider is unavailable.

## 5. Forecasts and limit changes

Treat expected reset times, estimated job completion and lease TTL as forecasts, never present capacity. A lease expiring does not establish provider process death. An advertised monthly allowance does not prove remaining allowance. Do not release an unknown remote effect or reserve future credits as already available.

Provider Control owns current window sets and epochs. A confirmed reset, plan change or provider-issued allowance adjustment revises the owner observation and accounting without rewriting history or dropping outstanding obligations. Remove obsolete windows only from owner-confirmed plan evidence; do not infer an extra allowance from the absence of a field. A possible promotion or unsourced model statement is not a reset event.

The existing scheduler can place deferrable work around forecast availability when deadlines allow. Within the first lawful suitability tier, compare currently admissible routes by expected accepted-result yield, scarce-resource consumption, elapsed completion and quality risk. Prefer a ready suitable route over waiting for a fashionable model; do not lower the quality bar solely to avoid waiting.

Provider throttling and 429 responses reduce new admissions through existing limit/cooldown ownership. Honor explicit Retry-After and canonical observations, distinguish quota exhaustion from transport failure, and avoid immediate retry storms. Never switch identities or accounts to evade a denied provider allowance.

## 6. Native embedding contract

Native Codex and Claude orchestrators must discover the existing Fabric capability and submit through its admitted, identity-bound entrypoint. A deterministic adapter may translate the native tool call and result; it must not add another reasoning coordinator, credential store, queue, lease or return service.

At launch, verify selected source generation, client version, exact parent session/runtime binding, account/realm eligibility, available tools, model/effort selection and return support. Do not assume a project agent file installed the MCP server, that a plugin card proves selected settings, or that a built-in subagent uses a cheap model. Denied tools remain denied; no arbitrary shell or permissive flag substitutes for the governed spawn path.

Native local caps are defense in depth, not fleet-wide enforcement. All descendant origins must be charged by the canonical owner, including resumes and alternate harness features. When a native path cannot enforce the accepted envelope, keep that path unqualified rather than grant it ambient unrestricted spawning.

## 7. Submission, effects and return

The existing commission carries objective/DONE_WHEN, complexity and task-fit reason, exact source/artifacts, allowed writes, dependencies, tests, root/parent identity, admitted capacity/budget references and one durable return address. Do not invent a new wire schema or receiver name; map to the actual existing tool contract.

A successful transport write is not acceptance, process start, terminal completion or independent acceptance. Preserve the existing Job/Attempt/Worker identifiers and idempotency rules. If a modifying submission or stop has unknown effect, hold its budget and reconcile the original carrier before replay or failover. A changed model, new chat or new operation label does not clear uncertainty.

Return evidence includes exact candidate/artifact digest, tests and failures, unresolved effects, actual serving/cost facts where observable, and the original parent's matching consumption receipt. A native child response alone does not prove a closed Web chat was awakened. An interactive nested return and a non-interactive late return require distinct qualification.

## 8. Quality and economical escalation

Escalate after evidence of a genuine capability gap, not after an unclassified infrastructure error. Separate bad specification, unavailable tool, flaky environment, quota exhaustion and model reasoning failure. A repair uses an explicit changed hypothesis and remaining budget; two equivalent attempts without new evidence require a changed tactic, not a loop.

Use independent tests and review appropriate to execution risk. Cheap builders can implement consequential deterministic work when the packet and independent proof are sufficient; consequential uncertainty still belongs with a qualified stronger reviewer. Do not force every review to be frontier or count one model's second pass as independent authorship.

Evaluate quality-adjusted completion cost, including coordination, review, repair, rejected artifacts and fallback. Also track accepted outcomes per frontier minute, completion latency, queue age, throttle rate, underutilized admitted capacity and stranded-return incidents. Record estimates separately from observed usage. No fixed frontier/worker ratio or throughput improvement is asserted before measurement.

## 9. Acceptance and adoption

Release the projection and policy through normal protected review and CI. Section 12 of the routing addendum links this amendment into the existing routing-law reading path. Actual sessions must still prove that they loaded the accepted source generation; a source link does not prove installed adoption. The incumbent runtime owners must independently qualify producer observations, transactional claims, native launch, result consumption and settings selection.

Roll out in shadow, then one admitted leaf, one domain with review, and a bounded mixed-provider wave. Test duplicate submission, sibling races, shared keys, invalid windows, provider resets, stale identity, unknown termination and parent loss. Require unchanged foreign workers and preserved recovery references. Ramp only after accepted-result and budget evidence supports it; disable new admissions on regression while reconciling existing children.

No account purchase, automatic API spill, default-off profile activation, live broker replacement, global settings mutation or all-account adoption is authorized by this document's creation.
