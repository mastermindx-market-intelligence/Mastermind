## 8. Closed source and coverage model

This section is load-bearing. It closes the ambiguity between visible known items and complete portfolio coverage.

### 8.1 Source-state vocabulary

```text
CURRENT
PARTIAL
HISTORICAL
UNAVAILABLE
CONFLICT
NOT_PROJECTED
NOT_APPLICABLE
```

The reducer consumes accepted source-validity/degradation results. It does not sample a new clock or invent freshness budgets.

### 8.2 Coverage vocabulary

```text
COMPLETE
INCOMPLETE
HISTORICAL_ONLY
NOT_PROJECTED
NOT_APPLICABLE
```

A section may contain known items while coverage is `INCOMPLETE`. In that case its total count and overflow count are `null`; the UI says the list is known-subset evidence, not the full queue.

### 8.3 Section envelope

Every list section uses:

```json
{
  "state": "AVAILABLE",
  "coverage": "COMPLETE",
  "reason_codes": [],
  "total_count": 0,
  "items": [],
  "overflow_count": 0
}
```

Rules:

- `COMPLETE` permits exact integer totals and exact overflow.
- `INCOMPLETE` requires `total_count=null` and `overflow_count=null`; known items may remain.
- `HISTORICAL_ONLY` permits dated historical items but no current total.
- `NOT_PROJECTED` means the capability/source does not exist in this generation; it is not a zero.
- `EMPTY` is a section state only when coverage is complete and the exact total is zero.
