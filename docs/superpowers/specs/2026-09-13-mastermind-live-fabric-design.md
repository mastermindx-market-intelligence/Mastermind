## 1. Outcome, not a dashboard clone

Chris should open one trusted product, understand what the AI organization is doing, follow a mission through its hierarchy and evidence, enter an exact operator workspace, and intervene when needed without discovering tabs, choosing routine accounts, relaying messages or maintaining watchers.

The machine job is equally important: the existing autonomous organization must retain responsibility, route bounded work, consume returns, recover unavailable reasoning sessions safely, and advance approved programs while the graphical interface is closed. The interface makes that operation understandable; it is not the process keeping the organization alive.

The differentiated capability is **an intelligible AI organization with truthful execution, accountable continuation and safe interaction**. An attractive graph alone is insufficient. A rigorous inspector that cannot help Chris accomplish those jobs is also insufficient.

The initial useful slice is deliberately smaller than the final outcome: one authentic mission with its recorded parallel work, exact identities, source-qualified activity and evidence, shown through a graph, equivalent list and operator inspector. It is not called a complete fleet or a self-sufficient ecosystem.

## 2. One product and existing authorities

Live Fabric is a full-screen operational workspace within Chairman Control Room. Protected Decision-First Today remains the default executive experience. Live does not replace Today, duplicate Linear, or revive the rejected H1A/#424 target. E03 establishes that #521 is merged and #424 is terminally superseded; stale PR prose is not a reason to restart that work.

Live Fabric owns rendering, navigation between views, presentation preferences and interaction affordances. It owns no new authoritative lifecycle database, session registry, scheduler, queue, memory store, credential vault, retry ledger, permission policy or source-gather daemon.

This does not prohibit all storage: immutable build assets and provenance manifests are source artifacts; client preferences are presentation data; a bounded existing compositor cache is still that owner's cache. A browser-local pending operation reference may aid navigation, but cannot determine effect state or authorize replay. Every durable command receipt stays with its existing owner.

## 3. Identity and graph semantics

Do not force all identities into a single parent-child chain. The estate is a typed graph: a responsibility can have several work items, a Worker can perform sequential Attempts, an Attempt can involve a session epoch and multiple turns, and an observed surface can be unjoined.

The display distinguishes responsibility, role/practice, Job, Attempt, Worker, logical session, provider session, session epoch, process generation, turn, host, artifact and source observation. A model name is not a person. A subscription is not an executive seat. A browser tab is not a Worker. A native helper is not automatically an independently admitted Executive Job.

Display identifiers are namespaced derivatives of owner-provided identifiers. They never become new canonical IDs. If a source cannot establish an identity, show an unjoined observation with its limited provenance instead of manufacturing a join. A missing team registry does not authorize parsing AGENTS.md into a new organization database.

### Three underlying relationships

1. **Authority:** the current responsibility and action-authoritative parent for a specific semantic obligation.
2. **Work:** source-declared dependency and admitted parent/child relationships. Dependency does not grant authority.
3. **Communication:** deliveries, consumption and reciprocal edges. A message is not a lifecycle transition merely because its prose says STARTED.

Execution, capacity and evidence lenses join these only where accepted owners provide exact applicability. Aggregate edge bundles retain their underlying exact edge references. Expanding a bundle cannot introduce an authority relationship absent from its source.

The authority display follows the accepted Meta/Program/Project/Integrator/Auditor Sol structure. Fable is not a mandatory intermediate node or default bottleneck. Professional specialism, execution capability and provider selection remain orthogonal.

### Observation versus action cardinality

The current Steward singular runtime query intentionally refuses multiple candidates, a wrong root, uncertain effect or stale binding. Preserve it. The plural mission inventory must use the existing plural-reader program, not remove those checks or select the newest candidate.

The first plural dependency is the #508 family, subject to its release and installed consumer proof. Its current source reads a bounded root and descendants; it does not supply every field needed by a full operator cockpit. Required fields absent from the producer remain explicitly unprojected until the owning producer is extended. E02/E04 give the inspected boundaries.

## 4. Truth presentation without a second status engine

Five conceptual display axes organize the inspector: **execution, presence, attention, capacity and evidence**. These are UI categories, not a new five-axis lifecycle schema. Each value comes from a source-owned state and a closed display mapping.

A recorded Executive RUNNING value establishes what the runtime records. It does not alone prove that a provider process is presently making progress. Show separate provider activity/presence qualification. A generation cue in a web page is only an observed cue; it cannot upgrade recorded execution or capacity.

Examples of permitted copy:

- `Recorded running · provider activity not observed`.
- `Surface observed · no exact runtime join`.
- `Result returned · parent consumption not established`.
- `Available capacity not established`.
- `Implementation merged · production proof absent`.

The canvas emphasizes the axis relevant to its current lens. The complete evidence appears in the inspector. Do not decorate each card with five equally prominent status lights.

### Scope, coverage and counts

Every list identifies its authorized scope and independently describes inventory coverage, observation/probe coverage and history coverage where relevant. Complete inventory with partial probes may have an exact inventory count. It cannot have an exact count of active provider executions unless that separate proposition is established.

Within a positively complete inventory, an empty list means exact zero. Partial or unavailable inventory has a null total; known rows remain visible. Redaction, authorization filtering, truncation and unprojected capabilities are not interchangeable reasons. Never use a hidden or unauthorized population to disclose a denominator.

C3's four-profile and 512-session bounds are its current proposal, not evidence of full company coverage. #508's 128-row root limit is not a fleet count. Live may display a smaller pilot scope; it must name that scope honestly.

### Correction and freshness

Retain owner validity and source references rather than generating a new downstream proof map. Rewrapping old data with a new composition timestamp does not make it current. A client wall clock may display elapsed time, but cannot grant action eligibility. Missing freshness evidence stays unknown.

Source corrections replace current projections and link to retained historical evidence where available. They do not erase earlier receipts or use newest-timestamp-wins across owners. During conflict, affected facts and actions degrade; unrelated valid source sections remain useful.

## 5. Projection and consistency contract

The proposed `mastermind.live_fabric.v1` is a **derived display contract**, not an installed API or new authority. Its logical sections are scope/coverage, organizational references, work/execution references, observations, relations, semantic history, capacity and capability hints. Sections are bounded and independently degradable.

The implementation contract must use exact existing owner field shapes or narrow adapters. It must not define a second universal event or entity model that later competes with Executive OS. Schema compatibility is explicit; unsupported major versions fail closed for dependent sections, not by guessing field meanings.

A whole-document render is one atomic publication by the existing compositor. It is not a global transaction spanning GitHub, Agent OS, Slack and SQLite. Retain each input's revision, applicability and observation boundary. Cross-source joins require the existing owner's exact identity rules. Where coherent applicability is not established, preserve separate observations and label the join unverified.

Client publication keys combine the current authorized scope, client/auth epoch and compositor generation. A late response from an earlier scope, revoked session, previous selected mission or old connection epoch cannot replace the current view. Server generation numbers are comparable only within the owner-defined epoch.

Derived display changes must not rewrite protected Steward outputs, Today admission, or the remote X1 document. New owner data is added only through the separately reviewed source seam that owns it. The same view must not cause different source reads merely because it is opened in a second tab.

## 6. Update architecture: do not confuse smooth motion with live truth

The current local Control Room is a stdlib HTTP server with an existing single-flight whole-document cache. Historical source-gather latency is expensive. Having FastAPI or sse-starlette in project dependencies does not make this server an ASGI application. E01 is the actual inspected implementation.

**First release:** use the existing header-authenticated cached read path. Polling is a bounded presentation refresh, at the host-approved cache policy, not one source gather per node or per second. Only one request per active view is in flight. Background views reduce work; reopening/returning from sleep causes a fresh synchronization. Do not add a second collection loop.

**Later low-latency release:** the existing source/composition owner may expose cheaper versioned updates or invalidations. This is an owner extension with measured cost and fan-out limits, not a Live-owned hot-state cache or event bus. Source facts keep their own age even if the transport heartbeat is fresh.

Bare browser EventSource cannot supply the current X-CCR-Token header. Use an authenticated fetch-stream consumer if a reviewed SSE route is later added. Do not move the token into a query string, remove the header requirement, or enable permissive CORS to make a demo work. Keep command POSTs separate from observation transport.

Backpressure is finite. A slow client receives a resynchronization requirement rather than unbounded queued events. UI coalescing may combine repeated display refreshes; it cannot delete canonical lifecycle events, suppress a result/decision, or acknowledge an obligation. Resume cursors reference existing source history only and never become a second durable replay ledger.

A broken transport displays disconnected/dated evidence. Reconnection alone is not freshness or permission. The client re-fetches the applicable snapshot; actions still require action-time owner validation. Missing replay coverage is visible rather than invented from the client's memory.

## 7. Product experience and design quality

### Workspace hierarchy

Today remains the ordinary entry. `Open Live Company` enters an immersive workspace with a return to Today. The long-term lenses are Company/Authority, Work/Missions, Execution, Dialogue, Capacity and Evidence. The pilot exposes only useful lenses; empty speculative tabs are not shipped as features.

On a wide screen, use a compact scope/filter rail, central canvas or list, resizable inspector and collapsible semantic event strip. Selection persists across lenses if the exact identity remains in scope. On medium widths, inspector becomes a drawer. On narrow screens, the equivalent list and full-screen inspector are the default; forcing a desktop graph onto a phone is not acceptable.

The top strip answers: what scope is visible, what is current or incomplete, and what meaningful exception exists. Raw SHAs, paths and schema names belong in evidence detail, not the primary sentence.

### Graph behavior

Use React/TypeScript and React Flow as the preferred implementation foundation, reusing current Control Room typography and semantic color tokens. Keep positions stable across heartbeats and text updates. Structural changes trigger bounded layout; selection, keyboard focus and the user's viewport do not jump.

Dagre is acceptable for separately laid-out acyclic groups. Its documented subflow problem means it must not receive a single nested graph whose children have external edges. Lay out group interiors and the aggregate graph separately, then render cross-group links as explicitly visual overlays. Preserve the underlying exact relations. ELK is a fallback candidate only after measured layout need and license review; no dependency switch by aesthetic guess.

Cycles in an authority/dependency source are displayed as conflicts, not silently removed to satisfy the layout library. Deep graphs collapse progressively. Aggregate nodes identify grouping as presentation, not a new department or owner. Dragging/repositioning never changes organizational responsibility.

### Inspector and cockpit

One click shows an inspector: mission, source-qualified recorded execution, last material activity, next accountable role, exact current target or its absence, result/evidence and relevant capabilities. `Open cockpit` expands into a focused workspace.

Now, mission, lineage, semantic events and evidence are first-class. Conversation, browser, terminal, files and diffs are progressively enabled only through proven approved owners. An unavailable capability has a concise explanation and its real dependency, not a fake empty terminal.

Show reported phase or latest observable tool action, not fabricated internal thoughts or reconstructed hidden reasoning. Summaries are advisory unless they quote an exact accepted result. Full transcripts are not ingested as organizational memory merely to fill the cockpit.

### Accessibility and attention

Every graph task has an equivalent searchable keyboard-operable list. State is never color alone. Preserve focus on refresh and drawer close; provide meaningful graph/list labels, reduced motion, adequate contrast, text scaling and large touch targets. Dense mode cannot hide uncertainty, cut off an action consequence or silently omit overflow.

Semantic animation indicates observed events only. Idle decorative pulses are forbidden. Event arrival does not move the user's scroll position when reading history. A paused visual timeline is labeled historical and cannot supply action eligibility.

Candidate qualification targets, not measured results: warm shell within 2 seconds excluding source refresh, inspector response within 150 ms on the qualified host, and no continuously running layout simulation. Test at least 500 synthetic logical entities with bounded visible detail, plus the authentic pilot at its actual source limits. The final resource budgets must be measured in the browser/WebView matrix before release, not inferred from library marketing.

## 8. Captain's Log and useful intelligence

The Captain's Log is a semantic projection of existing source histories, not a new transcript or event store. Default grouping is deterministic: admission, dispatch, recorded execution, observed activity, result, parent ruling, implementation evidence, installation and production proof remain distinct.

An observed display change is labeled as such; it cannot be invented as an Executive Event. Event IDs are owner-namespaced. Causal relationships use explicit parent/operation/obligation references. Cross-host timestamps provide a presentation sort only; clock skew must not invent causal order.

History coverage is explicit. The product can offer a recent window without claiming complete replay. Correction and supersession are navigable. Missing historical source means unavailable detail, not a synthesized reconstruction.

A later advisory model may explain why a mission is stalled, summarize a recorded return, or answer questions over a source-bounded context. Every factual explanation cites its input. The model cannot author owner, priority, lifecycle, trade authority, action permission, or an unrecorded critical path. A critical-path label requires an accepted owner calculation with sufficient dependency information; otherwise use `declared dependencies` or `known blocking chain`.

## 9. Interaction and effect safety

A snapshot's capability hints are not permission. Every action obtains a fresh owner-native preflight and validates again at dispatch. The action target is one exact applicable binding, not whichever graph node most recently responded.

Preflight must bind the authenticated principal, accepted grant, target/scope, source/binding epoch, payload, effect class and relevant semantic obligation. A change after preflight refuses or re-prepares; it does not silently apply to the new target. The UI may not accept arbitrary URLs, project roots, provider homes, executable strings or account labels as action targets.

A stable client request key handles retransmission of the same request. It does not stop two tabs generating different keys for the same single-consumption obligation. The existing command owner must atomically enforce that obligation and its target generation as well as request-key deduplication. This is not a restriction on intentionally distinct messages or independently admitted work.

Before a possible external effect, the existing owner persists intent and its dispatch fence. A lost response after dispatch leaves the owner's actual uncertainty visible. No retry, second provider, new session or different host is selected to hide it. Reconciliation asks the original owner. A missing client receipt is not evidence of no effect.

The guarantee is scoped at-most-once admission/dispatch where the accepted contract supports it, with explicit effect reconciliation. There is no universal exactly-once guarantee for arbitrary provider side effects.

### Talking to an operator

A user message or status request can consume a provider turn, tokens and tools. It is an action, not an observational GET. The UI distinguishes inspect recorded status, send a message at the next allowed turn, and interrupt. It does not implicitly interrupt a writer or queue duplicate instructions after reconnect. The exact conversation and mission context are shown before send.

Completed receipts are durable at the owner. The browser may restore an operation reference after restart and query it; it cannot maintain an offline auto-send outbox. Revocation or a changed principal clears sensitive client state and refuses pending actions.

### Interrupt, stop and emergency controls

Interrupting a turn, gracefully stopping a provider generation, canceling an Attempt, revoking a grant and pausing new admission are different operations. The UI must say which one is supported and what it cannot undo. Cancel cannot undo an already completed external effect.

Bulk operations use an explicit bounded target set and per-target receipts. They are not represented as atomic fleet-wide success. Emergency pause of new work must use its existing owner; it is not a generic host process killer. These capabilities require their own accepted vertical proofs after the first message/action slice.

## 10. Autonomous continuation and dead-owner recovery

The final product cannot pass merely because it faithfully displays a stuck organization. Autonomy is a separately proven company capability, not a setting in the graph.

The intended closed loop is:

`approved parent -> bounded child admission -> exact worker -> canonical return -> accountable parent obligation -> exact Sol wake -> target consumption -> explicit ruling/CONTINUE/STOP -> independently admitted next child when still within approved scope -> useful result and final acceptance`.

Existing Executive, Wake, Dialogue, Capacity and binding owners implement this. No model must keep generating and no browser must remain open to preserve the obligation. Provider-native return observation must not depend solely on a cooperative model remembering to post a Slack message.

If the current reasoning target disappears, the obligation remains attached to the durable responsibility. Existing continuity owners determine unavailable versus merely unobserved, reconcile prior effects, revoke/fence stale authority and bind an eligible successor under accepted law. Recency, browser visibility, Slack identity and the first responder never elect the successor.

A dead session cannot be the only entity capable of acknowledging its own release. The owning recovery policy needs evidence-based alternatives with bounded diagnosis and escalation, including verified process/effect state and accepted custody transfer. This specification does not create those permissions. Where existing policy lacks a safe alternative, that is a named upstream capability gap, not a reason to fabricate success or wait silently forever.

Lease expiry alone does not fence a process that still has direct filesystem write access. Recovery proof must cover actual effect sinks: workspace isolation, source custody, executor authority and stale-process behavior. Do not reassign an in-flight writer simply because its heartbeat stopped. Conversely, do not hold unrelated work because one exact effect remains uncertain.

The UI shows four separate facts: accountable role, exact current action target, observed serviceability and the current recovery/next-action receipt. No bare `owner to act` with an unknown owner is acceptable. Response windows and escalation derive from the existing recovery policy; the GUI owns no independent timeout policy or retry daemon.

A child's STOP does not terminate sibling work or an aggregate seat watcher. An active parent with no successor returns to the accountable responsibility; it does not let a leftover child watcher originate work. Independent next children still require fresh admission and binding. E06 is the controlling existing authority boundary.

## 11. Security, content and privilege boundaries

The threat model includes malicious repository/text/artifact content, compromised or confused workers, stale clients, cross-site requests, lost replies, concurrent Chairman tabs, same-user local processes and remote unauthorized users. Not every first-release surface defends against every adversary: each release explicitly states its trust boundary.

The current local nonce is CSRF/origin protection, not authenticated user identity against local peers. Therefore it cannot be promoted into authorization for provider turns, admin operations or remote writes. These require the existing authenticated action/Business/Executive owner and the appropriate principal isolation.

Untrusted content is text by default. No raw artifact HTML in the privileged application origin, arbitrary inline scripts, executable Markdown, unchecked SVG, uncontrolled links or user-selected shell commands. Rich previews run isolated without application credentials or native IPC. Download/open behavior uses approved artifact IDs and mediated paths, not URL concatenation.

Terminal output and browser streams have separate sanitization and privilege rules. Terminal escape sequences, clipboard writes and automatic links are not harmless text. Browser previews must not expose credential/settings pages, cookies or tokens through the model/view pipeline. Capture only authorized project/session content. Secrets are excluded before serialization, not hidden by CSS.

Do not place API/session credentials in URLs, logs, telemetry, localStorage, receipts or repository files. Raw provider homes, process argv and environment are not fleet inventory sources. Administrative operations use separately reviewed narrow recipes in their existing owner; neither this app nor a generic password file becomes an unrestricted sudo path.

Authorization is rechecked after awaited work and before publishing protected results. Per-principal/per-scope caching must not leak one user's project/session data into another's view. Logout/revocation closes streams and clears protected client material. Missing telemetry does not silently broaden access to compensate.

## 12. Web and macOS are two clients with different proof obligations

Use one React/TypeScript component model, with platform-specific transport and native integration adapters. Shared components do not imply shared privileges.

The local web pilot reuses the reviewed Control Room origin and API header contract. The remote browser product consumes the existing remote owner's explicitly sanitized projection. It does not mirror all local fields. C3 currently excludes remote profile projection; any later remote fleet view needs an owner-approved contract, not a frontend flag.

The preferred Mac package is Tauri after the web pilot is useful. It is not sufficient to load the loopback site and assume everything works. Bundled application assets have a different origin and IPC trust boundary. The first native read adapter should expose only fixed operations against the approved existing local service, with bounded responses and validated service identity; no generic HTTP proxy, arbitrary host/port, shell or filesystem bridge.

Remote or untrusted content receives no privileged IPC. Native capability files are minimal and window-scoped. Built-in Tauri permission controls constrain the WebView; Rust-side operations still need explicit validation and existing Mastermind authorization.

The current B5 proof targets Darwin/Chrome and the generic HTTP qualification seam is unproven. WKWebView cannot inherit that proof. Until a separately accepted client qualification exists, the Mac app is a dated read-only viewer and must not enable actions based on copied Chrome validity fields.

Signing, notarization, updater verification, rollback and version compatibility are release requirements. An app update must not restart Executive services or migrate their schema as a side effect. The Mac shell owns no background scheduler. Closing or crashing it changes no admitted company work.

## 13. Capacity, models and multi-host correctness

Capacity presentation consumes the existing owners. Distinguish provider quota, current cost, estimated cost, subscription fixed cost, incremental API spend, concurrency limit and host pressure. Unknown quota is not an empty progress bar labeled zero. Model requested, selected-next-turn and observed-served are separate facts; self-description is not model attestation.

Do not infer that different provider accounts are interchangeable, or rotate a write-capable in-flight Attempt after quota loss. Rebinding, new Attempt creation, credential realm changes and handoff occur only through current continuity/capacity law after effect reconciliation.

Host identity includes its owner-defined boot/executor generation. An online connector is not proof of a usable small operation, eligible toolchain, source checkout, authenticated realm or reserved capacity. WSL and its Windows host can share a physical resource domain; do not add their memory or CPU as independent machines. Do not confuse logical slots with physical headroom.

Resource placement and routing explanations use actual owner receipts. The UI can display constraints and the chosen route, not fabricate a model explanation as the scheduler's reason. Browser profiles, provider homes, live SQLite files and worktree indexes are not copied between machines to make migration look seamless.

## 14. Organization studio and controlled learning

The full vision includes teams, repeatable routines, role configurations, artifacts and evolving instructions. These are later useful capabilities, not omitted from the product because the first PR is narrow.

A team/role editor proposes a change to the existing organizational/configuration owner. Routines edit the existing scheduler's accepted definition, including timezone, missed-run, overlap and idempotency behavior. It never creates a second schedule database in the GUI. The lead-agent status board is a view over accepted artifacts and actual results, not an unconstrained HTML application with privileged access.

Instruction evolution uses immutable candidate versions, exact diff, supporting discoveries, evaluation, appropriate independent review, rollout and rollback. Existing Attempts remain pinned to their admitted instructions. Concurrent clones create separate records or reviewed changes; they do not overwrite a shared mutable decision log or silently promote each other's lessons.

Promotion cannot widen authority, spend, tools or data rights by editing prose. A practice or skill is not a grant. Quality improvement is assessed on complete tasks and cost, not token volume or number of generated artifacts.

## 15. Delivery and completion contract

The delivery program reorganizes the earlier infrastructure-heavy list into independently useful verticals. A reducer, fixture gallery or schema may be necessary subwork, but is not called a shipped capability on its own.

There are three distinct acceptance levels:

- **Visibility:** an authentic scoped mission can be understood through real producer-to-UI joins, source-qualified history and evidence.
- **Interaction:** an exact approved operator action runs through real admission and receipts, including lost-reply and stale-target cases.
- **Autonomous operation:** approved missions advance and recover through existing owners while the GUI is closed, without Chairman message shuttling or routine account allocation.

Mac and remote-web acceptance are separate, with their own trust and version matrices. Multi-host scope expands only after real host/resource proof. A later sustained fleet interval must include worker/parent restart, transport loss, partial source coverage and recovery, not just a happy-path animation.

Each release records source/head, built artifact, installation identity, input scope, actual exercised journey, negative cases, rollback disposition and remaining unknowns. Tests and code review do not replace live user proof. The evaluation matrix names required cases; none is reported executed merely by being listed.
