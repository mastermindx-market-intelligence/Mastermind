# Pro continuity safety — source-policy slice

Status: IMPLEMENTED_SOURCE_CANDIDATE / NOT_PROTECTED / NOT_DEPLOYED. The Chairman approved the checkpoint-first reliability proposal and directed implementation on 2026-09-19. This document records that scope; retrieved prose does not grant a new session authority.

## Outcome

A substantial Web session may protect real progress at a justified continuation boundary without pretending its parent mission is complete. A fresh eligible session can recover the exact next action from current owner records rather than replaying the predecessor transcript. Long productive turns remain desirable when useful work is safe; neither minimum duration nor endless work is acceptance.

## Architecture and ownership

ACTIVE_EXECUTION remains the single procedural finalizer. CHECKPOINTED_CONTINUATION is a turn disposition, not an Executive enum, Job/Attempt status, source-writer grant or wake mechanism. Agent OS retains organizational continuity; Executive OS retains admission, runtime/effects and succession; GitHub and existing artifact owners retain source/evidence. No checkpoint database, transcript service, second latest-state authority or provider dispatcher is introduced.

A current cumulative working checkpoint differs from the existing immutable prepared transfer capsule. Never overwrite a prepared capsule for the same target Attempt. Existing owner revision/fencing governs working-state updates. A new chat does not inherit a lease, STARTed operation or source custody.

## Behavioral requirements

The permitted continuation boundary requires all of: mission explicitly incomplete; a specific chunk boundary or observed continuity risk; verified current owner persistence/readback and exact revision/digest; all effects and obligations through that boundary; exact next action and intended resume surface; preserved custody and same-carrier effect handling. A saved plan, old checkpoint, arbitrary elapsed time or desire to finish early is insufficient. When none of the real stopping conditions applies, continue the highest-leverage useful authorized work.

Checkpoint after material decisions/results and before long, effectful or high-output work, not only at the final response. Preserve objective/scope, authority refs, source/operation/carrier identity, last verified effect, accepted work/DO_NOT_REDO, rejected approaches, research hypotheses/falsifiers, uncertainty, children/returns and exact evidence/next action. No secrets or hidden reasoning transcript is required.

Recovery loads compatible current procedure, resolves the exact operation and latest verified checkpoint, and checks only facts that can invalidate the next action. No valid checkpoint triggers bounded canonical recovery once. Important contradictory evidence must still be investigated; context minimization is not permission to omit acceptance evidence.

An instruction to ignore earlier messages does not prove host-side context compaction. A fresh chat is a new presentation context, not guaranteed exclusion of Project history. Observed route-local output is not total ChatGPT context. Hidden budgets and unexposed deadlines remain UNKNOWN; no fixed twenty-minute cutoff or minimum Pro runtime is manufactured. User-requested work profile, observed model/mode, tool exposure and proven actions remain separate.

Research work must be decision-ready, not just a first outline: primary evidence when needed, credible alternatives, strongest objection, explicit unknowns and discriminating acceptance criteria. A completed research commission does not complete a separate delivery program.

## Failure and correction behavior

A checkpoint write with an ambiguous result stays EFFECT_UNKNOWN on its original carrier. An older snapshot does not prove that the newer write failed. No blind retry or alternate authoritative store. If no lawful persistence is reachable, avoid enlarging the unrecoverable effect gap and return a labeled emergency note under the actual platform/gate classification, not fake verified continuation.

Ephemeral result expiry does not justify re-executing a modifying tool. Unknown model identity stays unknown. Quota, safety refusal, connector outage and premature voluntary stopping are classified separately from context symptoms. No account/tool/carrier workaround for a refusal is authorized.
