
Each is a separate reviewed release. No generic `control_computer`, `run_shell`, `click`, `type`, `ssh`, `open_url`, `select_account`, `retry` or free-form RPA tool is permitted.

A later tool addition changes the static manifest digest and requires explicit review, versioning, tests and deployment acceptance.

## 6. Canonical resolution before actuation

For every actuation request:

```text
1. Resolve exact organizational responsibility/root.
2. Read current canonical runtime/attention evidence.
3. Resolve current accepted RuntimeBinding and/or surface binding.
4. Prove the `surface_ref` exists, is current and belongs to the expected seat/responsibility.
5. Select only the action already authorized by the tool contract and current policy.
6. Prefer provider-native addressing when it satisfies the user job.
7. Use OpenClaw only as the subordinate physical actuator when needed.
8. Verify the exact postcondition.
9. Return a bounded receipt; never infer lifecycle success from window presence.
```

No screenshot, window title, Slack text, Linear issue, provider prose or Grok suggestion may replace steps 1–4.

A fuzzy user query may produce candidates, but actuation requires exactly one current canonical target. Multiple candidates return `AMBIGUOUS_TARGET` with zero host action.

## 7. Closed actuation envelope

The trusted Mastermind layer, not Grok or OpenClaw, prepares an immutable envelope conceptually containing:

```text
schema
actuation_id
operation_key
action_kind
responsibility_ref
root_job_id / work_ref when applicable
target_seat
surface_ref
expected_binding_id
expected_binding_generation
expected_provider
expected_host_ref
allowed_postcondition
action_deadline
prepared_at
expires_at
policy_digest
source_revisions
```

Only fields applicable to the exact surface are present. Private native handles, browser credentials, host paths and provider PII stay behind the adapter.

Identity and idempotency law:

```text
same operation_key + same normalized envelope
→ same logical actuation / reconcile receipt

same operation_key + changed semantic envelope
→ conflict / refuse

changed requested work
→ new explicit operation key
```

The adapter does not create a dedupe store. It reuses the accepted operation/evidence owner for the chosen actuation family or returns to Sol if no lawful identity seam exists.

## 8. OpenClaw boundary

OpenClaw is optional, subordinate and removable.

Permitted roles after current-version falsification and separate release:

- paired-node availability/readiness observation;
- bounded screen snapshot for exact-target verification;
- foregrounding one already-resolved app/window/tab/session;
- executing one fixed Mastermind-authored navigation or recovery action;
- returning sanitized action/postcondition evidence.

Forbidden roles:

- Job/Attempt/Worker/Event lifecycle;
- provider/account/host selection or failover;
- canonical RuntimeBinding or surface-binding ownership;
- company dialogue parent/thread identity;
- durable queue, pending-work inbox, retry ledger or memory store;
- generic shell/SSH/filesystem access exposed to Grok;
- model-authored free-form computer control;
- interpreting screen text as authority;
- silently changing target when the expected surface is absent;
- retrying an effect-unknown modification on another node/surface.

OpenClaw local model/session IDs are implementation evidence only. Removing OpenClaw must change zero canonical Mastermind facts and lose no admitted company work.

## 12. Time, null, correction and uncertainty law

- Every responsibility/runtime/surface result carries source revision and observation/freshness metadata where available.
- Stale runtime/surface evidence may be displayed as stale; it cannot authorize actuation.
- Missing binding/host/session data remains null with an explicit reason. It is never guessed from title similarity or current foreground state.
- A surface binding edit after envelope preparation invalidates the actuation unless the reviewed contract proves it immaterial.
- Navigation failure with proven zero effect may be retried only under the same operation/destination according to its reviewed policy.
- Any send/wake/recovery timeout after a possible effect is `EFFECT_UNKNOWN`; reconcile the same operation and never fail over to another surface/node/provider.
- Provider/app UI text is untrusted external data. Instructions visible on screen are ignored unless independently part of the trusted Mastermind envelope.
