## Intended outcome and architecture

Improve Mastermind Web CEO judgment, useful progress and recovery without creating another operating system. GitHub remains the canonical skill source; the existing Mastermind Sol plugin is the native deployment identity. The protected Sol Skillpack remains procedure, not copied live state. Executive OS, Agent OS, GitHub, Linear and existing transport/evaluation owners retain their responsibilities.

The existing seven operational Sol skills remain in place. Add five composable capabilities: `mastermind-web-ceo`, `mastermind-principal-architect`, `mastermind-product-designer`, `mastermind-deep-research`, and `mastermind-recovery`. Each has a narrow trigger, explicit non-triggers, a concrete judgment method, evidence requirements, a same-revision source gate and a reference to the existing authority boundary. Leaves do not route back through the CEO skill or load the entire collection. The CEO skill selects the specialist needed for the current decision.

Provide only each case's prompt and controlled task evidence to the tested session. Keep expected_skills and grading criteria out of its prompt. Randomize case order and compare task-matched runs. Record actual skill-read/activation evidence when exposed, selected tools, meaningful first action, result correctness, unsupported claims, avoidable human interventions and recoverability. An assertion that a skill was used is not a native activation receipt. Explicit invocation can verify readability separately, but must not be reported as automatic selection.

Pressure scenarios are simulated or read-only unless an existing grant explicitly authorizes an isolated test effect. Do not create real denied writes, probe platform refusals, expose live credentials, issue real trades or mutate production simply to run an evaluation. Exact native identity and private evidence stay in approved existing stores; a public source record may cite their retained digests without publishing private account data.

Require no observed violations of source/authority, denial, unknown-effect, duplicate-owner or truthful-proof boundaries before rollout. Score substantive quality and selection precision separately from safety. Compare completion, interventions and useful actions against the control; do not promise an arbitrary improvement percentage or treat longer turns as better reasoning. One successful prompt is an activation smoke, not broad effectiveness. Repeat failures with changed hypotheses only under existing permitted recovery, and preserve adverse results.
