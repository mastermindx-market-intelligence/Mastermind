## 3. Missing capability now frozen — Chairman Surface Supervision

The prior architecture strongly covers work/runtime continuity but does not yet freeze a closed contract for a distinct failure family:

> the canonical responsibility is known and attention may be owed, but the exact ChatGPT/Claude/Codex/browser/application surface through which the responsible reasoning session is reached is frozen, missing, degraded, blocked by auth, or otherwise unusable.

This is not a Job-state failure and must not be repaired by retrying work.

The accepted extension is a pure, ephemeral observation family conceptually named:

```text
mastermind.surface_health_observation.v1
```

It belongs under the existing OCR-6 / Executive Steward product path. It is **not** a new workstream, runtime lifecycle, host registry, watcher service, session registry, health database or retry plane.

### 3.1 Exact-target prerequisite

A surface-health probe may run only after existing accepted Mastermind owners resolve one exact `surface_ref` / binding identity appropriate to the responsibility.

Health evidence may never choose the target.

Forbidden target authority includes:

- newest browser tab;
- matching window title;
- screenshot similarity;
- provider username/account text;
- Slack display identity;
- process recency;
- model judgment such as `this probably looks like Sol 2`;
- OpenClaw node/profile fallback.

When the exact target is not uniquely resolved, the health result is `AMBIGUOUS` or `UNKNOWN`; it does not scan the estate and choose a substitute.

### 3.2 Closed health-state vocabulary

The first reviewed contract uses only:

```text
RESPONSIVE
DEGRADED
UNRESPONSIVE
TARGET_MISSING
AUTH_REQUIRED
PROVIDER_ERROR
HOST_UNREACHABLE
AMBIGUOUS
UNKNOWN
```

These values describe **surface usability**, not company-work status.

A bounded reason-code vocabulary may include only reviewed descriptive reasons such as:

```text
CONTEXT_PRESSURE
DOM_PRESSURE
NETWORK_DEGRADED
UI_BLOCKED
PROBE_STALE
TARGET_CHANGED
PERMISSION_MISSING
PROVIDER_RATE_LIMIT_UI
```

Unknown future evidence stays `UNKNOWN` / typed unknown. A model may not mint new machine health states.

### 3.3 Conceptual observation shape

The implementation may refine names, but semantics are frozen:

```text
schema
observed_at
surface_ref
surface_binding_revision / fingerprint
probe_kind
state
reason_codes[]
freshness_seconds
host_reachable = true | false | unknown
target_present = true | false | unknown
responsive = true | false | unknown
auth_intervention = none | required | unknown
provider_error_present = true | false | unknown
postcondition_evidence_refs[]
degraded_reasons[]
```

No raw credential, cookie, private browser URL, provider-native secret, clipboard content, unrestricted screenshot, arbitrary window title, host username/path or account PII belongs in the public Steward/Grok projection.

The raw observation is ephemeral/read-only unless an accepted owning proof wave preserves a sanitized immutable receipt as evidence. No mutable current-health store is created.

## 4. Evidence hierarchy — deterministic probes first, model interpretation subordinate

Surface supervision uses the strongest available evidence in this order:

1. **provider-native / application-native structured evidence** for exact target/session availability when available;
2. **reviewed exact-surface adapter probes** tied to the already-resolved `surface_ref`;
3. **optional private OpenClaw inspect evidence** through an immutable Mastermind envelope;
4. **optional local model / VLM interpretation** of a bounded already-authorized visual diagnostic.

A Qwen-class or other economical local model may be useful for bounded UI anomaly interpretation, for example distinguishing a login wall from an ordinary idle page after the exact surface is already resolved. Its output is advisory evidence only.

The local model/VLM may not:

- select the surface, host, provider, account or browser profile;
- promote `UNKNOWN` to healthy/runnable without deterministic evidence;
- decide Job/Attempt/Worker state;
- create Wake;
- retry or fail over company work;
- choose an alternate target;
- type/send/submit merely because it believes the UI is stalled;
- grant itself broader OpenClaw/browser tools.

Deterministic policy decides whether an already-authorized surface-only action is permitted. Model prose can explain or recommend; it cannot author the gate.

## 5. Work state and surface state must remain separate

Control Room / Steward MUST preserve both dimensions rather than collapsing them into one green/red status.

Valid combinations include:

```text
work = WAITING_ON_FABLE       surface = RESPONSIVE
work = ATTENTION_OWED         surface = UNRESPONSIVE
work = RUNNING                surface = DEGRADED
work = BLOCKED                surface = RESPONSIVE
work = COMPLETED              surface = TARGET_MISSING
runtime = UNKNOWN             surface = RESPONSIVE
```

A responsive window does not prove work is running. A frozen window does not prove the Job failed. A missing watcher does not prove zero local execution. A Slack return does not prove canonical runtime completion.

### 5.1 Steward-derived surface flag

The Steward may produce a **descriptive, non-authoritative** field such as:

```text
surface_repair_required = true | false | unknown
```

A positive value requires both:

- exact current responsibility/surface binding; and
- fresh health evidence showing the bound surface is unusable for the presently owed interaction.

Example:

```text
canonical attention owed to CEO
+ exact bound Sol surface
+ surface state UNRESPONSIVE
= surface_repair_required=true
```

That result means **repair the cockpit**, not **retry the company work**.

If human login/MFA/captcha/credential intervention is required, surface state is `AUTH_REQUIRED` and the Steward may escalate a Chairman/admin action. It must not bypass or automate that authority boundary unless a separately accepted source law explicitly permits the exact mechanism.

## 6. Surface-actuation ladder — release progressively

The normal sequence is closed and monotonic:

### Stage S0 — observe only

```text
INSPECT exact surface
-> bounded health receipt
-> zero foreground / click / type / send / provider-work effect
```

This may be implemented with provider-native reads, a native host adapter or optional OpenClaw inspection after its own prerequisites are accepted.

### Stage S1 — exact foreground only

```text
FOREGROUND exact surface_ref
-> verify exact intended managed environment/seat/conversation
-> zero message typing / submission / account switch
```

This remains subject to the accepted P0B/successor exact-intended-seat foreground law. Window/title similarity cannot satisfy the postcondition.

### Stage S2 — surface-only repair

Only after a separate reviewed release may one immutable operation perform a narrowly defined repair such as reopening/reloading/restarting the **same exact bound surface** when that operation cannot create or repeat the underlying Mastermind work effect.

A future reviewed operation must define the exact permitted action, preconditions and postcondition. `fix it`, generic RPA, arbitrary browser control and free-form shell commands are not valid contracts.

### Stage S3 — dialogue/Wake/recovery

Message sending, canonical Wake, provider session resurrection, work continuation and recovery remain owned by their existing Mastermind paths:

- Worker Presence / Agent Relay for company dialogue;
- Wake for attention/resume obligations;
- provider-native session adapters / RuntimeBinding for exact continuation;
- Executive OS for Job/Attempt/Worker lifecycle and effect reconciliation.

OpenClaw must not create a parallel `send continue`, `retry worker`, `pick another Claude account`, `start another Sol`, or `wake newest tab` path.

**Provider-native exact session operations always outrank GUI/OpenClaw automation when the reviewed native path exists.**
