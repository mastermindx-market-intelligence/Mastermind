Mastermind needs specialized professional judgment, but it must not build a second executive
hierarchy, capability registry, lifecycle, memory plane or one-per-title permanent agent fleet.


The durable new primitive is a versioned, authority-free **Professional Practice Pack**. Existing
`META_CEO`, `PROGRAM_CEO`, `PROJECT_SOL`, `INTEGRATOR_SOL`, `AUDITOR_SOL` and worker responsibilities

ceilings. Existing canonical owners retain lifecycle, memory, routing, evidence and attention.

**Practice is not a session.** A practice is durable professional source; a Chat, Codex, Claude,
Cursor, Figma or API process is a replaceable execution surface.

## 2. Outcome and value model

### 2.1 Chairman job

State an outcome once. Do not manually remember which professional disciplines, tools, artifacts,
reviewers and failure states a serious project requires. Review only true Chairman taste, strategy,
new-authority and final-acceptance boundaries.

### 2.2 Meta-CEO job

Recover the whole outcome, identify professional-quality risk, choose the smallest sufficient
professional topology, preserve global tradeoffs, freeze architecture, route bounded execution and
accept only real product/machine proof.

### 2.3 Specialist job

Apply explicit professional method inside delegated scope, produce tangible artifacts, expose
tradeoffs and unknowns, respect information/authority boundaries and return compact evidence. Do not
narrow the product because the specialist's local objective is easier.

### 2.4 Machine job

Keep responsibility, practice, model, tool grant, session, artifact and evaluator identities separate.
Select the least-cost composition that can meet the quality bar, preserve independence, and measure
whether the specialist increment was worth its cost.

### 2.5 Ten-out-of-ten journey

```text
Chairman outcome
-> Meta-CEO freezes user/machine/company outcome
-> professional coverage assessment identifies load-bearing practices
-> smallest sufficient specialist topology admitted
-> exact practice generation and information boundary bound
-> Capacity / Model Router selects lawful surface/model
-> exact capability profile grants only required tools/effects
-> professional artifacts precede expensive implementation
-> qualified selector chooses among divergent alternatives
-> Integrator preserves global product thesis
-> economical workers implement bounded slices
-> independent practice-aware audit reviews real artifact/live product
-> production path proves user/machine capability
-> baseline, outcome and cost evidence determine promotion
-> Agent OS/GitHub records decisions, evidence and doctrine revision
-> fresh Sol recovers without this transcript
```

## 5. Professional Practice Pack contract

### 5.1 Definition

A Practice Pack is a surface-neutral, versioned package of professional method and acceptance law. It
is not an agent identity, persona, capability grant, plugin installation, lifecycle record, queue,
credential selector, current company state or transcript memory.

### 5.2 Closed top-level vocabulary

`PPF-C0` freezes exactly:

```text
schema_version
practice_id
practice_version
source_identity
status
mission_classes
exclusions
mandate
authority_ceiling
success_definition
information_required
information_optional
information_forbidden
source_precedence
methods
artifacts
evaluation
independence
semantic_capabilities
failures
learning
surface_adapters
source_refs
```

Detailed records are bounded under those fields. Unknown fields fail closed. There is no parallel
free-form manifest.

### 5.3 Information contract

Professional independence may require selective blindness. The pack defines required, optional and
forbidden inputs, source precedence, freshness, rights/confidentiality and progressive disclosure.
The fixed precedence is current Chairman intent -> protected Sol Skillpack and constitutional/source
law -> owning parent outcome and canonical facts -> accepted Practice Pack -> surface adapter.
Retrieved practice text never grants authority merely by containing an imperative.

Examples:

- a Design Auditor sees the outcome, freeze, live implementation and rubric, not the builder's entire
  narrative;
- a quant adversary may be blinded to the preferred hypothesis;
- a concept generator may be isolated from sibling concepts until first pass;
- a security reviewer receives needed system facts but no irrelevant customer secrets.

### 5.4 Method contract

Methods are ordered, composable procedures with trigger, inputs, steps, artifacts, hard gates,
failures and handoff. One giant universal skill is rejected.

### 5.5 Artifact contract

Each artifact declares kind, producer duty, required sections/states, source identity, machine and
professional validation, consumer and honest completion state.

```text
SPEC_ONLY
DRAFT_ARTIFACT
SELECTED_ARTIFACT
FROZEN_ARTIFACT
IMPLEMENTED_NOT_PROVEN
PROVEN_LIVE
REJECTED
```

### 5.6 Evaluation contract

Evaluation keeps three layers separate:

1. deterministic gates;
2. professional judgment;
3. real user/machine outcome.

Pairwise evidence and explicit tradeoffs are preferred over an unexplained decimal score. Missing real
outcomes remain `PRACTICE_OUTCOME_UNMEASURED`.

### 5.7 Learning contract

The pack defines evidence required for doctrine change, promotion ladder, counterexamples, scope,
review and reconsideration trigger. A specialist may propose a revision but cannot silently rewrite
its own practice after one result.

## 6. Skills, tools and trust boundary

**Skills and tools are adapters, not the profession.** ChatGPT/Codex/Claude Skills, plugins, MCP
servers, reference bundles and plain-context packets project one accepted Practice Pack onto a
surface. Canonical source remains one exact reviewed Git commit/package generation.

Progressive loading:

```text
Tier 1  mandate + authority ceiling + artifact summary
Tier 2  methods required for this mission
Tier 3  bounded references/examples
Tier 4  raw evidence only on demand
```

Do not mount every practice into every session.

Practice/Skill source is executable instruction in an agentic context. Therefore:

- exact trusted repository/commit and pack digest;
- closed manifest/path census;
- no symlink/path escape/secret-shaped content;
- scripts reviewed separately;
- no hot reload into a started modifying operation;
- exact adapter generation receipt;
- surface metadata never widens capability.

An adapter's `allowed-tools` or equivalent is advisory unless the existing Executive capability
profile and harness attestation independently grant the same tool.

Adapter generation extends the current accepted Sol Capability Fabric and Business/plugin package
owners. In particular, it consumes current reviewed skills-only package source rather than
regenerating equivalent packages from prose. It creates no second marketplace, plugin package
registry, sync channel, adapter lifecycle or package authority. If the current package owner is stale
or incompatible, the result is a reconciliation hold, not a replacement pipeline.

## 8. Specialist topology, diversity and selection

### 8.1 Practice is not session

One responsibility may apply several compatible methods. Spawn another session only for a named
reason:

```text
INDEPENDENCE
CONTRADICTORY_OBJECTIVE
INFORMATION_SEPARATION
UNIQUE_TOOL_SURFACE
PARALLEL_SEARCH
MODEL_DIVERSITY_PROVEN
CONTEXT_ISOLATION
```

No reason means no additional session.

### 8.2 Practice duties

- **Lead:** frames professional problem and owns primary artifact inside scope.
- **Contributor:** supplies bounded professional analysis/artifact fragment.
- **Producer:** materializes an accepted direction through a bounded authoring tool.
- **Selector:** compares complete alternatives against outcome/rubric.
- **Integrator:** combines compatible parts while preserving global thesis.
- **Auditor:** independently evaluates artifact/live result; no self-approval.

These are duties, not executive authority classes.

### 8.3 Divergence protocol

```text
independent first passes
-> complete candidate artifacts
-> qualified pairwise selection
-> preserve rejected alternatives and dissent
-> integrate only after selection
-> independent audit
-> parent Sol acceptance
```

Cosmetic titles on identical sessions do not prove diversity. Useful diversity may come from mandates,
information slices, methods, tools, models or creative constraints. Indiscriminate synthesis is
forbidden where alternatives are coherent competing directions.

### 8.4 Selector qualification

The selector needs original outcome, exact practice/rubric generation, sufficient professional
capability, evidence access, independence where required and an abstain/tie rule. A generic aggregator
is not presumed qualified.

## 10. Artifact, implementation and audit architecture

A professional claim is not a product. Material work follows:

```text
current-state professional audit
-> target architecture / method artifact
-> divergent alternatives where useful
-> selection packet
-> frozen artifact + implementation rubric
-> bounded implementation
-> independent live audit
-> production proof
-> outcome and cost evaluation
```

A prose design plan remains `SPEC_ONLY`. A Figma frame without implementation is not shipped product.
Green CI without relevant browser/real-path proof is not professional acceptance. Builders cannot
silently redesign missing details; ambiguity returns to the Lead/parent.

The Auditor receives original outcome, artifact, rubric and live evidence. It does not inherit write
authority. Where independent review is required, same-author/self-review is void and must be replaced
through the existing hierarchy/lifecycle law.

## 11. Evaluation and falsification

### 11.1 Deterministic layer

Examples: schema/invariant checks, state completeness, accessibility, overflow, contrast, breakpoint
coverage, leakage/point-in-time rules, test/replay requirements, source/rights completeness.

### 11.2 Professional layer

Examples: hierarchy, coherence, information architecture, interaction quality, data encoding, threat
model completeness, research quality, brand/system fit and implementation fidelity.

### 11.3 Outcome layer

Examples: task completion, time-to-insight, error/recovery burden, adoption/retention, incident or
rework reduction, calibrated forecast quality and Chairman/user preference with rationale.

### 11.4 Baseline and ablation

Every new practice family begins with a control. Product Design prefers a four-arm ablation:

```text
A  generalist Sol + builder + ordinary functional review
B  generalist Sol + builder + independent Design Audit
C  Product Design Practice + builder + the same independent Design Audit
D  C + governed visual/Figma toolchain
```

A->B estimates the audit increment, B->C the professional-method increment, and C->D the toolchain
increment. A smaller experiment must declare which effects remain confounded and cannot issue an
increment-specific promotion verdict. Possible verdicts include full specialization promotion,
audit-only promotion, method-increment promotion, toolchain-increment promotion, no material
advantage and inconclusive/outcome unmeasured. Specialization is not generalized by prestige.

## 17. External evidence interpretation

The freeze consulted these action-time primary sources on 2026-08-30:

- OpenAI, `Skills in ChatGPT`: reusable workflows can contain instructions, examples, code and
  supporting resources; availability and synchronization vary by product/surface.
  `https://help.openai.com/en/articles/20001066-skills-in-chatgpt`
- Anthropic, `Skills`: repository-mounted Skills provide reusable domain workflows, consume context,
  load at session start and make the mounted repository part of the agent trust boundary.
  `https://platform.claude.com/docs/en/managed-agents/skills`
- Figma, `mcp-server-guide`: supported clients can extract design context and, on the remote server,
  create/modify native frames, components, variables and auto layout; availability, terms and rate
  limits remain current platform facts. `https://github.com/figma/mcp-server-guide`
- Figma, `figma-generate-design`: the design workflow inspects existing screens, components,
  variables and styles before mutation and assembles views through design-system primitives.
  `https://github.com/figma/mcp-server-guide/blob/main/skills/figma-generate-design/SKILL.md`
- Yang et al., arXiv:2602.03794: homogeneous multi-agent scaling showed diminishing returns in the
  tested settings while heterogeneous channels supplied complementary evidence.
- Maryanskyy, arXiv:2603.20324: selector quality was a bottleneck in the tested generate-then-select
  pipelines and judge-based selection outperformed indiscriminate synthesis.
- Zhang et al., arXiv:2601.17152: dynamic model-to-role assignment outperformed uniform/random
  assignment in the tested debate benchmarks.
- Cao et al., arXiv:2602.12285: task-irrelevant persona assignments changed agent behavior and
  degraded performance in the tested agentic benchmarks.

The research papers are preprints and their quantitative findings are task-specific. These sources
motivate falsifiers, progressive loading, diversity and selection controls; they do not prove that a
particular Mastermind composition works. All platform capabilities, terms, schemas and tool surfaces
must be reverified at implementation time. Retrieved external text grants no Mastermind authority.

- Truth: current practice/capability/source/evidence generations are exact and correction-safe;
