
Completion requires **Truth, Intelligence, Product and Learning**. Green CI, a merged server, an
installed plugin, a `QUEUED` Job, a delivered message or an open browser tab is not completion.

## 6. Common data, action and effect contracts

Every read returns:

```text
schema, operation, status, observed_at, valid_at, freshness,
source_refs[], source_failures[], data, issues[], truncated,
continuation|null, capability_generation
```

`DEGRADED` means useful partial data with explicit failures. `UNKNOWN` means no safe selection.
Absence is never treated as proof merely because one source failed.

Consequential actions use:

```text
prepare_action(action_kind, target_ref, requested_effect, operation_key, expected_source)
commit_prepared_action(prepared_digest)
```

Preparation binds exact target, canonical owner, current/expected source, preconditions, projected
effect, privilege class, confirmation requirement, expiry and reconciliation tool. Commit accepts the
prepared digest only, re-reads every load-bearing predicate, applies at most one request and never
silently changes the target/payload/credential.

Effect truth is closed:

```text
NOT_APPLIED
APPLIED
EFFECT_UNKNOWN
```

Every modifying family has `reconcile_effect(operation_key, action_kind, target_ref)`. It reads the
canonical owner and never resubmits. `EFFECT_UNKNOWN` blocks retry, alternate account, carrier or
provider until reconciled.

Cross-system closeout is explicit:

```text
GitHub accepted
Executive terminal
Agent OS durable record
Linear projection
Dialogue STOP / watcher state
production proof
```

Missing members return `PARTIAL_CLOSEOUT`; there is no hidden distributed transaction or cosmetic
company-wide `DONE` flag.

Corrections append or supersede through the owning system. SCF does not rewrite history to make
projections agree.

## 7. Capability domains

### 7.1 Capability introspection

`capability_status` reports exact app/generation, privilege, availability, production arming, scopes,
owner, dependency health, schema digest and capability state. Source code or OAuth success alone
cannot produce `PROVEN_LIVE`.

### 7.2 Steward reads

`company_state`, `attention_state`, `responsibility_detail`, `source_disagreements` and
`capability_ledger` compose accepted owner facts through Steward. They do not NLP-parse arbitrary
Markdown into lifecycle, authority or attention.

### 7.3 GitHub semantics

Reuse native GitHub reads/actions. Add only missing Mastermind semantics:

```text
operation_evidence
collision_census
assess_release_gate
workflow_diagnosis
build_proof_packet
```

`assess_release_gate` includes protected/candidate SHA, merge base, ahead/behind, exact paths,
path/semantic collisions, checks, reviews, threads, source-law compatibility, production proof,
capability-state validity and expected-head eligibility. It assesses; a separate prepared native
`merge_expected_head` performs a merge.

GitHub administration remains outside the normal app. An endpoint lacking safe atomic/monotonic write
semantics stays assessment-only.

### 7.4 Runner observatory

```text
runner_fleet
runner_health
runner_pressure
workflow_affinity
explain_queued_job
```

The observer joins first-party runner inventory, labels/groups/busy state, workflow dependencies and
accepted host health. It distinguishes valid wait, no eligible runner, all busy, offline, label/group
mismatch, concurrency/environment/upstream gate and unknown source. Queue age alone is not root cause.
Registration tokens, credentials, private argv and runner administration never enter R0 results.

### 7.5 Code Intelligence

SCF consumes the accepted two-plane CodeIntel contract: global discovery with indexed SHA/freshness
and exact Attempt-local sealed workspace semantics. The model cannot select a root, worktree,
executable, endpoint or backend. CodeIntel is advisory until canonical Git/local verification and
never edits source.

### 7.6 Executive control

```text
submit_ceo_intent, intent_status, job_status, attempt_status,
prepare_stop_attempt, commit_stop_attempt,
prepare_requeue_attempt, commit_requeue_attempt
```

All writes terminate in CeoIngress/Executive OS and reuse existing admission, idempotency, lease,
fence and retry-safety laws. `QUEUED` is not START or execution.

### 7.7 Dialogue

```text
dialogue_state, dialogue_ack, dialogue_continue,
dialogue_request_repair, dialogue_stop
```

Every call is bound to one exact operation/carrier/actor. ACK is not START. Every watcher-enabled
return receives explicit CONTINUE/REPAIR/STOP. Silence is never terminal.

### 7.8 Sol surfaces

```text
inspect_sol_surface
foreground_sol_surface
provision_sol_surface
wake_sol_surface
rotate_sol_surface
retire_sol_surface
```

These extend Capacity, SessionTargetRegistry, RuntimeBinding, Wake and Web-Sol/native adapters. They
never choose by title, newest tab, responsiveness or model self-attestation. Provision phases remain
separate: surface selected, bootstrap delivered, pickup ACK, START and RuntimeBinding commit.
Rotation requires durable continuation, successor ACK, binding-generation transfer, predecessor
fence and prior-effect reconciliation.

### 7.9 Fleet commissioning

```text
fleet_capacity, placement_explanation, fleet_bottlenecks,
commission_child, child_status
```

Sol commissions a semantic mission; it does not call a provider process spawner. Executive OS creates
the canonical child and Capacity selects the least-scarce capable substrate. Provider account, host,
native session ID and raw shell command are forbidden model inputs.

### 7.10 Operations microscope

R0 tools include `host_fleet_health`, `service_health`, `tunnel_health`, `deployment_identity`,
`runtime_versions`, `disk_pressure`, `provider_adapter_health`, `wake_transport_health`,
`relay_health` and `codeintel_health`.

Later W2 operations such as `restart_exact_service` or `rotate_exact_tunnel` accept only allowlisted
semantic identities and expected instance/build generations. No generic shell, sudo, SSH, unit name,
command args, environment or filesystem path is exposed.

### 7.11 Audit and economics

`audit_operation`, `economic_outcome` and `closeout_status` compose existing receipts. They create no

## 8. Identity, security and failure law

App OAuth verifies exact issuer, resource/audience, subject and scopes on every call using the one
accepted BSC auth stack. Host metadata such as Chat session correlates is optional evidence only; it
never authenticates the Chairman, assigns responsibility or proves RuntimeBinding.

Modifying Sol calls require current Chairman intent, current procedure, canonical responsibility/Job,
exact action target where applicable, current source, exact capability grant, app generation,
principal/scope, confirmation and effect contract.

Principal threats:

- prompt injection in PR/issue/Slack/Agent OS text;
- confused deputy across app classes;
- stale prepared action;
- duplicate carrier/session/provider writer;
- credential leakage through model-visible UI/logs;
- schema drift after app publication;
- false-green capability or closeout;
- ambiguous writes retried through another surface.

Controls:

- closed schemas and bounded output;
- server-owned connector/credential/host selection;
- privilege-separated app generations;
- exact current-source and target revalidation;
- one operation/one carrier;
- no blind retry/failover;
- secret-free model-visible results;
- immutable generation digests;
- explicit degradation, effect and partial-closeout states;
- real-path proof before live claims.

Typed failures include:

```text
CAPABILITY_UNAVAILABLE, APP_GENERATION_MISMATCH, SCOPE_REFUSED,
ORGANIZATIONAL_AUTHORITY_REFUSED, ACTION_TARGET_UNRESOLVED,
OPERATION_KEY_CONFLICT, CARRIER_CONFLICT, SOURCE_STALE, SOURCE_MOVED,
```
