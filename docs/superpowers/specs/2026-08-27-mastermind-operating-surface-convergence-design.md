## 4. Final role of each operating surface

### 4.1 Chairman Control Room

The Control Room is the primary present-tense cockpit. It remains a deterministic read-only compositor and never becomes another lifecycle or queue.

The target product is a **Responsibility Matrix**. Each exact work/root card preserves source attribution and may show:

- workstream/program and current organizational phase;
- accountable CEO and logical COO;
- Executive Job/Attempt/Worker state;
- current provider/realm/account label and capacity state;
- continuity state (`RUNNING`, `DRAINING`, `REBINDING`, `WAITING_CAPACITY`, `BLOCKED`, `TRANSPORT_DEGRADED`, `COMPLETED`, `UNKNOWN`);
- current carrier and GitHub evidence;
- Linear project/wave/gate projection;
- watcher/attention state from accepted Worker Presence/Wake facts;
- intentional wait reason and review-after evidence where canonically authored;
- exact `needs_chairman`, `needs_sol`, `needs_coo`, reconciliation and degraded reasons;
- navigation links that remain navigation only.

There is no synthetic overall lifecycle. Unknown joins remain unknown.

### 4.2 Linear

Linear becomes the primary human portfolio/project-management UI, but remains a selective projection rather than organizational or runtime authority.

V1/V2 mapping:

- Initiative: optional portfolio/program family;
- Project: selected major Agent OS `WS:<KEY>` workstream;
- Milestone: major program phase or release;
- Issue: selected CEO/COO wave, gate, independently useful deliverable, production-proof gate or admin action;
- sub-issue: optional bounded deliverable only when human tracking adds value;
- project/issue comments and updates: organizational summaries, decisions, accepted returns, blockers, evidence and next actions.

Linear must **not** model every Executive Job or Attempt, provider account, runtime ACK, Wake obligation or watcher event. `In Progress` does not mean a worker is currently running. `Done` never outranks the declared completion owner/proof law.

### 4.3 Slack

Slack's final role is communication fabric:

- Agent Relay / Executive Relay transport;
- bounded Sol↔Fable company dialogue;
- machine protocol and hot-state visibility;
- selective Linear project/update notifications and human discussion;
- high-signal Chairman exception notices.

`#agent-dispatch` is transition/backend plumbing and must not be the Chairman dashboard. During cutover it may remain an explicitly labeled manual-pickup board for unsupported paths; it never becomes a Job queue or execution authority.

`#ceo-control-room` becomes high-signal only: Chairman action, Sol action, named degradation, bounded executive summary and links to the owning surface. Giant commissions, step-by-step implementation logs and raw machine protocol do not belong in its normal channel timeline.

Human organizational discussion may use Linear↔Slack synced threads. Agent Relay, Wake and Executive protocol frames must not be mirrored into Linear comments as if they were work state.

### 4.4 GitHub

GitHub remains implementation and evidence truth. One logical modifying operation binds to one implementation carrier until canonically reconciled. Linear and Slack link to that carrier; neither creates a replacement when it becomes inconvenient.

### 4.5 Grok Secretary

Grok is an exception-first conversational secretary over accepted read projections. Initial responsibilities:

- answer what needs Chris/Sol/COO attention;
- explain where a logical responsibility is running and why it moved;
- report stale, unavailable or contradictory projections;
- identify missing watchers/ACKs without inferring runtime from Slack;
- navigate to Linear, Control Room, GitHub and the bound dialogue thread;
- produce bounded executive updates.

Grok initially has no Job creation, routing, retry, provider selection, Linear bulk mutation, GitHub mutation, generic SSH, Mac control, secret access or durable private queue/memory authority.

### 4.6 OpenClaw

OpenClaw is optional subordinate infrastructure. It begins as an allowlisted read-only shell over Executive Steward. Later actuation requires a separate reviewed release for exact, already-authorized Mastermind operations such as foregrounding one bound app/session or executing one accepted Wake/navigation command.

OpenClaw never owns Job/Attempt/Worker/RuntimeBinding, provider selection, failover, Slack identity, company memory or effect-unknown retry. Removing OpenClaw must change zero canonical Mastermind truth.

## 9. Failure and correction behavior

- Slack delivered with no canonical claim: transport only; runtime unknown.
- Missing Slack ACK: does not prove non-execution; reconcile exact operation against GitHub/Agent OS/Executive evidence.
- Linear says Done while owner proof remains open/unknown: Linear false-green; repair projection only.
- Linear unavailable when a scoped exact binding is required: unknown/blocking, never fabricated absence or safe grounding.
- Executive unavailable: display degraded/unknown; do not manufacture runtime state from PR or Slack.
- provider capacity stale/unknown: capacity unknown; never unlimited/available by default.
- carrier head moved unexpectedly: hold, inspect and reconcile same carrier; never reset or create a replacement.
- modifying effect uncertain: `EFFECT_UNKNOWN`; same carrier/destination reconciliation only; no failover.
- watcher unavailable: explicit `WATCH_UNAVAILABLE`; no silent abandonment and no invented background service.
- Grok/OpenClaw offline: core Mastermind truth and operation continue unchanged.
