## Approval

The Chairman approved the Operator Continuity & Realm Rebinding architecture in the governing Sol conversation on 2026-08-27 and directed Sol to continue end to end through planning, integration, production proof and durable closeout, using Codex help where useful.

The approved rulings are:

1. **Machine-operated substrates.** Claude Code / supported Agent SDK session surfaces and Codex App Server are the primary autonomous sustained-operation substrates. Native Claude/Codex applications remain valuable cockpits/manual surfaces but are not required for canonical failover.
2. **New-Attempt cross-realm law.** A provider/account/auth-home/placement change such as `Claude realm 05 -> Claude realm 02` creates a new Executive Attempt and fresh provider-native session. It is not same-session resume.
3. **Stable logical responsibility.** Fable/COO or Codex-Sol responsibility belongs to the accepted commission/root Job/seat, not the provider account, native conversation, Mac or Slack username.
4. **Canonical rollover owners.** Executive OS owns lifecycle/requeue; Model Router and Capacity Fabric determine lawful placement; Operator Harness/provider adapters perform native execution; Wake addresses the exact current binding; Slack/Control Room/Steward project the result.
5. **Effect-unknown fail closed.** A modifying operation with an uncertain effect stays on the same Attempt/carrier/realm until reconciled. No blind account/provider/host failover.
6. **Deterministic continuation.** Cross-realm continuity uses a versioned continuation capsule derived from existing canonical sources. It does not depend on transplanting the old provider-native conversation and does not create a new memory store.
7. **Runtime binding projection.** RuntimeBinding must be derived from/reuse Executive and Operator Harness evidence rather than introducing a second session database.
8. **Five-Claude pool only after isolation proof.** The five paid Claude subscriptions become routable execution realms only after installed-host proof establishes concurrent account/auth isolation and correct capacity attribution without exposing credential values.
9. **OpenClaw subordinate boundary.** OpenClaw may later serve as an optional Steward shell, read-only session catalog or bounded host actuator, but it cannot own Executive lifecycle, account placement/failover, Slack commission identity, retry, effect reconciliation or company memory.
10. **Slack company continuity.** The same logical actor and commission thread may continue across Attempt/runtime replacement. Provider usernames are not the durable company identity.
11. **One canonical control plane.** No new Job/Attempt/Worker lifecycle, provider-specific scheduler, Slack queue, session registry, retry ledger, credential synchronization service or continuation-memory database is authorized.

```text

-> safe Attempt terminal/requeue

```

```text

```

Until those proofs pass, cross-account continuity remains nonterminal regardless of CI or individual adapter merges.
