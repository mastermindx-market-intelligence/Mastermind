## 1. Chairman outcome

Keep Personal-Pro ChatGPT Web sessions as the primary high-frontier Sol CEO cognition surface while removing their one-hour watcher latency, browser-hunting burden and dependence on a reasoning session staying continuously awake.

The company must not pay API costs merely to obtain always-on presence when the already-paid Web/Codex reasoning surfaces provide the desired CEO quality. Instead:

- high-end CEO cognition may sleep;
- deterministic infrastructure stays awake;
- canonical Worker Presence / Wake / Steward facts determine when Sol attention is owed;
- one exact already-bound Web Sol surface can be health-checked and foregrounded without the Chairman hunting tabs;
- difficult decisions still return to Sol rather than being delegated to a generic RPA agent;
- OpenClaw remains optional fallback hands, not the nervous system.

A Web Sol conversation is working memory for a CEO reasoning episode. Durable company truth remains in existing canonical owners. Context exhaustion rotates a reasoning surface; it does not create a new CEO identity or company-memory plane.

## 3. Preferred ChatGPT adapter: profile-local extension + native bridge

The preferred ChatGPT Web S0/S1 architecture is a deliberately narrow Chrome-compatible extension installed into each approved managed-browser Sol environment plus one local native-messaging bridge.

The adapter is subordinate to the existing `mastermind.surface_bindings.v1` navigation record and OCR-6 Surface Supervision. It does not create a second session registry or discover organizational ownership.

Conceptual path:

```text
exact `surface_ref`
-> existing surface binding: managed environment + exact conversation URL
-> profile-local Mastermind extension
-> authenticated local native-messaging bridge
-> bounded surface observation / foreground receipt
-> OCR-6 / Steward composition
```

The extension may not choose which Sol seat or responsibility to operate. Existing Mastermind owners resolve the exact `surface_ref` first.

## 5. Native bridge boundary

Use browser-native messaging or an equivalently reviewed local IPC mechanism supported by the installed managed-browser cores. The native bridge:

- has one fixed extension/application identity allowlist;
- receives only closed schemas;
- exposes no generic shell, argv, filesystem or network proxy;
- carries no browser cookies/session tokens;
- accepts no caller-selected host/profile/url outside the already-resolved binding;
- stores no transcript or mutable watcher cursor;
- returns bounded sanitized receipts only;
- refuses unknown extension IDs, profiles, actions, bindings and schema versions.

If the installed Multilogin/GoLogin browser core does not support the required extension/native-messaging contract in the real managed profile, return a typed unsupported result. Do not fall back silently to GUI automation.

## 7. No transcript-scraping architecture

Mastermind does not require Grok to copy worker/COO/CEO conversation transcripts from ChatGPT Web in order to supervise the company.

Canonical problem-solving flow is:

```text

-> Sol reads canonical Control Room / GitHub / Agent OS / dialogue evidence

```

The extension is therefore state/actuation infrastructure, not a conversation-export mechanism.

## 8. Context rotation

Logical `Sol` remains stable across Web conversations.

When a Web Sol surface approaches context limits or is intentionally retired:

```text
current Sol episode
-> durable Agent OS / GitHub / decision closeout
-> exact current responsibility state remains in canonical owners
-> new bound Sol surface
-> cold-start/Session Truth/Steward rehydrate
-> same logical Sol responsibility
```

Do not copy the entire old transcript into a new durable store or treat a specific conversation ID as the CEO identity.

## 9. Stuck-worker supervision

A worker is not classified stuck by Grok staring at a terminal or screenshot. Steward derives the condition from structured evidence where available.

Examples:

```text
worker RESULT + no later Sol edge -> needs_sol
worker DECISION_REQUEST -> needs_sol
attention owed to worker + exact runtime available -> Wake worker
child terminal + active parent + no successor -> PARENT_ACTIVE_NO_SUCCESSOR / needs_sol
attention owed to Sol + Sol surface responsive -> wake/foreground path eligible
attention owed to Sol + Sol surface unusable -> surface_repair_required
```

Visual/terminal inspection is only subordinate evidence for surface usability after exact target resolution.

- exact disposable profile healthy;
- extension unavailable -> typed unsupported, no fallback;
- native bridge unavailable -> typed degraded/unknown;
