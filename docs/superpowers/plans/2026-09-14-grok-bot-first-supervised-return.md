## 8. Acceptance matrix

| --- | --- | --- |

| Budget unknown/exhausted | Affected work held and reason preserved | Paid fallback or guessed remaining allowance |
| Effect unknown | Same-operation reconciliation | Restart with another provider/account |

| Reserved strategy decision | Correct Sol/Chairman obligation | Foreman silently changes thesis or acceptance bar |
| Successful provider run | Arrival, review and consumption separately observed | Provider terminal equated with company completion |

## 9. Promotion and evaluation

The first pilot is deliberately not a model benchmark. Before extending it, the current evaluation owner freezes a matched sample and acceptance/economic threshold. Compare direct qualified-worker work with Grok-assisted work only where both are lawful and useful; do not automatically run every production job three times.

Report accepted useful outcomes, human interventions, parent-consumption latency, first-pass quality, repairs, Grok usage with measured basis, helper usage/cost, duplicate effects and false completion claims. Where concurrent account use prevents per-run attribution, say so. Local CLI dollar estimates are not subscription charges. Raw token throughput does not demonstrate positive return on investment.

**Do not promote** until the real consumer works, negative cases preserve authority and correction, the selected route is permitted, and measured incremental value justifies Grok's coordination cost. A merged specification or all-green unit suite does not satisfy those conditions.
