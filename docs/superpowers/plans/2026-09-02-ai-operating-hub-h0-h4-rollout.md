# AI Operating Hub — H0→H4 Vertical Rollout Plan

> **Execution rule:** dream at full scale, build one independently useful vertical at a time. The Hub is an `UMBRELLA_EXTENSION` over the protected Project Workroom, live 7/64/62/2 Linear portfolio, and existing Chairman Control Room; it is not a standalone application or operating system. This plan does not authorize implementation; each wave requires a bounded handoff, exact current-state reconciliation, immutable-head review, and its own proof.

## Program success metric

An authorized Chairman/Sol user can orient to one active workstream, inspect evidence, recognize the exact blocker or decision, and safely advance one existing operation without Slack archaeology, false-green state, duplicate effects, or a parallel control plane.

## H0 — current-estate archaeology and contract freeze

**Mission:** identify the real implementation path and prove every required source/authority seam before UI or runtime work.

### Required read set

- current protected Mastermind architecture and Skillpack;
- protected Project Workroom Fabric architecture and its current-source reconciliation amendments;
- protected Linear current-epoch source and fresh live readback (`7 / 64 / 62 / 2` at this F0 freeze);
- current Macro Agent OS workstreams, decisions, discoveries, handoffs and validators;
- Executive OS source/API/installation/proof state;
- existing web/admin/control-room routes, component system, auth and permission owner;
- GitHub, Linear and Slack connector/adaptor ownership;
- latest relevant PRs, production deployments and browser evidence;
- any current competing Hub/workroom/control-room program.

### Outputs

1. Exact capability ledger with `PROVEN_LIVE`, `BUILT_NOT_PROVEN`, `PARTIAL`, `DARK_OR_DISCONNECTED`, `BROKEN`, `SPEC_ONLY`, `NOT_BUILT`, `REJECTED_BY_DESIGN` per sub-capability.
2. Exact reference workstream and complete real source identity graph.
3. Contract table per field: owner, source, query, time semantics, null/failure/correction behavior, permission and freshness budget.
4. Repository/path collision census and recent-PR archaeology.
5. Real-data reference payload and desktop/mobile reference composition covering every failure state.
6. No-rebuild boundary and explicit reused owners.
7. One bounded H1 implementation handoff with exact paths, sequence, tests, browser proof and stop condition.

### Source gate and stop condition

The Chairman-delivered H1 Codex packet is not implementation authority until F0 and H0 are protected. Slack/interactive delivery without `PICKUP_ACK` and separate `START` remains `DELIVERY_UNCONSUMED / PRE_START`; any attempted H1 source effect must return `BLOCKED SOURCE_PREDECESSOR_UNPROTECTED effect=NONE`.

Stop after the H0 return. No UI, API, database, cache, runtime action, Slack/Linear/GitHub write, deploy or production claim.

## H1 — Workstream Workroom

**Observable mission:** a real authorized user opens the Hub and completes the orientation/evidence job for the frozen reference workstream.

### Vertical composition

- existing source adapters or the smallest read-only extensions;
- one typed derived workroom contract;
- one real server/route consumer;
- premium responsive UI;
- evidence drawer and canonical deep links;
- stale/conflict/permission/outage/unknown/no-data states;
- instrumentation for orientation and evidence use;
- deterministic tests + browser proof + production read-back.

### Non-goals

No action submission, attention ranking, new DB, generic dashboard framework, second auth layer, LLM status, background retry or broad portfolio migration.

### Acceptance

A user unfamiliar with the live operation can correctly answer outcome, current capability, current actor/binding, latest proof, blocker/decision, freshness and exact next owner/action from one screen, with every answer auditable.

## H2 — one CEO continuation action

**Observable mission:** submit and reconcile one existing child-operation `CONTINUE`, `REQUEST_REPAIR`, or `STOP` decision through the canonical admission path.

### Contract

- exact authority and permission;
- expected revision / source pin;
- stable semantic fingerprint;
- preflight with explicit effect and non-effects;
- canonical submit;
- duplicate replay and changed-payload conflict;
- timeout/effect-unknown reconciliation;
- projection lag without optimistic success;
- immutable receipt and evidence drawer projection.

### Non-goals

No arbitrary GitHub/Linear/Slack writes, no provider failover, no new action queue, no merge/deploy controls, no bulk actions.

## H3 — deterministic executive attention

**Observable mission:** a real canonical waiting/blocking condition appears in the Hub because a transparent policy admitted it, and disappears only after canonical correction/continuation.

Policy rules are versioned, tested and replayable. LLM summaries explain but never admit, rank, suppress or close items.

## H4 — learning and operating leverage

Instrument:

- median time to correct orientation;
- time from worker return/blocker to executive edge;
- time to unblock and to accepted proof;
- stale/conflict detections and prevented actions;
- duplicate replay preventions;
- evidence opens and correction rates;
- action accepted/refused/effect-unknown/reconciled rates;
- return usage and retention by workroom.

Promotion of new attention/action policy requires preregistered replay and measured forward evidence. Model prose never acquires implicit authority from engagement.

## Review checklist for every PR

- What real user or machine capability now exists?
- Is the primary job complete end to end?
- Is any feature present but dark or practically useless?
- Did infrastructure replace product?
- Is a spec being called shipped?
- Are all claims grounded at promised precision?
- Did the worker create a duplicate authority, store, queue, identity, auth, retry or carrier?
- Can it be seen through the real production path at relevant breakpoints?
- What correction/discovery must be durable?

## Current gate

Only H0 is eligible after this F0 architecture is independently reviewed and protected. H1–H4 are held. The existing delivered H1 operator packet may be used as advisory input during H0, but it is not ACK, START, a carrier, source effect, or permission to bypass the protected predecessor. The architecture PR itself creates no runtime, workstream, action, job, deployment, production proof, Linear projection or Slack lifecycle.
