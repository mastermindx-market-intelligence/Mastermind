## 1. Outcome

Prove, in one reversible single-active-user ChatGPT Business cockpit, that a fresh
approved Web CEO can use **Mastermind Navigator** to recover from the exact
READ-proven / WRITE-unprobed capability state without Chairman correction:

1. GitHub READ is already evidenced for the exact Mastermind repository.
2. The task now requires a GitHub WRITE-class action.
3. WRITE has not yet been probed in the fresh session.
4. Navigator must keep WRITE `UNKNOWN / UNPROBED`, discover only the GitHub WRITE
   action family, use the smallest non-mutating repository permission/serviceability
   preflight available, and recompute the health projection.
5. When current technical/resource WRITE serviceability is proven, Navigator must
   continue to the separate organizational/source-writer gate rather than emit
   `UNAVAILABLE`, `EXACT_HUMAN_GATE`, or a platform blocker.
6. No dummy GitHub mutation is allowed solely to prove capability.

The canary is successful only when this behavior is observed on the real served
ChatGPT Business path with the protected package generation, not merely in fixtures.
