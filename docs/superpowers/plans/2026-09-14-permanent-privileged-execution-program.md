Owner: Sol, under the Chairman's approved bridge-and-permanent-solution mission. This plan grants no runtime authority, installs nothing and arms nothing. The existing broker carrier is Mastermind PR #613; do not create a replacement broker or lifecycle. Authoring source: protected `2aa28559a857461fd674fae52d2904116b854891`, Skillpack 1.0.1, bootstrap-major 1.

## Outcome and completion
Codex, Claude and their orchestrators must complete approved host-administration steps without asking Chris to copy commands or repeatedly enter a password. The deterministic system resolves current authority, selects a fixed operation, executes it once, verifies the actual target, recovers its result after interruption and reports a truthful terminal or unknown outcome. The capability is governed unattended execution, not unrestricted sudo.

Completion requires real assigned work through each intended native client, an installed root executor and verified target result, loss/recovery and revocation proof, recoverability across a fresh session, and evidence that routine manual interventions decreased. Permissive provider settings, a merged schema, a successful shell exit or an installed plist is not that outcome.

## P1 — Bridge and read-only reconciliation
PR #613 implements six fixed effects for the installed operator UID and control UID450: service start/stop/restart, worker-auth verify-only/verify-ready and explicit readiness-lock recovery. This trusted user-account bridge is not a grant of SERVICE_CONTROL or CREDENTIAL_ADMIN to untrusted workers. Verify-ready can invoke a provider canary and write readiness state; it is not a read-only probe.

`mmx-admin status --request-id ID` uses the same socket and evidence store. `TERMINAL` carries the original child receipt; `RECONCILED_NOT_APPLIED` carries a separately validated marker-preserving reconciliation record and is query success without claiming the original effect succeeded; `EFFECT_UNKNOWN` means unresolved marker evidence remains; `NOT_FOUND` is observation only. Historic and installed release identities remain distinct. Status queries never create/remove state, spawn, recover a lock or resubmit an effect. Creating `RECONCILED_NOT_APPLIED` evidence is a separate broker reconciliation operation with exact request/marker/pre-effect proof, and the original request id remains non-replayable afterward. Reconcile any possible effect before a separately authorized recovery/new attempt.

Acceptance: exact protected release installed through the current authorized host installer; a real non-root request produces a verified target result and receipt; replay does not repeat the effect; status recovers it without execution; malformed/unauthorized/unknown states remain honest. Source tests and review do not satisfy production proof.

## P4 — Governed upgrade, rollback and revocation
Reuse exact-source installation, release manifests, preimage/restore and the existing owner-specific prepared-action contract. Freeze an authenticated release-artifact/approval mechanism in its existing owner before building an updater. A digest, PR prose, model-supplied source path or unsigned script is not approval. No generic package manager, root network shell or caller-selected launchd label.

Approved upgrades preserve credentials, lifecycle state and actuator receipts and coordinate with the existing installer owner. No other started effect may be interrupted without reconciliation. Revocation rejects new effects, preserves earlier evidence and proves the exact target's resulting state; rollback is another explicitly authorized fixed effect, not erase-and-retry.

The current independently useful substep extends `ops/executive_os/uninstall.sh`: revoke the privileged registration before normal services; support `--privileged-only`; prove disabled and native service/socket absence before deleting only fixed plists; preserve all state and privileged evidence. This is administrative revocation tooling, not yet passwordless self-upgrade or an additional broker action. Unknown/denied native readbacks fail closed. A surviving marker **without** a mutually valid create-only `RECONCILED_NOT_APPLIED` record remains unresolved: report `EFFECT_RECONCILIATION_REQUIRED` and preserve evidence. A marker plus a cryptographically and semantically valid reconciliation record is historical resolved-not-applied evidence; registration revocation may proceed while preserving both files byte-for-byte. Missing, orphaned, tampered, mismatched or unsafe marker/reconciliation evidence remains fail-closed.

P4 acceptance additionally requires an approved upgrade with no repeat password and negative signature/source/target/expiry/revocation tests. Until its authenticated update mechanism is implemented and accepted, adding new root code retains an administrator boundary. The first bootstrap never grants arbitrary future code or vendor-auth authority.
