## Program objective

Create the missing source-attributed executive cognition-allocation layer so Meta-CEO/Program CEOs and the Chairman can operate from a compact **Executive Attention Frontier** instead of scanning a flat `needs_*` estate. The system must surface real emergencies and hard windows, preserve intentional waits and autonomous progress, batch exact related decisions, prevent starvation, degrade on stale/unknown evidence and keep **priority strictly downstream of authority**.

The program is not complete when a schema, score, ranking unit test or dashboard exists. Completion requires real multi-program Control Room/Executive Steward proof that Chairman interruption and executive switching fall without missed severe decisions or hidden stalled work.

## Global no-rebuild constraints

1. Executive OS remains the only Job/Attempt/Worker/Event lifecycle and CEO-intent admission owner.
2. Agent OS remains the durable workstream/decision/discovery/handoff owner.
3. GitHub remains implementation/evidence truth; Linear remains selective projection; Slack remains transport/hot state.
4. RuntimeBinding/Wake/action-authority owners remain the only exact action-target owners.
5. Capacity Fabric/Model Router remain the placement/suitability owners.
6. OCR-6 Executive Steward remains the cross-owner responsibility/attention compositor; EAF extends it rather than creating another compositor.
7. Chairman Control Room remains the primary operating-surface consumer; Project Workroom Home/Radar may display EAF later but may not own it.
8. No new attention DB, inbox, queue, scheduler, watcher registry, session registry or lifecycle store.
9. No weighted scalar becomes authority. Unknown/stale never defaults to zero.
10. No worker/provider placement or RuntimeBinding transfer can be caused by priority.
11. No Chairman hard quota may suppress a true emergency.
12. Mastermind PR #228 is an exclusive current Steward carrier. Until protected/accepted, this program may not modify `control_plane/executive_steward.py` or `tests/test_executive_steward.py`.
13. Every implementation wave must produce one independently useful observable capability and real proof.
14. Every worker dialogue gets explicit CONTINUE or terminal STOP; terminal completion does not authorize the next wave.
