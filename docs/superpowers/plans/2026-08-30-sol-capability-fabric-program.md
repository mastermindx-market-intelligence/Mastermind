# Sol Capability Fabric Implementation Program

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement each accepted wave plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Chat-native CEO Sol a coherent, source-attributed and safely writable executive operating surface across Mastermind without creating a duplicate lifecycle, authority, identity, memory, queue, retry or control plane.

**Architecture:** The Mastermind Sol plugin supplies procedure and one coherent experience while privilege-separated apps and native connectors expose typed capabilities owned by existing canonical systems. Reads are broad; consequential actions use exact targets, prepared actions, current-source revalidation and effect reconciliation; administration is isolated and normally disabled.

**Tech Stack:** Python 3.11+, existing Mastermind control plane/integrations, accepted BSC MCP v1/OAuth stack, GitHub/native connectors, RuntimeBinding/Wake/Web-Sol, Capacity/Model Router/OHF, pytest, GitHub Actions, and real browser/host proof.

**Spec:** `docs/superpowers/specs/2026-08-30-sol-capability-fabric-design.md`

## Global Constraints

- Load current protected Mastermind and every required same-SHA Skillpack skill before each modification.
- `COGNITION_ROUTE: CHAT_PRO_DEFAULT` is the Sol-class default.
- Executive OS owns CEO admission and Job / Attempt / Worker / Event lifecycle.
- Agent OS owns durable workstreams, decisions, discoveries and handoffs.
- GitHub owns implementation and evidence truth.
- RuntimeBinding/SessionTargetRegistry and Wake own exact surfaces and attention.
- Capacity Fabric / Model Router own provider/account/surface eligibility and placement.
- Steward / Control Room own cross-owner read composition.
- One Experience, Federated Authority remains controlling.
- Deliver one independently useful capability per PR, or one explicitly records-only source-law slice.
- Every modifying family has paired status/reconciliation and never blind-retries `EFFECT_UNKNOWN`.
- Prepared-action semantics are implemented per canonical owner/app; no universal cross-owner action router or durable prepared-action store is permitted.
- No model input selects credential, numbered provider account, arbitrary host/root/executable/endpoint, shell, SQL or browser selector.
- No plugin memory, super-MCP, process spawner, duplicate scheduler, retry ledger, session registry, capability registry or lifecycle.
- Green CI, merge, install, delivery, ACK, START, execution, production proof and acceptance remain distinct.
- User-facing promotion requires the real production path and browser proof at relevant breakpoints.
- No wave inherits START from this records carrier.
