# OCR-8 Full Subscription Pool & End-to-End Acceptance Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Graduate Operator Continuity from a two-realm canary into the real Mastermind-X governed workforce: all five intended Claude subscriptions and the accepted Codex subscription realms are individually attested, capacity-aware, routable only within lawful suitability tiers, observable in the Steward/Control Room, and proven under concurrency, quota exhaustion, cross-realm continuation and adverse effect uncertainty—without Chairman account/machine micromanagement.

**Architecture:** OCR-8 adds no new scheduler or pool manager. It is the acceptance/composition layer over Shared Provider Control + CF2-I + RF1 + HF1/PF1 + Operator Harness + OCR-3/4A/4/5 + Worker Presence/Steward + MH1/OCR-7. Each subscription is an opaque Worker/capacity realm with host-local authentication. Executive OS claims concrete Workers; provider-capacity evidence ranks only already-lawful candidates. The final pool may span multiple physical hosts/OS principals. Operational learning is derived from existing Executive Events, provider-capacity receipts and transport receipts; no metrics truth database is created for this program.

**Tech Stack:** accepted production Executive Runtime, Shared AI Provider Control, Capacity Fabric, Worker/Operator Harnesses, Agent Relay, Wake, MH1, Control Room, existing telemetry/evidence surfaces.

**Specs:** all Operator Continuity architecture/amendments on the same source-law program.

## Dependency Gate

Do not call OCR-8 complete until:

```text
OCR-1: five intended Claude native realms are provisioned/attested
CF2-I + RF1 + HF1 + PF1 accepted
OCR-3 continuation/binding accepted
OCR-4A/4 sustained Claude accepted
OCR-5 local cross-realm positive + effect-unknown negative accepted
Worker Presence/Agent Relay production path accepted
OCR-6 core Slack/Steward projection accepted
MH1 + OCR-7 two-host continuation accepted if more than one physical host is used
Codex production realms are independently attested under their current source law
```

A missing subscription login/OS principal/host is an explicit Chairman/admin provisioning gate; do not count an unprovisioned realm as pool capacity.

## Global Constraints

- Pool membership is not a new table. It is the set of currently registered/eligible Worker quota realms whose identities are already owned by Executive/provider-control configuration and current host proof.
- Five Claude paid accounts do not become one credential. Each realm retains host/OS-principal/native auth isolation.
- No worker is selected by Slack username, desktop app label or ordinal preference hardcoded outside CF2-I/RF1.
- Unknown/stale quota is not unlimited; provider health/account presence is not execution proof.
- Frontier reserve/economics policy remains Capacity Fabric/Model Router law. OCR-8 measures it; it does not create a second reserve policy.
- Completion requires real provider paths. Synthetic failure injection may validate deterministic transitions but cannot substitute for at least one genuine provider quota/rate-limit rollover.
- Each modifying operation remains one carrier/Attempt until canonical reconciliation.
- All metrics are descriptive operations learning only; no model-generated summary gains routing/authority control.

### Task 5: Adverse failure gauntlet

Each case must prove the forbidden successor action is absent, not merely that an error was logged.

- [ ] **Effect unknown after modifying provider turn**

Expected: zero new Attempt/provider/host; reconciliation only.

- [ ] **Stale/unknown capacity for the only spare realm**

Expected: no claim; `WAITING_CAPACITY`/degraded projection.

- [ ] **Wrong auth realm/account binding**

Expected: launch/attestation refusal; no work turn.

- [ ] **Provider session changes during same-Attempt resume**

Expected: refusal/effect reconciliation; never “close enough” continuation.

- [ ] **Remote host response lost after dispatch**

Expected: no cross-host replay/failover.

- [ ] **Slack rebound write effect unknown**

Expected: runtime remains correct; reconcile same Slack message key; no provider action.

- [ ] **OpenClaw unavailable or returns its own fallback session**

Expected: no change to Mastermind Job/Attempt/RuntimeBinding/Slack parent; core continuity remains operable.

- [ ] **Realm account logs out/expires**

Expected: provider/auth readiness degrades that realm; other future Jobs may use other lawful capacity, but an active modifying Attempt reconciles before replacement.
