# Project-Management Operating-Surface Cutover Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make Linear + Chairman Control Room the stable human operating surface for material programs, selected waves/gates, turn ownership, blockers and exact next actions so the Chairman no longer reconstructs company state from `#agent-dispatch`.

**Architecture:** Continue the existing one-way Agent OS → Linear portfolio projector and the already-frozen OSC-C1 selective issue/update projection. Linear remains a projection; Agent OS remains organizational truth, Executive OS runtime truth, GitHub implementation/proof truth, Slack dialogue transport, and OCR-6 Steward/Control Room the cross-owner read/attention compositor. No project database, Slack→Linear task bot, webhook lifecycle, retry queue or one-issue-per-runtime-object system is created.

- Existing started/effect-unknown implementation carriers remain where they started; projection repair never migrates them.
- Exact organizational identity (`WS:<KEY>` / accepted wave identity / operation key) binds projection. Never fuzzy-match by title.
- Provider account/session labels are runtime evidence, not durable project owners.
- `Linear In Progress` never proves a Worker/Attempt is running.
- Slack `ACK/START/RESULT` and GitHub merge never automatically mean a selected issue is complete.
- Missing canonical evidence stays `UNKNOWN / UNAVAILABLE`; never coerce to empty/healthy/done.
- No issue per Executive Job/Attempt, raw Slack protocol frame, PR, provider event or watcher tick.
- No new sync database/cursor/retry queue/webhook lifecycle.
