Interaction and build contract ↓

Each scenario is an independent fixture, not the next event in a run. Production must keep read quality separate from the retained run/result payload. A failed refresh after a returned result retains that result; it does not revert to working. The unknown-request fixture has no current run identity, but a real uncertain effect must retain any identity already established.

A changed working/result scenario demonstrates one 180 ms reveal. Production animates only an observed material change. Settled, stale, disconnected and unknown states rest. Reloading an unchanged scenario has no animation or announcement. Reduced motion preserves every fact.

Team identities and task states are fixtures here. Production must use existing qualified owner data, with a root-only fallback when task facts are absent. Recent runs uses the existing reader, capped at eight original-principal project runs; it is not complete history.

Continue from result opens an unsent draft. An existing draft is never overwritten. The production preview/submission owner must supply and revalidate the complete parent witness; one new self-root follows the verified result. Unknown original effects use the original reconciliation path, with no resend.

Files and Details remain after the mounted composer. Their owner sections remain mounted while navigating. Back/Escape returns to the exact available opener. Refresh preserves focus while its target remains available; a disappearing or disabled target returns focus to the project heading. Read the implementation and proof matrix ↗
