## User job and feature decisions

Today should help a member understand what changed since a usable saved reading and continue the appropriate research. The new inspector explains the exact reading pair, its available population label and local comparison scope. It does not create another comparison or treat every observed name change as a user list edit.

| Element | Disposition | Decision |
|---|---|---|
| Today member/guest/unavailable entry and existing shell | RETAIN | Keep existing server membership and subject-keyed lifecycle. |
| Source-produced change prose and Analysis destination | RETAIN | Keep producer wording and the existing instrument destination; contextualize coverage beside it. |
| Research continuation | IMPROVE copy | Browser-scoped wording; preserve report/revision and current access check. |
| Comparison-basis inspector | PROPOSED | Show captured prior digest and accepted response together; no new read. |
| Missing/malformed/inaccessible baseline | IMPROVE state clarity | No usable saved comparison; never claim a first-ever visit. |
| Failed comparison read | IMPROVE state clarity | This attempt did not save a new comparison; no inferred zero result or globally unchanged storage. |
| Local save result | PROPOSED | Preserve accepted reading while honestly exposing unconfirmed saving. |
| Quiet result with valid empty baseline | IMPROVE state clarity | Valid history can have no covered names; unknown saved date is a separate gap. |

## Actual source behavior

Terminal was inspected at `c30eab3f38717f571abcb8bb24a9df3e0a8edd30`; Macro at `ac830737b94697bcc77672062aaf278a5ca6f45d`.

TodaySinceLastVisit first checks portfolio-brief for the Pro gate and then posts the current request's previous digest to the existing portfolio-changes route. The source's accepted digest can contain an empty names mapping. Missing, malformed and inaccessible local data collapse to no usable digest. A successful response overwrites the stored digest before the existing displayed reading is committed. The current Reading type does not retain all inspector fields or a write result.

The proposal therefore needs a **transient extension in the existing owner**: capture this request's prior digest before any successful write, attach it to the accepted response and retain the storage-write outcome. Reopening the inspector must not reread storage to reconstruct that pair. Another tab may have written a later digest. The inspector must not start a second comparison request.

The producer's asof and previous_asof are desk dates. They do not establish when the member visited, elapsed visit time or valid ordering. The response names the current population; the previous digest does not store a population type. A current watchlist label cannot be copied backward onto the saved digest.

Names may be omitted when desk coverage is unavailable. The producer bounds prior-name processing to 500 sorted names and returned changes to 200; membership wording lists at most 20 names plus a remaining count. This is not a complete portfolio or watchlist audit. “Joined this read” does not establish that the member added an instrument to a list or position.

The ownerStorage wrapper exposes unavailable storage and a boolean write result, but the current void writeStored wrapper discards those distinctions. Visible saving status is proposed, not an existing emitted API field. No new endpoint, storage key, queue, automatic retry or lifecycle owner is introduced.

401 clears the owner's slot and terminates the reading; 403 retains the Pro teaser. Ordinary failed reads do not write a new comparison. Subject identity, abort and generation guards retain ownership. A prior record need not exist when a failure occurs; a different tab may change storage independently. The source's old minutes-cache comment is not used as a current API contract.

## State and action contract

| State | Native specimen | Meaning / allowed next action |
|---|---|---|
| Accepted response, reported change | 33A-0 | Fixture: one producer-reported NVDA change. Open Comparison basis or existing Analysis destination. No list-membership claim. |
| Inspector open | 33A-0 | Saved desk date 5 Nov 2026, returned desk date 8 Nov 2026; current Watchlist symbols, saved type Not recorded; this account/browser profile. Close or Back returns focus to the trigger. |
| No usable saved baseline | 375-0, 390 EN | Current reading remains available; no earlier comparison shown. Portfolio is an ordinary separate destination, not promised evidence for this response. |
| Comparison unavailable | 375-0, 390 ZH | This failed attempt saved no new comparison. Recheck through existing owner or continue Research. Keep “相关标的” neutral until the successful response identifies population. |
| Accepted response, save unconfirmed | 375-0, 320 ZH | Current reading remains readable. Next comparison may use an older digest or no usable digest. Continue Research or inspect this response's captured basis. |
| Quiet response, valid empty baseline | 3B0-0, 768 EN | No tracked changes returned. Saved comparison explicitly exists with no covered names; saved date unavailable. This does not mean empty watchlists/positions. |

Native values are illustrative fixtures, not live user or market data. The date interval is not advertised as visit duration. The same-saved-date, reversed-date and unknown-date source cases remain allowed without fabricated chronology.

## Source and visual critique incorporated

A reasoning-only read of the actual three boards found four wording gaps. The final design removes a global unchanged-storage assertion, removes an evidence promise from a generic Portfolio destination, removes “inspect the list” where no list route exists, and makes the valid-empty-baseline fixture explicit. The saved-date wording was also tightened. A separate body sentence now describes only this failed read's lack of a new write. These are six final exact text changes. Earlier five copy refinements removed implementation vocabulary from product-facing cards while retaining builder detail.

This critique is an aid to self-check. It is not reference approval, GitHub approval or runtime acceptance.

## Verification and limits

- 23 recorded Paper operations returned APPLIED_RESPONSE_OBSERVED; zero unknown effects.
- Final three JSX exports match the expected exact critic corrections. The earlier whole-board verification covered all 17 originals; subsequent mutations targeted only the three new boards.
- 12 important action frames have minHeight 44px. Responsive frames are 390, 390, 320 and 768px. A selector initially also matched two text labels; it was corrected to observed Frame components without changing the design.
- Final screenshots of all three new boards and the two corrected original Today boards were inspected. Labels and actions fit; no visible clipping was found.
- Whole visible JSX equality does not prove hidden-property equality or a full-file backup. Native frames do not prove interactive browser reflow, keyboard operation, zoom, account isolation, working navigation or production deployment.

Before implementing the proposal, prove: request-captured previous digest survives overwrite and concurrent-tab changes; missing/malformed/inaccessible/empty history are distinct from quiet/failed reads; current-only population is not inferred backward; unknown/equal/reversed desk dates remain qualified; bounded coverage is disclosed; successful responses survive failed local writes; 401/403 and identity teardown remain correct; Close restores focus; all touched widths reflow without hiding the primary task. Preserve source-produced prose and existing route/query ownership. No actual account endpoints were exercised in this design phase.
