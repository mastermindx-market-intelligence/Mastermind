# Secretary interaction: observation, action and exact recovery

Use this playbook when the assigned task needs a native ChatGPT Project or a
Web-Sol surface. It describes existing owners and evidence limits; it grants no
browser, account, submit, callback, credential, installation or company authority.
Apply the current task scope and actual tool grants. A completed attended Chat
qualification does not authorize another send. An explicit refusal remains on
that exact effect and must not be retried through a different account or carrier.

## What the existing observer proves

`integrations/chairman_surfaces/web_sol_extension/content.js:buildProbe` reports
the closed `mastermind.web_sol_surface_probe.v1` observation. It hashes the
canonical conversation URL, including the Project path, and compares that hash
with the expected conversation fingerprint. It collects bounded target,
responsiveness, document-ready, visibility, composer, generation, authentication
heuristic and provider-error indicators. It rejects navigation during the
asynchronous hash rather than returning the preceding conversation as current.

It does not read or attest the account, selected model/mode, Project instructions,
answer completeness, submitted prompt or original-parent consumption. A Project
URL hash distinguishes URLs; it does not attest membership or data access. A
composer on a conversation route makes `auth_required=false` under the existing
heuristic; this is not an account identity or a proof that no login dialog exists.
On a chat route without a composer, authentication remains unknown. The existing
v1 schema has no dialog or mode attestation field. Preserve those limits.

`web_sol_protocol.py` validates the closed request/receipt vocabulary and bounded
request window. `web_sol_extension/background.js` owns inspect, foreground and
typed reentry under its existing transport/target fences. `INSPECTED` is an
observation; `FOREGROUNDED_VERIFIED` proves the qualified focus operation;
`CONSUMED` is the existing typed-reentry receipt. None proves that a provider
prompt was submitted, an answer finished, or a company command committed.

## Before an interaction

Recover the assigned original operation and intended audience from its existing
owner. Use only the minimum permitted surface observation needed to establish
the exact candidate: origin, Project/conversation, intended account, visible
mode, current document and allowed action. Retain safe identifiers and qualified
timestamps; do not collect account emails, DOM transcripts, cookies, passwords,
tokens, screenshots or Project instructions merely to fill a generic report.
Private material requires the receiving audience's actual permission.

An observer may proceed under its own read grant while an action remains held.
If a required account, Project, mode or action scope cannot be verified, retain
that fact as unknown and withhold the dependent action. Do not infer eligibility
from a profile name, conversation fingerprint, healthy probe, historical seat,
or caller-supplied role. Do not create or rebind a target to make a fixture pass.

## Failure handling

| Observed condition | Existing-owner response and evidence boundary |
| --- | --- |
| Wrong Project or conversation | Compare the exact canonical URL/fingerprint with the assigned target. A different Project with the same conversation slug is a different target. Withhold the target-dependent action; an observation may report the mismatch. |
| Wrong or unverified account | The v1 probe cannot resolve this. Use only separately authorized, minimum account/audience observation. Withhold private return or submission until the required identity is verified; do not switch accounts as a workaround. |
| Login route, dialog or expired authentication | Preserve `AUTH_REQUIRED` when actually observed. Absence of a composer means unknown, not a fabricated login diagnosis. A visible dialog or fresh MFA/consent requirement belongs to the current permitted authentication owner/human ceremony. Do not include its contents or credentials in the receipt. |
| Selected mode changes or is unverified | Re-evaluate the dependent native capability against the visible mode and current scope. Served-model identity remains unknown unless independently observable. Do not invent a v1 field or auto-switch modes from a probe. |
| Probe/native stream detaches | Mark the observation unavailable or stale. Existing reconnect/generation fences own transport recovery; a reconnect is not proof the original operation completed. Do not continue an action using an old document or receipt. |
| Prompt may have been accepted but response is lost | Retain the original interaction/provider/Executive identifiers and reconcile that operation through its existing owner. Do not submit another prompt or adopt a different carrier merely because no answer is visible. |
| Answer is partial, pending or belongs to another operation | Preserve pending/mismatch status and read the exact original return through its qualified owner. Do not treat generation-idle, focus, ACK or a valid JSON shape as a complete accepted answer. |
| Provider/tool permission refusal | End that effect's retry. Preserve refusal and actual effect state; no alternate-account, profile, tool or carrier route to the refused effect. Independent permitted source work may continue. |
| Two interaction writers seek one desktop | Use the current desktop/Capacity interaction owner and its real custody. Conversation ownership and a historical author do not grant the desktop lease. A missing custody read is unknown, not expiry. |

When dispatch is proven absent, record the actual known non-effect; this is not
retry permission after a refusal. When dispatch may have occurred, preserve the
uncertain original effect. Do not turn transport loss into a provider refusal,
or classify an explicit permission refusal as a technical reconnection problem.

## Source and acceptance owners

The protected observer/protocol/reliability tests cover bounded observation and
transport behavior. The Secretary MCP grounding adapter is an injected Steward
read boundary; it is not the desktop operator or provider-submit owner.

Existing GitHub carriers must remain distinct:

- **#836** owns cognition submission/result observation and semantic ACK through
  the real extension paths, including original identity, generation, stale and
  ambiguous effect handling and result privacy tests. Inspect its exact current
  source and installation/admission before relying on it; its presence as a PR
  does not make these actions part of every installed observer.
- **#989** owns frontier mode and Secretary decision contracts. A mode contract
  does not prove a selected live mode or principal permission.
- **#847** owns census popup inventory-versus-document-probe health. Healthy
  inventory with failed probes is incomplete observation.
- **#1360** owns the separately disarmed Dot READ/RESEARCH worker transport. It
  is not native Project Chat or permission to reopen a refused Dot interaction.
- Session Bridge/Runtime return, Dialogue/Wake and the selected application host
  retain exact request/read/commit/receiver/parent-consumption responsibilities.
  Their receipts must be joined through actual current bindings, not labels.

No historical PR title, author or Draft flag proves an active writer or live
effect. Reconcile current source custody and operation state before modifying an
incumbent carrier. This playbook adds no scheduler, lease, session registry,
authority, queue or new recovery owner.

## Privacy-safe regression and release evidence

`tests/test_web_sol_inspect_no_effect.py` executes the actual repository
background source in Node using the accepted synthetic Chrome IO harness. It
checks duplicate targets refuse before reprobe or focus, successful inspection
performs one actual probe with zero tab/window effects, and every resulting
document passes the real Python receipt validator. The existing protocol suite
checks forbidden content/credential keys and branch-specific receipt evidence;
the existing content observation tests check navigation and coherent observation
timing. These fixtures never connect to a provider, read a real profile, send a
prompt or change account state.

This increment does not add a private-DOM/cookie extraction sentinel, account or
mode attestation, login-dialog detection, or provider submission/result handling.
Any additional coverage must exercise its actual source owner and be adjudicated
as separate evidence; the playbook does not turn a proposed test into a result.

Run it with the existing content observation, protocol and reliability suites:

```sh
python -B -m pytest tests/test_web_sol_inspect_no_effect.py \
  tests/test_web_sol_content_observation_epoch.py \
  tests/test_web_sol_protocol.py tests/test_web_sol_reliability.py
```

Node is required for these behavior checks. Source and fixture success qualify
this bounded observer regression only. R2 section 15 still requires installed,
permission-qualified wrong-target enforcement, dialog/account/mode evidence,
original interaction reconciliation after detachment/ambiguous submission,
complete exact return and actual receiver/parent consumption. A clean sample
without the relevant receiving enforcement or real-path evidence is insufficient.
