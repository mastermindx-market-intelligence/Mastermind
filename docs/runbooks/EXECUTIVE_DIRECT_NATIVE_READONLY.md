# Authenticated direct native research

The explicit `native_research_only` Launch choice uses the existing authenticated
App, CEO ingress, Runtime, local allocator, native Supervisor and worker broker.
It admits one self-rooted, role-null Job with an attempt limit of one. Its grant is
exactly READ and RESEARCH; write paths and test commands are refused. The existing
`research_only` choice retains its COO planning and child-workspace behavior.

Source qualification does not authorize a live submission. Before using this
choice, the combined protected release must be installed and selected through the
normal gateway/control owners. Actual company identity/readiness, sealed acceptance,
Gate B, the current source/configuration and the existing execution receipts must
qualify. Initial direct execution uses the existing full ARM with
`foreground_only=True` and `native_return=False`. The normal Control and Worker
operator flags and root-owned autonomy receipt remain required; no new arm or
receipt is introduced. Foreground selection suppresses unattended COO drive.
READY or CEO-submit admission alone is insufficient.

## One task and its result

1. Open the authenticated app and choose **Native research only** explicitly.
   Use the prepared immutable source and a concise read-only objective. Do not
   provide a worker, provider, path, principal scope or execution binding.
2. Submit once. Commission/source preparation can precede inner admission: a
   refusal with zero Job/Attempt does not prove that preparation had no effect.
   Preserve the original operation pointer for reconciliation.
3. The server derives the original principal/source binding and the configured
   native Worker. The existing allocator reserves the exact Job before creating
   its credentialless local clone, then records same-call completion. An
   unresolved reservation is not adopted from a matching path. No remote paid
   filesystem, paid capacity probe, planner, child or review Job is involved.
4. Read the selected direct result. The server discovers only that Job's current
   Attempt when the initial selection has `attempt_id: null`. A visible result
   requires the actual retained native collection, validation, assignment seal,
   principal, grant, completion Event and finalized bounded-read observation.
   A summary or a successful process exit is not a substitute.
5. Use the explicit acknowledgment action after reading the result. It binds the
   exact Job, Attempt, terminal digest and original receiver. Reading or polling
   never acknowledges. The original commissioning parent still judges the
   returned content; acknowledgment does not assert product acceptance.

## Lost replies and unavailable results

Keep the existing pending pointer. For a lost submit reply, recover through the
original status identity; do not submit a replacement. Status derives the durable
mode and Job from the original creation Event. A queued Job is not evidence that
it executed, nor permission to replay its allocation or start.

For a lost acknowledgment reply, read the original terminal selection. A committed
acknowledgment is returned with its same retained receipt digest. Once the consume
boundary has been entered, an unavailable readback is `EFFECT_UNKNOWN`, with no
fabricated UNCONSUMED state. Recovery reads never issue another acknowledgment.
Conflicting operation keys, changed digests, another principal, changed source or
changed authority generation refuse.

A lost/partial allocation, claimed start with uncertain delivery, expired lease or
changed fence stays on its original operation. There is no automatic startup
relaunch, path adoption, general dispatch bypass or second lifecycle store. Use
the existing owner for exact-operation reconciliation. Do not reset identities,
change carriers or infer settlement from process absence.

## Implementation and qualification limits

Schema 7's role-null Attempt columns remain NULL. The existing Event owner retains
closed direct claim/placement and launch-principal evidence. Internal typed Attempt
views rederive those exact unique joins; callers cannot supply them as authority.
The normal mixed-worker factory retains its genuine native primary as this task's
launch and finisher owner. The existing readonly native quota view is reused only
at an admitted direct action; it is the same physical Worker, not extra capacity
or a review Job. Merely installing a callable or starting closed readside does not
add that view or change the prepared baseline.

Offline connected tests exercise real signed HTTP, Unix ingress, allocator/Git,
Runtime, native Supervisor validators, bounded result reads and the existing
consumption transaction. Root receipt/current-host grants, source-publication
observation and physical process/UID/broker observations are explicit simulations.
They do not prove installed credentials, inference, live readiness, the real H2
journey, a repair operation, or authenticated production UI acceptance. Those
remain separate action-time and parent acceptance obligations.
