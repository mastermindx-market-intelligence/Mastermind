# Retained work and review results for a programme

Programs keeps the canonical workstream's full bounded Runtime root candidate
list. When more than one root is present, the current Mission remains in
CONFLICT; no newest root is guessed and terminal roots are not hidden.

Choose **work and review history** under that programme, then **Show retained
results**. Choose an actual returned result reference to read its exact root,
Job, Attempt and envelope digest. This is a separate read-only selection: it
never changes the current Mission, a Launch form, a command pointer or an
execution/consumption grant. Another programme's results are not substituted.
All candidates remain available through the finite disclosure after eight rows;
a malformed, duplicate or over-budget vector offers no choice.

Only root multiplicity is admitted by this additional retained-history route.
The existing Workspace principal permission, unique programme/responsibility,
source card validity and fresh paired CCR cache remain required before and after
the bounded Runtime read. The selected root must belong to that same validated
candidate vector, and actual immutable Runtime workstream provenance must match.
Source, membership, auth or Runtime observation drift refuses without returning
result data. Mission/global singleton selection and all action guards stay exact.

A new Programs read, candidate/workstream change, auth epoch or host epoch clears
this local choice and aborts old requests. Re-select from the newly validated
list. This UI state is neither authority nor a new durable registry. Catalogue
age and global Mission state remain visible; reading historical results never
refreshes them or turns the Mission CURRENT.

The reference index serves the existing canonical orchestration role results:
planning, work, review, repair and aggregation. It does not invent an OHF role
for a direct native task. H2 native results and explicit acknowledgment stay on
their existing original-principal direct pointer/panel. Reading this list or an
exact result does not acknowledge consumption, approve a review or accept work.
Actual original-parent judgment and authenticated product proof remain separate.

The App also recognizes the already-supported closed consume-pointer variant
when reopening a retained operation. This corrects its presentation label only;
Check status still invokes the existing readOperation/recover owner, never
prepare, submit or another consume. Malformed/unknown pointer variants remain
unrecognized and uncertain operations remain on their original owner.

## Source qualification scope

This is an existing Programs utility inset (archetype I), using the canonical
card, button, section heading, muted copy, native focus ring and disclosure.
Dark uses the existing graphite surfaces and restrained complete outlines;
light uses the existing cool canvas, white cards and neutral hairlines. No CSS,
colour token, container-edge accent or new component family is introduced.
Affected labels have EN/ZH parity; eight visible choices expand to the complete
bounded list through keyboard/touch-accessible disclosure.

The source fixture matrix covers dark/light × EN/ZH × 1440/390, with the global
CONFLICT retained beside the selected work/review history. The controlled fixture
has no actual sign-in, installed Runtime, provider or accepted Mission. Separate
unit/owner tests cover malformed/unknown/over-budget candidates, source/auth/root
changes, unavailable reads and the existing result-detail path. These checks
qualify implementation, not the final authenticated installed product journey.
