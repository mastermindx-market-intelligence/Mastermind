## Each account / distinct Project

1. In ChatGPT Web open the intended Mastermind Project's **more (•••) >
   Project settings > Project instructions**. An authorized Project owner or
   editor needs to make the save. A shared Project requires one successful save
   per distinct Project, not one per member account.
2. Inspect/copy the existing saved instruction text first. Replace the older
   **managed Mastermind Sol Bootstrap** block with the complete export; do not
   blindly delete newer Project-specific policies or another session's live UI
   edit. The Project field must satisfy both the UI character limit and bytes.
   If additional valid Project rules cannot fit, do not silently discard them:
   leave that seat unmodified and reconcile a smaller approved source block.
3. Save, reopen **that same Project** and confirm the saved start marker,
   `LONG-HORIZON DEFAULT`, `PRE-FINAL FALSIFIER`, preserved safety/release
   markers and exact full text. GitHub publication alone is not installation.
4. For a separate personal ChatGPT account, repeat only if it has a *different*
   relevant Project. If it shares the same Project and saved text, the Project
   settings apply to that shared Project's chats.
5. If Mastermind work happens in chats outside Projects, optionally add the
   account-global overlay via **Settings > Personalization > Custom Instructions**.
   Project instructions override global Custom Instructions inside that Project.
   Do not paste the 7,998-character Project block into the smaller global field.
6. On each intended account/surface, start a fresh real, authorized mission
   canary with a ready phase and a distinct next phase. Observe whether it
   actually *starts* the second phase after checking and saving the first.
   Test CI-pending-with-independent-work, a live writer/unknown effect, a real
   denial (no reroute), and a bounded one-phase task (correct early finish).
   Record only real behavior/receipts, not hidden-reasoning guesses.
7. Keep an installation matrix in the **existing authorized rollout evidence**
   (no new registry): exact account/Project identity as appropriate, saved-text
   readback or blocked reason, canary result, actual mode if exposed and evidence
   timestamp. Do not copy credentials or cookies.

## Important limits

A live Web response ends the model's tool/reasoning work. The instructions seek
longer *healthy foreground execution* across useful phases; they do not confer
unattended reasoning, duration guarantees or background Work/automation capacity.
If continuous work after the ChatGPT response is genuinely required, use an
already-authorized external executor with a proven STARTED/RUNNING identity and
return path. No new queue, watcher or recurring cost is authorized by this rollout.

Outcome measure: completed accepted user/machine milestones per turn and fewer
unnecessary user re-prompts, while protecting actual denials, runtime custody,
code review/security rules and correct early task completion. Elapsed time alone
is not the success metric.
