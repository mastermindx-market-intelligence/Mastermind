# Qualified Ubuntu0 GLM observations

This is a source composition for the original H1 app-to-worker path. It does
not install/adopt a collector, qualify an actual host, clear a prior refusal,
select capacity or grant a provider request. Canonical provider-entry parity is
a separate, required composition through the original controller and executive
owner. The old collector, Qwen and ordinary legacy worker behavior are unchanged.

The unchanged normal collector sources mutable `HOST_ENV` and reads private
account configuration. Merely selecting a generation with the stdin transport
fix is therefore not a qualified deployment. The old detached physical command
returns DATA only and cannot populate recurring admission state. The Root paid
qualification object remains same-process, single-use and at most 60 seconds
old; neither that object nor its timestamp is a 600-second account observation.

## Existing owners and new finite modes

`host_pull.sh --physical-only [--once]` uses the existing collector transport,
PID guard and host snapshot writer for fixed Ubuntu0. It produces new physical
measurements, never builds an account probe or reads provider configuration.
The occupancy program still needs actual qualified source/custody; a historical
support digest or the spent physical diagnostic is not that proof. Missing or
failed readings remain unavailable. Boot identity is actual public kernel DATA.

`host_pull.sh --qualified-readiness [--once]` adds the separate fixed observation
after physical publication. It loads only the real fixed Root paid definition,
verifies the complete sealed release, retains the current definition/source and
registry identities, and compiles the exact private initializer package. The
installed commitment remains expected initialization DATA. This explicit source
mode, its fixed observer and actual action-time commission supply the new read
scope; installation alone does not authorize private reads.

The new observer reuses the existing held-image/no-site startup and exact c7
outer/private-DATA helper transformation. It does not execute helper code or
source mutable legacy `HOST_ENV`. Its one selected account comes from actual
installed registration. The exact current GLM validator inspects a bounded
no-follow private configuration snapshot in the actual initialized context;
configuration must be regular, account-owned, single-link and mode 0600;
credential bytes and arbitrary errors never leave that process. Genuine alias
presence is distinct from quota, grant room and model/provider availability.

## One binding at producer, writer, picker and broker

`paid_host_readiness.open_installed_context()` accepts no caller input. Its live
context exposes detached `binding`, `initializer_commitment`, `source_hashes`
and `check()`. `qualified_config_identity(context)` reads/rechecks the same
fresh known/True installed-alias envelope and returns only its detached nine
metadata fields for independent remote verification; descriptor timestamps are
not copied into a long-lived capability. The closed binding schema is
`mastermind.paid_host_readiness_context/v1` with exactly:

- `schema_version`, `host`, `transport_alias`, `worker_id`, `account`, `model`,
  `boot_id`;
- `source_config_sha256`, `release_manifest_sha256`, `registry_sha256`,
  `initializer_commitment_sha256`, `validator_sha256`, `readiness_source_sha256`.

The fresh envelope is `mastermind.glm_qualified_account_readiness/v1`, scope
`qualified_glm_context.v1`. It carries that exact binding, actual observation
time, the sole registered alias's literal flag and the held configuration's
nine-field identity. Unknown/refused observations carry no aliases or identity.
They never become a grant or a synthetic available account. The native source
module must equal the Root sealed copy; expected context is re-derived at each
consumer, not read back as authority from the envelope.

Physical time is never updated when account DATA is published. A physical
refresh may preserve an existing NEW-schema observation with its original
account timestamp and DATA unchanged; it never copies legacy account envelopes
into the new mode or renews stale facts. Physical
freshness is at most 180 seconds; account freshness is independently at most
600 seconds, with the existing one-second future slack. Null, non-finite,
future, stale, mixed-source, foreign-boot and changed context refuse. The
current ordinary picker uses the new stricter predicate for a new envelope.
The canonical broker additionally requires `require_qualified_context=True`;
legacy cache format cannot silently satisfy canonical admission. Real broker
room/lease checks and the actual canonical AccountTable/Control guard remain.

## Failure, loss and correction

A malformed configuration or unavailable read is not positive evidence. A lost
read-only transport clears account readiness; a later cycle under the existing
recurring grant is a new observation with a new nonce. This is defensible only
because this exact fixed startup performs exports, a directory-existence test
and private DATA parsing: no helper evaluation, provider request, process launch
of a worker, credential rotation or external write occurs. This rule cannot
recover any old uncertain mutating/provider operation or spent diagnostic.

An actual permission/custody/protocol/context refusal is retained as the
original `status=refused` observation, with its original scope, context and
time. Physical refresh, restart, elapsed time or transport labels cannot erase
it, freshen it or enter the internal transport around it. There is no retry
counter, new queue or new authority store; this is negative observation DATA in
the existing host snapshot and the normal collector return.

The fixed module's explicit `correct-refusal` action belongs to the genuine
Root administrative owner. Both current-context SHA and exact original-refusal
SHA are mandatory CAS inputs. The existing canonical CONFIG_ROOT publication
mutex serializes the action before CAS and private observation; concurrent
correction or installation cannot dispatch around that owner interval. Root UID, a commission or those hashes **do not
resolve an actual OS/tool/provider denial**. Invocation stays held until the
specific supported resolution and admission exist. A failed, denied, unknown or
lost correction retains the exact old refusal. Only a genuinely successful,
newly permitted observation replaces it; there is no flag-clear operation and
no Root reinstall requirement.

The incumbent qualifier already drops a verified principal to UID501 and owns
a bounded child, but has no readiness-correction parent-authentication API.
Correction therefore uses one ephemeral inherited AF_UNIX socket through the
same dispatcher. Kernel Root peer credentials plus exact context, request and
refusal digests authenticate only that handoff. They grant no organizational
admission or denial clearance. The socket is consumed once and closed locally;
the fixed-FD9 spawn follows the incumbent controller pattern, and Bash closes
FD9 before SSH. There is no listener, daemon, grant issuer or persistent capsule.
Mac uses the native `getpeereid` API; Linux fixture coverage uses `SO_PEERCRED`.
Unsupported peer inspection fails closed.
