# Successor of an installed but unstarted migration preparation

This finite source contract applies when the genuine completed migration executor P has already been selected by the normal installer, but its original migration-aware preparation has never started acceptance. A different independently sealed release R is needed. Installation is not acceptance: this mode gives P no PASS, run marker, proof Job or carry, and performs no migration, checkpoint, install, configuration change or service stop/start.

The original branch `--supersede-unstarted-migration-preparation-sha` still requires the original selected release and exact original source-control bytes. It cannot be used after selecting P, and the operator must not restore the old config to make it eligible. No legacy selected-schema allowlist is widened.

## Source and current-state contract

The parent is only the original `supersede_unstarted_preproof_v5_to_v7_v1` descriptor with its exact canonical digest, closed eight-file preparation, genuine sixteen-origin spent-ctime material, four P migration receipts and all sealed payloads unchanged. A prepared successor cannot itself be the parent. Run-started, carry, acceptance leaves, partial preparation and occupied target refuse.

The installed-P config is not accepted by `proof_base_sha` alone. The owner parses the parent's immutable original `source-control.json`, calls the unchanged `prepare_control_successor.build_successor` with P and the same sealed Macro coordinate, then applies only the incumbent installer's exact disabled terminal-return socket normalization. Complete current raw bytes must match the canonical normal-installer output. Every optional and privileged setting remains the supplied value; privileged readiness is not silently disabled or newly armed. The fixed normal install verifier checks P's release manifest/full seal and Control/Worker plist source binding. No caller config DTO, alternate input path, general field whitelist or skip flag grants this mode.

Fresh Root/Darwin qualification, guarded config identity, stopped Control/Worker/Relay, closed worker harness and intake arms, canonical service lock and the existing source/deeper lineage guards remain required. The helper still uses actual CURRENT INITIAL evidence: exact C67 database path/device/inode/size/raw SHA, absence of authoritative sidecars/barrier/running marker, full semantic projection, exact P working baseline, preservation inventory and canary, original source-v5/full-eight-table digest and genuine P/R seals. A prior running read transaction reporting semantic equality is not a substitute. Never inspect the authoritative running DB with immutable reads or checkpoint it to make these conditions pass. If any action-time physical or semantic predicate differs, refuse and report that fact; do not reseal a baseline or replay migration.

## Explicit preparation and publication

From qualified sealed R, use normal predecessor/root/terminal-carry arguments and only these selectors:

```
--supersede-installed-unstarted-migration-preparation-sha P
--superseded-migration-preparation-descriptor-sha256 D
--expected-installed-parent-control-config-sha256 H
```

D is the genuine immutable parent descriptor's canonical digest. H is the current qualified installed-P raw config hash, a CAS comparison rather than authority. Omit the original prepared-selector, all old supersession selectors and all migration/reconciliation/qualification/recovery flags.

The new descriptor schema is `mastermind.executive_acceptance_maintenance/supersede_installed_unstarted_migration_preparation_v1`. It retains all original parent fields except schema and successor, the two prepared-parent references, and adds `installed_parent_control_config_sha256`. The R bundle contains exactly the existing eight working preparation files plus Root0400 `installed-parent-control.json`. That ninth file is the exact held current P raw preimage. All six original payloads, including the old source-control and migration material, are byte copies; P remains eight files. The current installed-P snapshot and original selected-source provenance have separate meanings and neither rewrites the other.

The owner retains the config, lock, full source/evidence and named/FD identities through final requalification and atomic target publication, including a final exact P install check. Any private candidate or uncertain publication is retained, never automatically cleaned or retried. Exclusive administrative custody remains an assumption against noncooperating privileged writers, not a global filesystem/SQLite lock.

Separately qualified normal R installation/selection remains the existing owner's operation. Admission authenticates the sealed P snapshot against the original source input again, requires actual R config equal its complete normal successor transform, proves R's actual install identity, and rechecks all sealed inputs and current INITIAL evidence through the exclusive run marker. It does not require P to remain currently selected after R installation. The migration executor remains P and material remains identical to the original sixteen origins.

Actual R proof Jobs, real summary, backup/restore, physical-history/count, running-Service-safe finish and future carry remain the existing acceptance owners. The installed-parent snapshot is hash-pinned and revalidated for first finish and historical carry; it is not a historical current-config requirement. Heartbeat/WAL activity after normal proof/restore is allowed by the unchanged finish contract. No historical fallback may stand in for INITIAL before admission, and P receives no acceptance credit.
