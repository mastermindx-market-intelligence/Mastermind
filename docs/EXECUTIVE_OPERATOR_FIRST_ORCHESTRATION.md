## Outcome and architecture

Fresh orchestrators and operators receive the same concise operating contract and their exact role, use an actually available root-bound Fabric client, delegate without repeated Chairman reminders, and return accepted bounded outcomes. Minimize total scarce-pool consumption per accepted outcome: framing + delegation + builder + review + repair + integration + principal consumption. A cheaper builder alone is not success when premium parents do all adjudication.

Allowed planning shapes include CEO -> worker; CEO -> operator -> workers/reviewers; Meta-CEO -> CEO -> operator -> workers/reviewers; and Meta-CEO -> operator -> workers/reviewers when another CEO adds no decision value. Fable/Opus have analogous shapes. These are instructional shapes, NOT new Runtime role enums or admission. Preserve the original root and true immediate parent; never hide an intermediary or mint a new root to fit a depth limit.

The default delivery operator is the least-scarce qualified admitted operator outside the protected principal subscription pool, usually GLM/Grok in the requested estate. It owns decomposition, worker briefs, source partitioning, independent review scheduling, return adjudication, bounded repair and domain integration. It does not spend its own expensive reasoning on routine leaves. Deterministic operations use code; routine implementation and test work use qualified economical workers. Classify each child separately; a management role is not a C3 frontier witness.

A program CEO retains consequential program decisions, difficult exceptions and final program acceptance, not every worker command or ordinary review. Direct CEO -> worker remains legal when the complete closure costs less or a concrete admitted exception applies. Direct dispatch includes ownership of adjudication; it cannot silently discard that duty. Retain direct work only for LOWER_TOTAL_OVERHEAD, PRINCIPAL_JUDGMENT, UNIQUE_APPROVED_ACCESS, CRITICAL_PATH_SHORTCUT or NO_ELIGIBLE_PRE_EFFECT_WORKER. Escalation cannot be a workaround for a denied or effect-unknown operation.

A strategy principal is optional. If no additional executive judgment is needed, do not add Sol/Opus between Astra/Fable and an operator. A role name neither fixes a provider nor proves a quota boundary. Current ModelRouter/Capacity and provider evidence decide exact qualified model, surface, account, host and economic envelope. Latest qualified Opus is a centrally resolved exception binding, not the default management layer and not an inherited Fable child.

M2 is currently a control endpoint, not a required worker host. Remote agents must not receive broad M2 SSH, provider credentials or a raw broker socket. A local adapter may use the existing local transport; a remote adapter must use the accepted authenticated ingress. Moving the control service to another host is a separately qualified deployment, not part of instruction installation.

Root, current parent Attempt/fence, role grant, budget and permitted scope come from the trusted launch/runtime owner. Model-visible delegation inputs contain bounded business intent and references only. Do not accept caller-selected account, provider, host, credential, root, parent, execution profile or scope expansion. An injected role description is guidance, not authentication. A self-hashed receipt is not authority.

All actual coordinators/operators may request descendants only under explicit admitted role/depth/capacity. Workers/reviewers remain leaves. Preserve root-wide ceilings across concurrent siblings, cumulative starts, repair/review reservations, quota windows, host resources and exclusive source lanes. Reserve completion capacity before widening builders; unconsumed review/integration applies backpressure. Unknown or stale capacity cannot become an allowance. A lease timeout does not restore a provider quota and does not prove process death.

Do not simply raise native subagent limits. Existing native restrictions remain until the exact managed child route is qualified. Ordinary native Agent/Task trees and nested provider CLIs must not replace Fabric admission. Use native harnesses when admitted, but manage their lifecycle through the existing Fabric owners.
