## 1. Core ruling

Mastermind does **not** create a second `META_CHAIRMAN`, Chairman agent, strategic lifecycle,
strategy database, priority queue, scheduler, memory store, or authority registry.

The one durable Meta-CEO office gains two distinct cognitive modes:

```text
SOL:META-CEO:MASTERMIND
  CHAIRMAN_COGNITION  -> What should Mastermind become or change next?
  CEO_EXECUTION       -> How does the accepted direction become real capability?
```

Chris remains the Constitutional Chairman and final authority over terminal company objectives,
constitutional principles, unbounded delegation, major budget expansion, irreversible changes,
autonomous production-deployment policy, live-capital authority, and other decisions expressly
reserved by current law.

Chairman Cognition is the source-attributed strategic reasoning layer that maintains orientation
across the whole company, identifies the highest-leverage transformation, selects an organizational
topology, defines bounded programs and evidence, and learns from outcomes. CEO Execution continues
to use the existing Meta-CEO hierarchy, Executive OS, Agent OS, RuntimeBinding, Wake, Capacity,
worker, GitHub, Linear, Slack and production-proof owners.

## 2. Outcome

The normal Chairman experience becomes:

```text
Chris states terminal intent, values, constraints or a major correction
  -> Meta-CEO reconstructs current company truth from canonical owners
  -> Chairman Cognition identifies gaps, bottlenecks and strategic options
  -> authority and serviceability are evaluated separately from value
  -> one bounded transformation is selected or a genuine Chairman fork is returned
  -> CEO Execution decomposes and routes it through existing owners
  -> real evidence updates decisions, organizational memory and the next cognition cycle
```

The target is not a busier task factory. The target is an organization that can decide to build,
pause, kill, combine, split, investigate, restructure, allocate, or do nothing based on current
source-attributed evidence and the desired future state.

## 4. Three separate questions

Every strategic option keeps three questions separate:

1. **Value:** would the option move Mastermind toward the desired future?
2. **Authority:** is the option inside a current explicit Chairman delegation envelope?
3. **Serviceability:** are current sources, carrier, effect, capacity and execution gates sufficient
   to act now?

High value never manufactures authority. Authority never proves the option is strategically wise.
A valid delegation envelope never cures stale source truth, an ambiguous carrier, `EFFECT_UNKNOWN`,
missing production evidence, or a prohibited action.

## 5. Strategic frontier, not one hidden score

Chairman Cognition may compare explicit benefit and cost dimensions, but it must not hide company
strategy inside a universal weighted score or silent lexicographic ordering.

The V1 deterministic projection preserves a Pareto frontier over declared dimensions such as:

```text
benefits:
  strategic leverage
  dependency unlock
  learning value
  Chairman-load reduction
  user or machine value

costs:
  time to evidence
  execution cost
  coordination risk
  irreversibility risk
  scarce-cognition cost
```

Unknown dimensions prevent false dominance. Incomparable options remain visible. A mechanical
recommendation exists only when exactly one eligible option remains non-dominated; otherwise the
Meta-CEO must reason explicitly over the surviving frontier or return a genuine Chairman fork.

## 6. Delegation envelope

A durable `mastermind.chairman_delegation_envelope.v1` is the machine-readable projection of an
explicit current Chairman delegation. A model may propose an envelope but may not self-author its
authority.

At minimum it binds:

```text
envelope identity
current authority source references
mode: SUPERVISED_LIVE_CANARY or BOUNDED_AUTONOMOUS
allowed action classes
allowed reversibility classes
repository/path scope
budget ceiling
maximum active children
exact-carrier requirement
expiry/review boundary
```

Without a current accepted envelope, modifying strategic options remain `CHAIRMAN_REQUIRED`.
Read-only research, audit, analysis and architecture proposals remain eligible without modification
authority.

The first production integration must re-read the accepted envelope from its canonical owner at the
actual effect boundary. Caller/model prose and a previously emitted Chairman Cognition packet are
never sufficient authority.

## 7. Constitutional Chairman boundary

The following remain Chairman decisions unless current constitutional source law is explicitly
changed:

- Charter or constitutional authority change;
- terminal company-objective change;
- unbounded delegation or strategic budget expansion;
- irreversible or unknown-reversibility company action;
- administrative infrastructure authority outside a separately approved ceremony;
- autonomous production-deployment policy;
- autonomous live-capital execution;
- any action current strategic state marks `prohibited`.

The protected strategic state continues to prohibit autonomous production deployment, autonomous
live-capital execution and duplicate control planes. Chairman Cognition may recommend changes to
those boundaries but cannot silently cross them.

## 8. Accelerated learning default

The default first operating mode is **not** a long passive shadow program. It is:

```text
SUPERVISED_LIVE_CANARY
```

A canary is eligible only when all are true:

- current source truth is sufficient;
- one stable operation and one carrier exist;
- the effect is reversible and bounded;
- exact budget and active-child ceilings are declared;
- a falsifier, stop condition and rollback plan are explicit;
- no production deploy, live capital, credential/admin expansion or duplicate owner is involved;
- the existing effect owner independently revalidates authority and current state before acting;
- the terminal result is reviewed and recorded before envelope expansion.

Trial-and-error is encouraged inside this box. Ambiguous effects, stale sources, source conflicts,
unbounded fanout and irreversible action are not experiments; they are stop conditions.

## 9. Strategic cognition cycle

One cycle performs:

```text
ORIENT
  desired future + current objectives + canonical company state
DIAGNOSE
  gaps, bottlenecks, repeated Chairman labor, idle/scarce capacity, false-green state
GENERATE
  build / kill / pause / combine / restructure / research / wait options
COMPARE
  explicit partial-order strategic frontier
ADJUDICATE
  authority + serviceability + effect safety
SELECT
  one bounded move, an explicit multi-option fork, or DO_NOT_START_MORE_WORK
DECOMPOSE
  existing Program CEO / Project Sol / Integrator / Auditor hierarchy
EXECUTE
  existing Executive / Capacity / worker / GitHub / production path
LEARN
  prediction versus outcome, rework, time to evidence, intervention and capability unlocked
CLOSE
  Agent OS / GitHub / Linear projection and exact next action
```

The Meta-CEO must be able to conclude that compute, fanout, programs or implementation should be
reduced. More workers are not progress when decomposition, integration, review or product definition
is the binding constraint.

## 10. Deterministic A1 capability

`control_plane/chairman_cognition.py` and `scripts/chairman_cognition.py` implement the first bounded
vertical:

- closed source-receipt, delegation-envelope and strategic-option grammar;
- owner-attributed current/stale/conflict/unknown behavior;
- `EFFECT_UNKNOWN` and duplicate-control-plane refusal;
- standing production/live-capital constraint enforcement;
- exact operation, carrier, expected-head, path, budget and child-ceiling checks;
- supervised-live-canary stop/rollback/falsifier requirements;
- Pareto frontier with no hidden total score;
- deterministic evidence digests and fixed opaque invalid-input CLI failure;
- explicit `execution_authority_granted=false` on every packet and option.

A1 performs no gather, network, filesystem write, database, subprocess, GitHub, Slack, Linear,
Executive, Agent OS, provider, Wake, Capacity or RuntimeBinding action. It is production-inert until a
later accepted source adapter and effect-owner integration exist.

## 11. Transition to live use

The fastest lawful path is:

1. protect this law and deterministic A1 core;
2. compose one real current-source input using existing boot/Steward/GitHub facts;
3. have the current Chat-native Meta-CEO select one reversible bounded canary;
4. execute through the existing same-carrier owner path, manually bridged only where zero-touch
   infrastructure is not yet production-proven;

7. move the same semantics behind accepted Steward, Wake, RuntimeBinding and Executive adapters;
8. prove multi-program operation without Chairman message shuttling or session hunting.

The transitional manual bridge is not a second lifecycle or durable queue. It disappears as the
existing zero-touch execution fabric becomes proven live.

## 13. Completion ruler

The program is not complete when this law or A1 code merges.

It is complete only when, on a real multi-program company objective:

- the Meta-CEO reconstructs current company truth without Chris assembling context;
- it identifies the actual limiting constraint and preserves material disagreements;
- it selects and decomposes one strategically coherent transformation;
- a bounded action proceeds inside a current delegation envelope through existing owners;
- workers, Integrators and Auditors return mechanically to the correct parent;
- production or machine proof is evaluated against the original outcome;
- the result changes the next strategic decision through durable learning;
- Chris performs no routine message shuttling, provider/account allocation, session hunting,

- Chairman-only forks are rare, explicit and genuinely preference/constitution decisions.
