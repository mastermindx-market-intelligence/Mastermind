# Product acceptance through the sealed Context owner

The trusted Control composition supplies its existing Workspace
`InstalledBootPacketCollector` to the review basis reader. It uses the same
attested Python, code root, expected protected source, configured Macro root,
clean snapshots, bounded child process and immutable Macro materialization.
The model cannot provide a collector, command, interpreter, source root or
expected source identity.

`read_product_acceptance_basis` is an internal acquisition method, not a tool or
an authorization. It requests the existing workstream CLI with the workstream
from the Runtime and the freshly verified Macro SHA. The existing basis parser
checks the exact commission and original objective. The referenced workstream
record is hashed from that same materialization. Both materialized and canonical
source generations must remain unchanged through the final read. The method
has a cumulative limit of 15 seconds and a 256 KiB process-output limit; it does
not join the global boot-packet collection key or reuse a completed result.

The basis reader accepts only the exact collector type with its own code root,
its configured Macro root, an expected source SHA and synthetic mode disabled.
It preserves the uncomposed isolated/no-site refusal. Collector failures become
the existing closed `CONTEXT_OWNER_UNAVAILABLE` result. The existing global
boot-packet method retains its schema, admission and coalescing behavior.
The reader retains the collector's source/Macro/code roots, interpreter, expected
source and synthetic-mode setting at construction and checks them before and
after acquisition. Runtime helper exceptions and failed/limited record reads
remain unavailable; only a successful record read with different bytes is a
source-change finding. Specific basis refusals retain their original reason.

Local tests use actual temporary Git repositories and the real snapshot,
materialization and source-byte checks. Their compiler output and sealed Python
entrypoint are fixtures. Isolated-parent routing is tested by setting the
reader's observed flags, not by claiming an installed runtime ran. They cover
identity mismatch, source-byte mismatch, source changes restored before return,
collector binding, bounded input and unchanged uncomposed refusal. Existing
reader and concurrency suites cover the shared physical path.

Installation remains held. PR #1273 owns the required workstream CLI, which is
absent from the current protected source. Its source-release protocol and the
original #1307 unknown review are unchanged. Qualification must compose that
protected CLI, prove its descendant process and environment behavior, verify
all Context dependencies are in the existing materialization, and execute the
actual sealed host path. Do not copy the held CLI, remove isolation, choose an
alternate interpreter or count fixture output as that proof.

Original-parent request ingress, principal qualification, committed ruling and
actual parent consumption are separate obligations. This source acquisition
neither borrows the Company consultation grant nor adds worker dispatch,
principal enrollment, installation or runtime arming.
