## 1. Chairman outcome

A ChatGPT Pro conversation is disposable working memory. One logical Sol responsibility is not disposable. The required product journey is:

```text
same logical Sol responsibility
-> current exact ChatGPT Project conversation is intentionally retired or can no longer continue safely
-> exactly one successor conversation is created in the same approved managed-browser profile and same ChatGPT Project
-> exactly one deterministic continuation bootstrap is delivered
-> successor reconstructs current canonical company state
-> semantic readiness is established through the accepted organizational owner
-> RuntimeBinding generation advances to the exact successor
-> predecessor generation is fenced and stale
-> surface navigation points to the successor
-> successor performs the next observable governed action
```

To the Chairman, many disposable conversations must behave like one long-lived Sol. Completion is not “the extension created a chat.” Completion is exact succession, recovery, authority transfer, predecessor fencing, and useful continuation with zero Chairman click/type/message shuttling.

## 5. Succession, not failover

Context rotation is a planned, fenced succession for the same logical responsibility. It is not permission to paste a started modifying action into another chat.

Before successor authority may advance:

1. resolve the exact predecessor binding;
2. establish `ROTATION_REQUIRED`;
3. reconcile every modifying effect;
4. establish sufficient durable continuation;
5. own exactly one successor attempt under one operation;
6. prove semantic readiness through an accepted owner;
7. ask the existing RuntimeBinding writer to perform the generation transition.

**EFFECT_UNKNOWN blocks modifying continuation.** A successor may perform read-only recovery/reconciliation while an effect is unknown. It may not repeat the uncertain modification, create replacement work, or perform a second swap. A stale predecessor that later produces text does not regain authority.

## 6. Closed rotation classifier

Closed session-health states:

```text
SESSION_HEALTHY
ROTATION_SUSPECTED
ROTATION_REQUIRED
AUTH_REQUIRED
PROVIDER_TRANSIENT
SURFACE_UNUSABLE
UNKNOWN
```

Closed reasons:

```text
MANUAL_RETIREMENT
CONTEXT_LIMIT_SUSPECTED
REPEATED_TERMINAL_GENERATION_FAILURE
SURFACE_UNUSABLE
UNKNOWN
```

The truth rule is: **Thinking failed != context exhausted**.

A generic error, stalled spinner, missing selector, slow generation, or single failure may support suspicion, transient failure, surface-unusable, or unknown. It does not prove a context ceiling. `ROTATION_REQUIRED` needs explicit manual retirement, supported provider limit evidence, a closed repeated-terminal-failure policy with corroboration, or an exact determination that the bound surface cannot safely continue.

**Never export raw provider error text.** Export only closed states, reasons, booleans, bounded timestamps, and opaque fingerprints. **If exact context exhaustion cannot be proven, preserve suspicion or surface-unusable uncertainty.**

The product need not always know why a conversation stopped. It must know whether the exact bound reasoning surface can continue safely.

```text

<responsibility_ref>
```

**Predecessor title is advisory only.** Prefer a continuation reference plus deterministic instruction over a giant summary. If the successor cannot yet read the canonical reference, a **bounded continuation manifest** may be embedded; its durable copy/reference still belongs in Agent OS.

## 9. Exact succession sequence

### 1. ROTATION REQUEST

Establish `ROTATION_REQUIRED` for the exact current binding, with a closed reason and one stable operation key.

### 2. EFFECT FENCE

Reconcile the predecessor’s modifying action boundary. **EFFECT_UNKNOWN blocks modifying continuation.**

### 3. DURABLE CONTINUATION

Ensure current Agent OS/accepted handoff state can recover the responsibility even when the predecessor is totally dead. Do not require the dying chat to summarize itself.

### 4. EXACT TARGET RESOLUTION

Resolve the current exact profile, account eligibility, Project, predecessor native handle, `session_alias`, `responsibility_ref`, binding id, and generation through existing owners.

### 5. CREATE ONE SUCCESSOR

Create exactly one candidate in the resolved same profile and Project. Prove it is a different exact identity. A lost receipt becomes `EFFECT_UNKNOWN`; **Never blindly create another successor**.

### 6. DELIVER BOOTSTRAP

Deliver exactly one validated bootstrap. A lost receipt becomes `EFFECT_UNKNOWN`; **Never blindly submit the bootstrap twice**.

### 7. VERIFY SURFACE

Prove exact same profile, exact same Project, different conversation identity, responsive surface, and no conflicting candidate.

### 8. SEMANTIC READINESS

A rendered response is browser evidence only: **visible generated text is not PICKUP_ACK or START**. **semantic readiness must reuse an accepted Agent Relay / Company Dialogue / continuation ACK owner**. If that path is absent or unproven, report the dependency and stop before authority transfer.

### 9. RUNTIMEBINDING SUCCESSION

Through the existing canonical writer, preserve the logical target, advance the exact generation, bind the successor provider handle, and fence the predecessor. The transition must be CAS/ABA-safe.

### 10. NAVIGATION UPDATE

Update only the existing navigation projection. If this fails after authority cutover, **authority remains with the successor** and status is `navigation degraded/stale`. **Do not roll authority backward merely to make navigation agree**.

### 11. POST-CUTOVER INSPECT

Use exact Web-Sol inspection to prove the successor is current/healthy and the predecessor generation is stale.

### 12. CONTINUE

The successor performs current `COLD_START`, reconciles any open reciprocal dialogue edge, and continues the same logical responsibility without restarting completed work.

## 10. Effect and retry law

| create response lost after possible creation | unknown | inspect/reconcile exact Project/profile; **Never blindly create another successor** |

There is no “try another tab/account,” newest-chat selection, silent OpenClaw fallback, or sister-Sol failover.

## 11. RuntimeBinding succession invariants

The transition is:

```text
generation N = predecessor
generation N+1 = exact successor
preserve the same session_alias and responsibility_ref
fence predecessor generation N
```

The current persistence/source writer must be discovered; the read-only `RuntimeBinding` dataclass, storeless action-target resolver, and navigation store do not authorize a new writer.

Minimum invariants:

- compare expected binding id, generation N, logical alias, responsibility, reasoning surface, and predecessor provider handle;
- write only generation N+1;
- reject a second N+1, N-1, mismatched profile/Project, changed root responsibility, missing evidence, or multiple candidates;
- make lost writer responses reconcilable from canonical state;
- be **CAS/ABA-safe**;
- ensure **stale predecessor remains non-authoritative even if it later becomes responsive**;
- re-resolve authority immediately before every modifying continuation;
- never let title, navigation, health probe, or model response elect authority.
