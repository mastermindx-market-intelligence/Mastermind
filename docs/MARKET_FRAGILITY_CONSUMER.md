# Descriptive market-fragility context in the Brain

`get_regime` includes an optional `market_fragility` object from Macro's canonical `data/regime/latest.json`. The underlying producer and research plan live in Macro; this repository does not create another gamma engine, risk score, validation gate, data collector or knowledge store.

## Meaning and boundaries

`amplifying` means the upstream **assumed** dealer-gamma sign is short and can amplify moves in either direction. `damping` means the assumed sign is long. Neither is a directional return forecast. `unknown` is the result when the observation is absent, stale or invalid; it is not a zero or a benign market.

The source contract is `market_fragility/v1`, `cboe/gex_SPX`, instrument SPX, position basis assumption. Actual dealer inventory is not observed by this proxy. The adapter validates these facts, the dollar-GEX unit, explicit non-trading authority and the unestablished-validation status. An unsupported source or a boolean claiming new policy authority does not get silently accepted.

Every read recomputes session age using Macro's incumbent `lib.nyse_calendar`. A saved `age_sessions=0` cannot keep yesterday's publication fresh forever. The original computation/session/availability clocks are retained. Missing raw availability is not invented, and an unavailable calendar fails the optional observation closed rather than substituting weekday arithmetic.

History is already computed by Macro on a fixed completed-session grid. The compact consumer retains observed/unknown counts, source window, sign changes, valid adjacent pairs and streak censoring. It never fills gaps or recomputes a different history. Counts are not independent statistical trials.

The optional VIX, VVIX, realized-volatility and macro-liquidity context is separately re-aged. A newer gamma date does not refresh an older VVIX value. A macro liquidity label is not order-book depth. Source inputs shared among these fields are not independent votes. Unsupported depth and spot-scenario sensitivity remain unavailable.

## Existing user path

The in-process Brain MCP server already exposes `get_regime`; there is no new tool registration or authentication requirement. Its description now advertises the descriptive fragility context. Core regime fields continue to work when the optional observation is missing or malformed. The compact observation is a protected qualification field in the existing transport: compaction must not remove its restrictions to make an oversized result look acceptable.

The scope does not change `brain.macro_risk`, `brain.anticipation`, ranking, sizing, execution or any autonomous trading gate. The output carries explicit non-authority. Any future predictive or policy promotion requires a new compatible contract and the incumbent validation/release owner, not a field flip in a JSON file.
