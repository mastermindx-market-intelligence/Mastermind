## 1. Narrow precedence and purpose

This amendment canonizes one operating distinction needed to turn Chat-native Sol plus the existing
Executive/COO fabric into an autonomous organization:

> **Web Sol owns scarce strategic judgment; an explicitly admitted operational principal and the
> deterministic Executive runtime may continue already-authorized delivery without requiring the
> original Web conversation to generate another routine `CONTINUE` turn.**

This amendment has narrow precedence only where older language could be read to require a new Sol
turn for every worker return or to make an exact personal-Web conversation a liveness dependency.
It supplements, rather than replaces:

- `docs/EXECUTIVE_CHAT_NATIVE_SOL_HIERARCHY_LAW.md`;
- `docs/EXECUTIVE_CHAIRMAN_COGNITION_LAW.md`;
- `docs/AGENT_DIALOGUE_SESSION_CLOSE_LAW.md`;
- `docs/EXECUTIVE_WORKER_ROUTING_CHAIRMAN_ADDENDUM.md`;
- Executive OS / Capacity / RuntimeBinding / Wake / Company Dialogue source contracts.

It creates **no** Job/Attempt/Worker lifecycle, authority registry, mission database, queue, scheduler,
retry controller, memory store, transcript store, browser-tab registry, model router or provider
session owner.

Where this amendment is silent, the existing controlling source law remains unchanged.

## 2. Three cooperating loops

Mastermind's operating organization separates three loops:

### Strategic judgment

The current admitted Sol responsibility recovers intent, performs or adjudicates difficult research,
freezes product/system architecture, resolves material cross-program contradictions, decides changes
outside an accepted delivery boundary and performs Sol-reserved acceptance.

Chat-native cognition economics remain controlled by the existing hierarchy law. This amendment does
not make turn-billed Pro reasoning the default and does not select a model by product name alone.

### Operational judgment

A specifically admitted COO/principal may decompose and integrate work, make implementation choices,
commission independent review, consume review evidence and issue bounded repair/continuation/terminal
edges **only for decision classes explicitly within its current grant and plan**.

Fable is not automatically that principal. Worker routing and scarcity law still chooses the
least-scarce capable avenue. A named model, native harness or long-running process grants no authority.

### Deterministic execution and recovery

Existing Executive/Capacity/Dialogue/Wake services hold durable lifecycle, exact identity, resource
claims, plan/revision applicability, result custody, review/repair lineage, effect uncertainty and
recovery. They should advance deterministic already-admitted transitions without keeping any LLM
polling merely to preserve liveness.

`control_plane/executive_coo_cycle.py` already demonstrates this direction by creating and reconciling
planner, review and bounded repair Jobs through existing Runtime commands. Source presence does not
mean the complete installed autonomous journey is production-proven.

## 3. The delivery interval is a projection, not a new canonical object

The phrase **delivery interval** means the currently applicable composition of existing authority and
execution facts. It must not become a second stored mission/lifecycle object.

At an effect boundary, the system derives the current permitted operating envelope from existing
owners, including as applicable:

```text
current explicit Chairman authority / accepted delegation envelope
+ exact Executive root and admitted plan/revision
+ current action-authoritative parent/principal binding
+ current capability/effective grant
+ current source/workspace/repository scope
+ current budget / active-child / depth / repair / review limits
+ exact artifact/result/review revision being acted upon
+ exact carrier/effect state
+ current strategic/production constraints
```

A stale packet, old chat summary, frontend flag, worker claim or model-supplied boolean is never a
replacement for those current facts.

The existing `mastermind.chairman_delegation_envelope.v1` remains the authority projection owner. This
amendment does not create `v2` merely to express operational continuation. Its existing
`allowed_actions`, scope, reversibility, budget, active-child and expiry controls must be re-read by
the owning effect boundary. If future implementation proves that a new field is indispensable, that
schema change requires its own reviewed version rather than an untyped metadata escape hatch.

## 4. Decision classes and authority split

The system must keep these categories distinct.

### 4.1 Deterministic already-admitted transitions

When current policy and exact evidence make the transition mechanical, the existing runtime may act
without waking a reasoning model. Examples include exact eligible dispatch, current-plan review-job
creation, bounded repair-job creation from a valid independent rejecting verdict, retry-safety
reconciliation and accepted aggregation handoff where their existing contracts already permit them.

This amendment does not widen those transitions; it prevents a Web `CONTINUE` turn from being treated
as an additional prerequisite where the existing runtime already owns the decision.

### 4.2 Operational-principal decisions

A current qualified principal may act without a new Sol turn only when the action is explicitly
inside its admitted authority and current evidence is serviceable. Examples can include:

- choose among implementation methods that preserve the frozen outcome/architecture;
- commission or select a required independent review through the existing routing/capacity owner;
- request a bounded repair tied to an exact rejected candidate/review when not already mechanically
  created by the accepted cycle;
- integrate exact accepted child outputs within the frozen architecture;
- park only the affected dependency while independent admitted work continues;
- emit the explicit nonterminal or terminal dialogue edge it is authorized to own.

These are conceptual decision classes. Implementations must reuse the existing action/policy owners or
introduce a reviewed closed vocabulary in those owners. They must not smuggle new authority through
free-form prompt text.

### 4.3 Sol-reserved decisions

Return to the current Sol responsibility when a decision would materially change, waive or adjudicate:

- product thesis or accepted user outcome;
- systems/experience/intelligence architecture;
- material cross-program priority or source-owner conflict;
- acceptance/proof requirements reserved to Sol;
- a strategic route or model/cognition decision outside current delegated policy;
- a new provider/host/tool authority whose admission is not already covered;
- a material budget/depth/active-child expansion rather than spend inside the existing envelope;
- an unresolved question explicitly reserved to Sol by the admitted plan/law.

Web/Sol unavailability makes that decision path blocked or unknown; it does **not** erase urgency and
does **not** grant the COO or Chairman a substitute decision by default. Independent admitted work may
continue.

### 4.4 Chairman-reserved decisions

Constitutional boundaries remain unchanged, including terminal objectives, constitution/charter,
unbounded delegation, major budget expansion, irreversible/unknown-reversibility company changes,
autonomous production-deployment policy, autonomous live-capital authority and other actions reserved
by current law.

## 5. Dialogue rule — action-authoritative parent, not mandatory Sol impersonation

`docs/AGENT_DIALOGUE_SESSION_CLOSE_LAW.md` remains controlling for exact carrier, fresh-read,
watcher and explicit-edge behavior.

For a worker return, exactly one **current action-authoritative parent** owes the next semantic edge.
When Sol owns that decision class, the existing `SOL CONTINUE / RULING / REQUEST_REPAIR / STOP`
semantics remain required.

When a non-Sol operational principal is explicitly authorized for that exact decision class, it must
emit the corresponding edge under its real role/identity; it must **not** impersonate Sol. The edge
must bind the exact current child operation, candidate/result/review revision and lawful carrier, and
must preserve all current freshness/effect/source-writer gates.

A watcher or frontend never acquires the right to originate that edge. A leftover watcher never
creates a successor child. Silence remains nonterminal.

This narrow rule supersedes only the interpretation that every worker `RESULT` necessarily requires a
new Sol model turn even when an accepted deterministic/operational owner already has the exact right
to continue it.

## 6. Web CEO liveness and personal-Web boundary

The durable Sol office and the personal Web conversation are different objects. The organization
must remain able to preserve and advance already-admitted work when the exact Web reasoning surface is
not currently generating.

An exact personal-Web Sol turn is required only when the current decision is actually assigned to
that surface/responsibility and no other authorized decision path exists.

Supported platform tasks/wake/provisioning mechanisms may be qualified as attention or reasoning
entry points, but none is presumed to provide exact model/mode, tool permission, current binding or
write authority before real proof.

Attended Web/host source modification also follows the protected workspace-custody owner: use the
installed `mmx-workspace` route when that host capability is available. A missing/uninstalled launcher
is a serviceability blocker for host-workspace modification, not permission to create an unmanaged
raw worktree or clone. This workspace rule changes no Executive worker workspace or lifecycle owner.

The operating system must not depend on unofficial personal-Web inference automation. Do not use:

- private/undocumented ChatGPT endpoints as the CEO transport;
- transcript/output scraping as the durable company return path;
- cookies/session-token extraction or account sharing;
- newest-tab/title selection as identity;
- automated approval/confirmation clicks;
- artificial human timing, fingerprint/proxy rotation or account rotation to evade restrictions;
- a paid API/Work/Workspace-Agent supervisor silently substituted for the Chat-native Meta-CEO.

A confirmed unavailable/restricted Chat route is a Capacity/serviceability fact. Preserve the pending
strategic obligation and use only a separately accepted alternative route; do not treat a restriction
as a quota bucket to defeat by shifting identities.

## 7. Scarce-cognition economics

Routine status, deterministic review/repair mechanics, worker placement, polling, message relay and
ordinary continuation should not consume scarce frontier reasoning merely because a Web tab exists.

Before a substantial Sol turn, economical qualified workers may prepare source-grounded evidence,
alternatives, disagreements and candidate recommendations. Sol spends its context on strategy,
architecture, cross-system contradiction resolution, hard debugging/adversarial judgment and
acceptance that actually requires Sol.

One high-value Sol turn should establish as much bounded foreseeable operating freedom as current
authority safely allows. This is not a blanket instruction to widen grants. It is a requirement to
avoid unnecessary micro-approval edges that carry no genuine strategic judgment.

The optimization metric is accepted useful outcome per scarce principal effort, not concurrent tab
count, raw tokens or worker count.

## 8. Failure and succession semantics

If the Web principal disappears:

- already-admitted deterministic/operational work may continue inside current grants;
- a Sol-reserved decision becomes a durable pending obligation;
- no worker/principal gains additional authority because Sol is absent;
- no effect-unknown action may be retried or failed over;
- any successor Sol must recover current authoritative state and current binding before acting.

If the operational principal disappears:

- existing Jobs/results/effects remain owned by their canonical stores;
- children do not become parentless merely because a provider process ended;
- recovery must reconcile physical source/workspace/process custody before assigning another writer;
- a logical lease/binding expiry is not proof an old effectful process stopped.

Gateway generation fencing does not revoke unrelated unrestricted GitHub/shell credentials held by an
old reasoning surface. The production execution profile must narrow those effects or state the actual
safety ceiling.

## 9. Live Fabric product contract

Live Fabric remains the presentation/interaction product; this amendment does not move authority into
the UI.

The current conversation-first workspace should project at least:

- the durable CEO office and current reasoning-serviceability state;
- the current accepted delivery boundary and what may finish autonomously;
- real operational principal and actual admitted children;
- exact pending strategic/Chairman decisions;
- accepted-revision dependency waits versus declared supervision;
- delivery, target consumption and ruling as separate facts;
- candidate/review/repair state separate from production acceptance;
- effect uncertainty with original-operation reconciliation, never a blind resend.

The UI may say that work continues without a Web message only when existing source facts prove that
current admitted work has a lawful continuation path. It must not infer autonomous authority from a
conversation title, synthetic prototype edge or model prose.

## 10. Implementation and acceptance order

Canonization does not make the runtime live. The required capability sequence is:

1. **Source-law acceptance:** this amendment plus the associated implementation plan receive exact-head
   review and protection.
2. **CEO-offline delivery canary:** one useful admitted mission advances through work, independent
   review and at least one real repair while no Web Sol turn is running; any reserved strategic
   exception remains durable and blocks only affected work.
3. **Conversation consumer:** the current Live Fabric C0/C1 journey truthfully projects the accepted
   delivery boundary, children, repair and pending strategic obligation from existing owners.
4. **Qualified executive review entry:** one supported native Chat mechanism, if available for the
   intended account/profile, reads a real pending decision and commits one permitted Sol ruling;
   exact model/mode/permission/binding limitations remain explicit.
5. **Scale:** only after the useful loop works, extend the existing plan/policy/capacity/runtime owners
   for deeper principal fan-out, typed accepted-revision dependencies and multi-host recovery.

Required negative journeys include stale result, revoked grant, exhausted repair/budget, unavailable
Sol target, duplicate/late return, `EFFECT_UNKNOWN`, lost operational principal, closed viewers,
changed recipient and restricted cognition carrier.

Completion requires real producer -> canonical owner -> real consumer -> visible/machine effect. A
merged law, green CI, queued Job, delivery receipt or Figma prototype alone is not acceptance.
