## 1. Architectural decision

Compose three existing graphs through explicit, source-bound identities:

| Graph | Authoritative facts | Existing owner |
| --- | --- | --- |
| Business organization | Company, reporting relationships, goals, projects, issues, assignees | Paperclip for its native company records |
| Project knowledge | Workstreams, decisions, discoveries, dated continuity; versioned purpose, requirements and task dependencies | Macro Agent OS and owning GitHub source plans |
| Execution | Admitted plans, original root, immediate coordinator, Jobs, Attempts, Workers, scope, budgets, effects, sealed results and joins | Executive OS Runtime, Capacity placement and native execution owners |

A Paperclip issue parent is containment. A source-plan dependency is authored planning information. An Executive dependency controls readiness only after admission. A reporting edge does not create execution authority. Native T3 thread ancestry remains native ancestry; an Executive parent must be retained separately and verified.

Mastermind OS presents these graphs together. Teamlink carries authenticated context, dialogue and returns through the existing transport owners. It does not become a fourth admission system. No second task store, scheduler, queue, registry, retry ledger, memory engine or watcher is introduced.

The principal retains mission acceptance, product direction, cross-project tradeoffs, and the critical path. Accountable suborchestrators receive complete bounded outcomes and own their local integration. Leaves receive exact inputs, scope, proof and return contracts. A suborchestrator creates descendants only through the actually admitted hierarchy; a role title or skill is not that grant.

## 4. Discovery and useful context

A project should answer four questions from existing owners: what outcome is owed, what is ready, who is related to this work, and which help avenue is actually addressable.

The company implementation uses `integrations/paperclip_control/connections.py` and `agent_context.py`, the existing current-company service, and the same SecretaryAccessClient. The frontend recomputes the graph from validated records and rejects a disagreeing optional server projection. It does not trust an attractive graph supplied independently of its records.

Hermes LeadershipReader can opt into bounded company context without creating a native tool or a new credential. The company portion is at most 8 KiB and the full brief at most 24 KiB, with bounded people/project work. Source and currentness are checked around the await. A permission refusal discards prior Mission facts; a non-permission company failure retains only fresh Mission context. The legacy default remains unchanged until the actual host opts in.

The existing long-horizon context preserves every source requirement/task identity, full focused acceptance, dependencies, blockers, original delegate references, and the next useful action. It distinguishes a side question from a revision. It retains source references when the entire plan does not fit; it does not silently redefine the mission as the visible frontier.

Available help is not inferred from a company roster. An avenue needs its real authenticated target projection or current placement eligibility. The observed session_targets projection was empty and Executive state reported backend_unavailable at its observation time. That proves neither zero estate work nor permanent global unavailability.

## 5. Delegation through admitted hierarchy

Use the incumbent Executive CooCycle:

1. Bind the current project/source-plan revision and original acceptance to a real admitted root.
2. Allocate a coordinator only when aggregation is required. Its planner child receives the actual planner Attempt.
3. Materialize the planner through the claim-aware factory with the retained producer binding, including original root, immediate coordinator, planner Job, schema and execution binding.
4. Admit only the exact sealed original planner result through `admit_cycle_plan`.
5. Attenuate depth, descendant and scope/budget grants. Charge every created descendant to all ancestors, including terminal children.
6. Let existing dependency/readiness and recovery owners progress the graph. Join compact child evidence locally; escalate only the unresolved decision.

This frees the principal from leaf execution without making hierarchy unlimited. Plans should choose economically useful fan-out within actual capacity. Additional management layers need an integration outcome; a hierarchy drawn only to occupy workers adds overhead.

Remote producer custody is implemented in the existing validate/start/materialization-status chain. Its source patch passed 350 unique focused cases; the composed tree passed 534 cases including the source-identity guards. Legacy omission retains the v1 wire shape. Explicit producer selection requires a closed, digest-covered receipt based on actual initialized native evidence; a proxy attribute is insufficient. Lost initialization is reconciled on the original operation, without a second initialization or useful turn.

The current Claude planner profile is disabled. This work does not enable it. Enabled Codex profiles need turn-scoped schema custody because Codex accepts outputSchema on turn/start but does not attest to a planner schema at startup. The existing TX-5 intent, acknowledgement and result-seal owners are the appropriate composition; source feasibility is not installed admission.

## 6. Completion, returns and recovery

Teamlink now compares the complete immutable semantic envelope, including all original correlation fields, destination, ordered context, reply and deadline. Default-clock expiry is enforced. A copied message ID cannot make a changed operation equal. Delivery state and hop observations do not become authorization.

The native return owner reserves the frozen original return in the existing RuntimeStore at the native prewrite boundary, before a frame can be sent. It retains the exact request, native binding and input digest. Concurrent or resumed callers read the original operation. An immutable unknown receipt may receive one validated delivered reconciliation event; unchanged unknown reads append nothing.

The real supervisor now awaits that owner after terminal seal and durable readback. A synchronous hook inside an active event loop sends nothing, schedules nothing and persists no false refusal. This is not a detached background continuation.

Production installation needs a valid current original target. The currently enrolled Secretary/Meta session source is not an arbitrary Paperclip teammate directory. Caller-provided teammate, project or conversation strings cannot authorize that join. A safe authenticated result read can expose original return state without sending or claiming parent consumption; the installer must remain fenced until the authoritative binding exists.

T3 already has a production wrapper for provider-only process identity, native presence and reattachment. Those are reused. Remaining work concerns bounded exact-run waiting, complete text, explicit existing-worktree selection, native terminal evidence and actual artifact/validation authority. Never synthesize PID, shell exit code, successful validation or a missing result envelope from thread completion. Native output truncation must remain an incomplete result until the original native item is fully recovered.

Recovery must retain one original operation, owner and target. A new chat, reconnect or coordinator restart does not erase an unknown write, create a new root, reset budgets or replay a refused effect.
