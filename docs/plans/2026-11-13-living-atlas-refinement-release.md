## What changed

### Creature and world

The rig now has a coherent body frame, continuous bank/crouch/landing and world-planted staggered feet. Stable probe anchors survive detail changes and retained-contact transitions. Dotted strands reveal and retract at constant spacing, with a moving current along each strand. Sparse contacts can remain in the prior region as the new fan develops. Travel history remains one separate fading route.

Irregular volumetric project fields include local contact illumination. The selected creature receives the richest detail while other leaders and helpers remain independent. The camera frames body and active work together, responds to travel and work bearing, varies elevation, keeps restrained roll, and preserves manual zoom.

Immersive mode gives the world the stage while retaining source qualification, work caption, follow and Off. Resource buttons now avoid the selected body and use fine leaders when displaced. They open exact supplied context rather than inferring activity from labels.

### Operational instruments

The expanded Capacity Fabric separates Traffic, Allowances, Routing detail and Processes:

- Traffic shows response pathways, active requests and reported usage coverage. Particles express activity, not one particle per real token.
- Allowances retain each owner-qualified scope and window. Unknown remains unknown; zero exhaustion remains zero. Configured concurrency is a separate measurement.
- Routing details project optional owner overflow, local seat estimates, peak-window records and gateway accounts without treating them as provider quotas.
- Processes remain separate observations with original targets. A request identity does not become a native agent.

The panel is scrollable with an accessible Off control. Layout responds to the component's width, including the 390 × 844 phone fixture.

## Drop-in adoption

The release includes `living-atlas-sdk.zip` (234,967 bytes) and `living-atlas-source.zip` (183,987 bytes). Hashes are recorded in the adjacent JSON receipt. Both archives include runnable adoption examples; the SDK includes declarations, the embedded stylesheet, original procedural assets, bundled chunks, React entry and validation report.

For a vanilla host, copy the complete SDK `assets/` directory into the host and import `mountMastermindAtlas` from its `sdk.js`. Preserve relative chunk paths. Give the mount a concrete height and pass the incumbent context/navigation ports.

For React, extract the SDK into a versioned host vendor directory, install/reference that local package with the host's existing package manager, and import:

```tsx
import {MastermindAtlas} from 'mastermind-living-atlas/react';

<MastermindAtlas
  context={projectionContext}
  observations={existingOwnerObservations}
  observationContext={contextCapturedAtAcquisition}
  host={missionHost}
  onNavigate={existingHQNavigation}
/>
```

The wrapper uses the host's React. Default power is Off with an internal viewer toggle. For controlled power, supply both `enabled` and `onEnabledChange`; internal buttons request the change. Committed props are forwarded only after React commits, so a suspended speculative project switch cannot invalidate the visible owner's data.

## Performance qualification

A matched selected-CEO scenario in the managed Canvas renderer reduced median scene work from 18.4 to 11.0 ms and median full JavaScript frame work from 22.9 to 15.0 ms. The p95 values were 24.6 → 15.9 ms and 32.5 → 23.6 ms respectively.

These were 12-second time-sampled measurements at 1363 × 936; camera composition also changed. They measure the combined refinement rather than an isolated rendering optimization. Repeated samples may refer to the same delivered frame.

The browser still delivered animation callbacks at about 600 ms intervals and reported WebGL disabled. **No 60 fps or proven video-game smoothness claim is made.** GPU/device proof remains necessary. Graphics execute on the viewing device; no server-side animation process was installed.

The normal build has 813,798 bytes across all JavaScript entries, approximately 216,896 bytes under per-file gzip estimation; stylesheet size is 49,169 bytes before compression. The standalone entry does not load React and has no runtime font/CDN fetch. These are artifact sizes, not measured production network transfer.
