# Native Hermes adoption of Agent OS context

## Status and purpose

This source composition connects the existing authenticated Agent OS read to
Hermes's actual memory loader and turn lifecycle. It is inactive until the
incumbent installation, enrollment, OAuth connection and mission grant owners
supply a compatible publication. Source tests do not prove an installed
activation, provider dispatch, model identity, memory efficacy or an accepted
always-on teammate.

Agent OS remains the durable continuity owner. Executive OS remains the
admission and runtime owner. Hermes supplies the native agent, MemoryManager,
turn hooks and prompt composition. This adds no memory database, principal,
credential store, daemon, scheduler, queue, retry service or publication owner.

Dependencies are the adopted receiver, authenticated COO context transport and
original native request-observation scope. The context transport's dedicated
profile remains disabled by default. Existing grants are not broadened. The v2
publication also requires the fixed `diagnostic_privacy` vendor derivation and
its verified six-field receipt through the original held release owner. Runtime
file hashes alone do not qualify the vendor transformation. See
[NATIVE_VENDOR_DERIVATION.md](NATIVE_VENDOR_DERIVATION.md).

## One enrolled consumer

`mastermind.hermes_native_executive_consumer/v1` retains its closed selected-child
contract. The optional v2 schema has two independent capabilities:

| Member | Meaning |
|---|---|
| `context` | Fixed provider `agentos`, fixed `ADOPTED_SNAPSHOT` source mode, a bounded byte ceiling and freshness duration. It accepts no local owner path or model-selected workspace. |
| `selected_child` | Explicit null, or one complete existing command/job/target/root tuple. Null constructs no delegate startup, performs no fabricated child qualification and registers no `mmx_delegate`. |
| `permission_digest` | The existing principal-binding owner's permission receipt digest. All original fields are included in that owner's digest; the consumer does not reconstruct a partial identity or mint a principal. |
| `tools_schema_digest` | The fixed eight-tool context descriptor. It is distinct from the legacy seven-tool descriptor. |
| Existing principal, mission, MCP, plugin and session members | Supplied by the incumbent owners and joined to the held publication, captured connection and original enrolled session. |

This v2 slice serves the publication's one enrolled session in a dedicated role
home. It is not a multiplex or arbitrary multi-session memory grant. A different
mission or enrollment requires a new qualified publication through the same
owners. Neither a query nor a model argument can retarget it.

The generated v2 native configuration selects `memory.provider: agentos` and
sets both `memory_enabled: false` and `user_profile_enabled: false`. Hermes
therefore does not also load independent `MEMORY.md` or `USER.md` stores. V1
configuration stays unchanged. The model-facing raw Executive MCP tool filter
stays empty; this internal read does not expose a generic authority API.

## Native lifecycle

1. The existing held release entry loads the consumer package through its
   first-party source importer. The exact general PluginManager import seam
   uses that same module while preserving the native discovery lock, profile
   scope, context, ledger, load deadline and isolation decision. Its policy
   lease names the actual held module. Host-mode import and foreign predeclared
   modules refuse; the package is never relabelled as bundled.
2. Qualification retains the factory in the original `ConsumerSlot` and captures
   the existing MCP server, SDK session, owner loop and their currentness guards.
   A context-only publication can register the factory without any child Job.
3. The original native request-observation scope names the actual admission,
   execution generation, authority epoch and process instance. A transient
   delivery record is attached to that scope. It is not an admission owner.
4. The original turn resolver invokes actual `_init_memory`, memory discovery,
   `_ProviderCollector` and `MemoryManager`. Provider registration is admitted
   only inside that exact loader call, from the held module and its original
   hook-source identity. The original manager owns the provider instance.
5. The original callback wiring adopts the agent into `SessionAuthority`.
   Cold initialization alone cannot deliver context. Cached-agent reuse rebinds
   the same provider to the new admission, invalidating the old provider epoch.
6. At `_memory_turn_start_and_prefetch`, after native recovery/compaction can
   rotate the physical session, the factory checks the original generation,
   prepares one read and waits up to 31 seconds outside the authority lock and
   the MCP owner loop. The provider's original pending state owns the acquisition.
7. The original MemoryManager prefetch and prompt builder remain in use. Before
   and after each bound main-agent `build_api_messages`, the composition checks
   the original attachment, binding, current READY snapshot and native stored
   generation. Expiry, rotation or replacement refuses that claim. It does not
   refresh or retry the claim silently.
8. An agent that has been bound to this factory cannot bypass the checks by
   losing its ContextVar or manager. Truly unrelated helper agents keep their
   original prompt-helper behavior.

## Original RPC and timeout custody

The remote provider calls only `executive_agentos_context(work_ref=...)` on the
captured native connection. The fixed 4,000-token receiver budget and original
128 KiB raw / 16 KiB receipt limits remain in force. The actual MCP SDK result
must have the single text envelope emitted by the reviewed server. Extra SDK
fields, alternative content forms, nonfinite numbers, scope drift and malformed
receipts refuse. No local compiler fallback, alternate connection or account is
attempted.

The native synchronous RPC observer has a 30-second bound. Its timeout leaves
the SDK future owned by the original connection. Context reads opt out of waiting
behind an occupied original RPC lock. On the owner loop they inspect the actual
supported `asyncio.Lock`, its waiter deque and the incumbent in-flight set before
acquisition. A still-running original call therefore cannot accumulate new
context exchanges behind it. Legacy selected-child callers retain their prior
lock-waiting behavior. No new pending registry is introduced.

A turn-barrier timeout leaves the original provider acquisition pending and
marks that claim unable to deliver. A late completion cannot revive it. Native
prefetch workers also capture their entry claim, binding and epoch; an old worker
resuming after cached-agent rebinding cannot discover or credit the new claim.

## What the evidence means

The private `consumer_capabilities` read uses the existing same-UID control
surface and owner loop. It is not a role HTTP dispatch verb. It invokes no
prepare/prefetch and checks the original enrollment before and after observing.
The readback freezes the instance, claim, binding and epoch, then rechecks them
before exposing active fields; it cannot combine one admission's identity with
another admission's snapshot.

| Observation | What is proved |
|---|---|
| Factory registered | The original qualified slot and native loader retain the context factory. |
| Provider installed | The active adopted agent's actual MemoryManager contains the original provider. |
| READY snapshot | The scoped transient snapshot is current and within its freshness bound. |
| Provider return | The original provider returned the digest-matched rendered context. |
| Prompt observed | The native manager returned the same bytes and the actual current user row at `build_api_messages` contains the exact fenced context block. |
| Historical last delivery | A prior observation in this process; it does not assert an active claim or current snapshot. |

The upstream native lifecycle deliberately skips semantic recall on trivial
prompts and can time out, gate or spill prefetch output. A READY snapshot therefore
does not imply prompt inclusion. A spill reference is not credited as full
context delivery. Historical `api_content` is not borrowed as evidence of current
injection. The current-turn suffix is joined after native historical-prefix
canonicalization, and the system prefix is accounted for.

The supervisor reports factory registration, active attachment, readiness,
delivery observation and prompt observation separately. It joins the held
publication, original enrolled instance and actual child. Invalid or replaced
observations clear its conclusion; a stopped/replaced child cannot retain a
current capability claim. `native_extension_proved` stays delegation-specific.
Provider authentication, actual provider dispatch and model identity remain
unproved by this metadata.

## Validation and reuse

The root protected test module `tests/test_hermes_native_agentos_memory.py`
imports the integration's actual-source lifecycle and SDK contract cases into
the existing CI collection and shards. It creates no alternate workflow.

Fixtures include complete MIT-licensed source files based on
`NousResearch/hermes-agent@1c0cd667746d3395fe9e1b6c74f8f85952486f18`.
`agent_init.py` and `memory_caller_scope.py` are the exact diagnostic-privacy
postimages pinned by the runtime. Their provenance retains original upstream
URL, Git blob, SHA-256 and size separately from derived identities and the fixed
patch. Other fixtures remain upstream-identical. The MIT notice is retained.
The tests execute the pinned selected ASTs or complete modules; the D8 source
audit and its injected-identity negative remain intact. Model/provider services, config and selected native edges
are explicitly controlled; this is component proof, not installed-host proof.

Coverage includes cold registration/adoption, cached reuse, physical rotation,
actual compiler-to-SDK-to-provider bytes, closed publication/receipt shapes,
identity and generation drift, publication replacement, disabled/isolation
policy, held general imports, source origin, late timeout ownership, unlocked
lock waiters, old-prefetch return, lost scope, current-row evidence, native
prefix removal/spill/trivial behavior, readback races and supervisor stages.

Steering cases compile two distinct authored Git revisions through the existing
collector/compiler and authenticated context provider, then deliver their exact
SDK bytes through cached-agent and fresh-agent native turns. Pause retains a
typed wait, cancel retains the named wave as `dropped`, reprioritize changes the
current next action, and resume removes only the resolved wait. The current
prompt retains the original objective, wave frontier and authored unresolved
effect warning. Principal, mission and profile scope stay fixed even when urgent
prompt text asks for broader hosts. These are prompt-continuity component proofs,
not evidence of model compliance, process restart, runtime cancellation or effect
settlement. Runtime ownership, outstanding effects and parent custody remain
`UNOBSERVED` in the provider envelope.

## Installed acceptance still owed

The next runtime slice must use the original authorized host connection and the
incumbent installer/enrollment owners. It must preserve any permission refusal
and original uncertain effect, rather than retry through another carrier.
The concrete acceptance requires:

- A new exact-source installation publication, real plugin digest and qualified
  native interpreter/vendor closure, including this optional v2 document and
  the original owner's verified diagnostic-privacy derivation receipt.
- The receiving owner's real context profile/grant, authenticated principal
  binding and original OAuth connection; a current selected mission and its
  permission receipt. This source change supplies none of those credentials.
- Private readback from that exact serving process, then one nontrivial native
  admission whose observed context and prompt digests join the original receipt.
- Original request/terminal evidence for the same admission. Prompt assembly
  must remain distinct from actual provider dispatch and verified model identity.
- Restart/revocation behavior and held-out task outcomes through the existing
  EVAL owner. Synthetic component cases cannot satisfy those acceptance gates.

Fleet rollout, vault/account enrollment, browser/computer-use activation,
full tool grants and endurance acceptance remain separate items in the canonical
Hermes teammate implementation plan. This memory slice does not close them.
