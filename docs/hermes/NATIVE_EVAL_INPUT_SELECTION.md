# Frozen inputs on the original native Hermes admission

Status: source implementation and component qualification. This selection is not
an installed fleet grant, complete EVAL producer, efficacy result or promotion.
The incumbent complete-producer contract remains
`docs/hermes/NATIVE_EVAL_PRODUCER_CONTRACT.md`.

## What this slice owns

The optional receiver resolves an existing immutable EVAL scenario, configuration
and optional experiment from the existing ArtifactStore. It binds the input text,
instruction-file bytes, context packet, comparison arm, replicate and explicit seed
to one original native finite admission. It does not create a runner, queue, memory
database, credential owner, retry loop, provider client or artifact-store root.

The held release explicitly selects `evaluation_inputs` with schema
`mastermind.hermes_native_eval_inputs/v1` and an absolute `artifact_root`. The
existing directory must be canonical, owned by the role, mode `0700`, and separate
from the vendor/import/inventory/pristine-source paths. The exact cumulative
`native_eval_inputs` vendor derivation is mandatory; its manifest is the source of
the patch and eleven postimage hashes. Nine prior Workspace OAuth/privacy
postimages are unchanged. Only the original native authority and retirement owner
receive additional changes.

This version selects **mmmeta with the existing `zai.glm-5.3` provider choice**,
consumer publication v3 or v4, and native gateway installation v3. The recipe
validator rejects Secretary selection before installation. The exact config
renderer uses Hermes's own `model.streaming: false`; unselected renderer bytes
remain unchanged. Existing credential, network and capability restrictions still
apply. The receiver grants none of them.

The incumbent Squid source now permits the Meta role's own Executive/Agent OS
edge and Office issuer, alongside its original Z.ai endpoint. Separate role
ACLs, hostname-only CONNECT on port 443, denied address ranges and the original
two listening sockets remain. Installation and same-cgroup allow/deny proof are
still required; configuration bytes do not prove effective network isolation.

## Artifact and admission bindings

The caller supplies IDs/digests, never a replacement scenario or configuration.
The receiver verifies the complete immutable artifact graph and exact selector
joins. Experimental trials must match the selected scenario reference and arm's
configuration digest, the original finalizer's pairing rule and replicate bound.
Standalone trials require null comparison fields.

The first slice requires an honestly authored warm-session scenario:
`fresh_process_required`, `fresh_workspace_required`, and
`fresh_session_required` are false, with `resume_allowed: true`. A frozen scenario
requiring freshness is refused. It is never rewritten to fit the runtime.

Scenario retention must be `PUBLIC_SAFE` / `DURABLE_SANITIZED`. Input and context
must match the source allowlist and model-visible references; known hidden or
denied references cannot be injected. Supplied text, context and instruction bytes
pass the existing reject-only privacy check. An instruction bundle is the explicit
variable procedure, not an additional retrieved-data source. Its existing Harness2
file-manifest digest must match the immutable configuration.

The run ID is an ordinary canonical UUID4 `run:` ID. The original submission ID is
`submission_id_for_run(run_id)`, yielding `mastermind-eval:<uuid>`. No alternate ID
scheme or reservation registry is introduced. The private control operation uses
`NativeSecretaryClient.submit(..., evaluation=specification)` on the same existing
role-specific control carrier. It remains one original request; a timeout is an
uncertain effect, not permission to resend elsewhere.

`_PrivateSelection` holds detached canonical bytes and the actual selected owner.
The explicit native derivation accepts that nominal private object, preserves
original actor authorization, and inserts its marker before the original payload
fingerprint. Public Submission payloads cannot inject the marker. The original
mutation lock, captured-media lease, tracked writer, admission gate, FIFO and
restart behavior remain the owners.

Every private marker composes its run-identity check inside the original native
admission transaction, including calls without an optional Control callback. Exact
live/terminal replay returns the original receipt before that new-write guard.
Otherwise any original live or terminal record for that run request refuses a new
admission ID, across principals and enrolled sessions in the same native profile.

The selected retirement owner preserves the original EVAL admission and identity
tombstones past the ordinary retry horizon. It does not preserve model output on
the strength of an input label: the original result expires normally. Missing
result evidence stays unavailable; the run cannot be repeated to recreate it.
This guarantee depends on intact original profile storage and the qualified
maintenance source. Erasing/restoring that database is the existing disaster
recovery boundary, not an inferred empty-run state.

The terminal retirement transition first retains the original closed, safe EVAL
payload. A malformed or unknown marker retains only a sentinel and the original
identity/digest, so its content cannot be published and its request cannot be
re-admitted. Ordinary input/history is still cleared. Tests exercise actual
retirement, transcript compaction, expiry, and refusal of a second admission.

Incomplete observation accounting uses the existing evaluator's explicit
[run/draft v2 contract](../HERMES_NATIVE_EVAL_RUN_V2.md). This is separate from
producer qualification: an input marker alone cannot establish observed
execution or a complete, technically valid run.

## Actual execution path

The existing observation binding recognizes a marked row before its optional
observer fallback. Missing receiver, stale enrollment, changed artifacts or a
published run refuse execution. Restoration uses the original marker and same
admission/generation; it cannot turn into an ordinary unbound chat.

The existing Agent OS wrappers apply the selected instruction/context rendering
to `combined_ephemeral` **before** Hermes computes its agent cache signature.
The native resolver and callback-wiring arguments both receive the same manual
reasoning config and explicit seed, including zero. The receiver does not change
persistent session preferences or enable adaptive effort. A competing active
adaptive-effort plugin is refused by this manual slice.

Pinned Hermes resolves our named `zai-glm` entry as `provider="custom"`, retaining
`requested_provider="zai-glm"`. Evidence preserves those actual identities. The
held provider specification fixes the model, API mode and endpoint; the existing
direct-Z.ai capability helper supplies the eligible manual levels. The current
v1 EVAL intersection is `low` and `high`.

Checks run at native prompt delivery, after request hooks, and at the incumbent
nonstream dispatch boundary after execution middleware. They require the actual
selected instructions, model, seed, effort and nonstream mode. Final `extra_body`
cannot shadow those execution fields. Before dispatch the existing Agent OS
attachment/snapshot and durable native generation checks execute outside optional
observation failure handling. Native request/HTTPX observers continue to own
assembly and serialized-request evidence; no extra request/client is made.

## Evidence and its limits

The original scope retains a separate versioned `mastermind_eval_inputs`
contribution in the original outer pending result. Deliveries join the same Agent
OS prompt receipt; assemblies join the original request event identity and digest.
Records share the existing 16 KiB metadata budget and original locks, and stop at
the original sealing boundary. Bounds or missing observations remain explicit.

Historical readback checks the saved input marker, receipt, historical producer
instance and sibling request-observation events. Today's process or enrollment
cannot substitute for the producer. Invalid EVAL evidence closes that projection
while preserving the native answer and ordinary terminal metadata.

`complete_evaluation`, provider-delivery proof and served-model identity remain
false. This contribution does not invent observed sandbox/network policy,
whole-trial effect coverage, cleanup, fresh process/workspace/session, or a valid
EVAL run. The existing finalizer still needs those actual owner contributions.
Candidate efficacy and promotion require held-out results and the existing
acceptance/rollback owners. Source/config installation alone does not provision
the store, enroll a session, activate tools, or establish any live fleet journey.

## Qualification and recovery

Component tests execute pinned native resolver, authority, admission transaction,
retirement, Agent OS lifecycle, request hooks and dispatch bodies with declared
host/service edges. The SDK test uses actual OpenAI/HTTPX and in-process HTTP; it
makes no provider/account call. The derivation qualifier applies exact patches in
a disposable tree and refuses changed or already-patched donor bytes.

The selected release closure contains the incumbent EVAL modules and the complete
existing OMH helper import closure. Rollback retains the existing full native
recipe/derivation/launcher/profile comparison. No EVAL-specific rollback receipt
or alternate maintenance path is introduced. Installed acceptance must prove the
same source-qualified maintenance owner, original enrollment, original carrier,
actual constraints and source receipt before trial execution or efficacy claims.
