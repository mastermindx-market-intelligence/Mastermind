# Current canonical Agent OS context

## Outcome and boundary

The installed COO context reader can compile the selected workstream from the
current canonical Macro DATA commit while retaining the installed executable
CODE commit. This is an explicit additional capability. The adopted-snapshot
wire, catalogue and native publication remain unchanged.

This source slice supplies the actual collector, isolated compiler, original
Control carrier, independently authenticated App and MCP path. It does not yet
select the native companion OAuth carrier or a current-context native
publication. The profile defaults to disabled. No enrollment, installation,
model dispatch, account login, fleet activation or live acceptance is claimed.

## Independent resource authentication

The HTTP call uses the ordinary Executive Authorization header and exactly one
`x-mastermind-workspace-authorization` companion header. Both carry actual
resource-specific credentials. The App independently verifies both resources;
it never copies the COO principal and relabels it as Workspace.

Issuer digest, subject digest and client reference must agree. Different
resources, scopes, policies and token identifiers retain their own meanings.
Two enrolled clients for the same person do not satisfy this join. The request
also needs the current COO mission/action/catalogue and the separate Workspace
READ and latest-project-DATA grants.

The original audited Workspace owner now exposes a bounded verification method
returning an actual VerifiedPrincipal and its non-null permission stamp. It
checks the audited access projection against the independently verified token,
rechecks the clock after awaits, and pins its original config, authenticator,
authorizer, policy and stamp callback. The COO owner retains equivalent original
owner checks and its own enrolled binding stamp.

Both resources and permission stamps are rechecked before and after acquisition.
A final synchronous check follows the last asynchronous verification, including
at the outer MCP boundary. Late revocation or expiry withholds the bytes without
recompilation. Only neutral verified projections cross the private Control
carrier. The two bearer values do not enter its frame, result or audit text.

The gateway serves the exact installed Workspace policy's protected-resource
metadata at that policy's own metadata path, and the original Workspace audit
gate advertises it in its challenge. It does not advertise Executive metadata
as Workspace metadata. The existing authenticated
`GET /workspace/native-draft-identity/current` remains a bounded identity read;
it does not itself authorize current project DATA.

## CODE C and DATA N

The actual executable compiler and sibling helper come from installed CODE C.
The isolated child executes the captured C bytes with the logical DATA N
location needed by the unmodified compiler's record, artifact and Git reads.
The helper at N must match C exactly. Both fixed context configuration inputs
must also match their qualified C identities.

The shared materialization selection preserves all selected Agent OS records,
citation/supersession discovery, fixed context configuration, active-build
input, artifact and owns-path probes, and actual Git history. It retains the
separately qualified Mastermind P0 source. Artifact files are data; they are not
added to Python's import path or executed. Regular Git modes 100644 and 100755
retain their execute parity as private 0600/0700 files. Symlink, submodule and
unsupported-object refusals remain.

The independent N Git database crosses the same ancestry-commit and historical
record-tree proof as the original configured checkout. A current tree with
missing historical trees is insufficient: the upstream compiler can otherwise
turn a failed per-path Git date read into an unknown date. The same original
deadline and Git environment govern this proof. Before/after seals still cover
the materialized database and worktree.

This version accepts only C=N or a current, original, same-Workspace-principal
canonical publication Event. It explicitly refuses `data_continuity`. The
existing unchanged-Knowledge proof does not establish equivalence of full
context inputs or Git-derived dates. Identical current file blobs alone are
also insufficient.

The explicit workstream compiler does not use the context-index search database.
It does read `config/context_index.yml` for artifact authority and
`config/compiled_kill_registry.yml` for higher-law values. The emitted
`research/DO_NOT_REBUILD.md` locator does not mean its prose was read; existence
is observed when an artifact/owns-path declaration selects it.

## Receipt and delivery

The new private frame and result use
`mastermind.ceo_ingress.coo_agentos_current_context.v1` and
`mastermind.coo_agentos_current_context_result.v1`. The result retains the exact
original compiler bytes as base64 and echoes the independently verified
Workspace projection.

`mastermind.agentos_current_context_receipt.v1` identifies
`CANONICAL_PROJECT_DATA`, installed compiler CODE C, DATA/repository N, the
nominal canonical DATA observation and its original Event, compiler/helper
identities, input selection, source/runtime seals and original byte digest.
The adopted v1 validator refuses this new receipt; the current validator
refuses adopted-mode or incompatible coordinates. The byte ceiling, token
budget, explicit degradation and omitted-items checks are retained.

## Remaining product path

The next native step is one complete, fixed derivation of the existing Hermes
OAuth manager and HTTP transport, retaining the accepted diagnostic-privacy
postimages. It must authorize a second resource in the original profile store,
exercise a real protected Workspace GET through the original HTTP client,
attach only that authenticated bearer to the exact COO destination, and retain
original refresh, redirect, cancellation, parking and interactive-login owners.
A static header or a synthetic OAuth response is not sufficient.

Canonical note and correction publication must then use the existing Project
Knowledge source owner, recipe adapter, fixed Git publisher and original source
Events. Fresh native delivery must consume that Event-backed context. The
original C26 installed-host boundary remains unretried; no alternate host,
account or carrier supplies acceptance for it.
