## Important native client traps already investigated

OpenCode's SDK retry setting alone is insufficient. At upstream `anomalyco/opencode@228e9095ba3988a02664c3816cb51f98584e86c2`, `packages/opencode/src/session/processor.ts` wraps its stream in `Effect.retry(SessionRetry.policy(...))`; `session/retry.ts` defines five outer retries and recognizes network/5xx/rate-limit failures. Disabling low-level SDK retries does not disable that independent session behavior.

The new endpoint therefore permanently stops forwarding after the FIRST admitted failure and notifies the existing supervisor. Five repeated HTTP requests after a synthetic unknown provider effect produce ZERO additional upstream calls in the tested instance. This is a transient fail-stop condition, not a new retry ledger or Job state. The supervisor must durably consume the failure and stop/reconcile the native harness. Callback failure remains observable via `failure_notification_failed`; it never reopens forwarding. Do not create a new endpoint automatically on error, because that would bypass the protection. Only existing canonical reconciliation can authorize a new operation/continuation.

A successful terminal wire event is not coding-task acceptance. A socket close is not provider cancellation. Partial-stream failure, missing terminal event, wrong receipt identity, sink failure and uncertain thread/pipe cleanup cannot be reported as success. Reentrant close from the request callback reports cleanup uncertainty; the actual outer supervisor performs cleanup. Blocking DNS, provider I/O or a blocked callback still requires the existing outer worker-process bound.

OpenCode custom configuration is MERGED with remote/global/project/.opencode/inline/managed settings, not an isolation boundary. `OPENCODE_CONFIG` alone does not disable inherited providers, plugins, tools or project behavior. The native adapter must seal its effective environment/config and verify it before loading the actual Go key. The documented CLI supports foreground `run`, JSON event output, explicit model/directory and session continuation; pin and qualify the installed binary's actual version/schema. Do not invent an undocumented disable-retry flag or use a permanently running `opencode serve` as a second workforce service.

## Data, time, correction and statistical boundaries

All account/model/session/enrollment/offer revisions stay separate. A price or new-model list does not rewrite pool membership. Three API keys do not establish independent purchased entitlements. The global models list is not account access and its `created` field is not release time.

Token quotes use disjoint uncached input, cache reads, cache writes and billable output/recognition of reasoning from the existing normalizer. They are estimates, not exact future token counts or cash authorization. Provider-reported rolling/weekly/monthly usage remains current truth. Do not rescale old observations after a price/promotion change, infer infinite capacity from null, or infer absolute balances from percentages.

TimeBoundRate uses explicit half-open UTC effective intervals and UTC weekly-minute intervals; context bounds are explicit integers from the reviewed owner. A quote expires at the earliest review expiry, effective-rate end or next time-band boundary. Cache categories with unknown prices refuse nonzero use. Gaps or overlaps refuse; there is no cheap-default branch. Promotion cutover timezones and retention validity must be owner-resolved, not guessed from 'Ends Sep 20'. A refreshed page does not renew an expired approval. Fresh future requests are re-quoted; an in-flight request is never rewritten/replayed because prices moved.

`quote_temporal_offer` reuses the original `ProviderModelCatalog.estimate_api_cash_usd` once. `require_current_quote` binds body, model, surface, offer, amount and expiry. Digests provide integrity only, not authorization. Source changes are proposal inputs to existing owners; an LLM summary or a discovered model may not authorize itself, choose the worker, add a provider account or widen private-data permissions.

A routine request should obtain a fresh quote before transport. If evidence expires during key loading, the second check stops BEFORE POST. The initial endpoint conservatively fail-stops that instance; automatic recovery/continuation belongs to the existing broker/owner and is NOT claimed implemented here. New models require compatibility/privacy/quality qualification; existing models can continue through unrelated inventory-only additions. Schema/fetch failure may retain a last accepted snapshot only until its original expiry, never refresh its age.
