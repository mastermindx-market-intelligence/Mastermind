# Native T3 requester provenance: exact API boundary

## Decision

The real COO API-principal avenue can proceed independently: the existing authenticated principal, installed mission/profile, selected-child target, Runtime claim, WorkerBroker workspace/result owners and versioned explicit acknowledgment form a usable scoped path. It must identify its requester as the authenticated API principal. It does not prove a T3 conversation, native parent consumption or Paperclip teammate identity.

The native fork contains useful per-call and forwarding protocol primitives, but its current production composition does not join them to an enrolled Control origin-attestation authority. Do not add an arbitrary `_meta` binding, signer, generic intent record or inferred `activeRunId`. Official Codex 0.167 source establishes host-tool advertisement support behind the experimental capability that T3 already requests. The missing generated field is a typed-binding gap, not a proven missing native protocol capability. That bounded typed-wire correction is now built and qualified in isolated source; original-call connection retention and native-origin authority remain required before Executive dispatch can be composed.

## Smallest grounded native change

Implement initially for the provider whose actual host callback is qualified, rather than claiming every T3 provider can attest the same context.

1. **Capture at the native provider owner.** In `CodexAdapterV2`, a genuinely advertised host tool would receive the existing `item/tool/call` request. Resolve its exact native `turnId` in `activeTurns`, compare native `threadId` to the retained provider thread, preserve opaque `callId`, and derive T3 project/thread/run/root/parent from that original context and projection. Do not fall back to the latest active run or adopt a settled/background context. Native descendant support needs its own actual context proof; refuse unsupported cases.
2. **Use the original captured Control connection.** Official Codex `ToolInvocation.step_context.mcp` already retains an `Arc<McpBinding>` for the exact sampling request. Its `PreparedMcpCall` owns client/catalog/permission authority. The current host `mcpServer/tool/call` instead refreshes configuration and calls `latest_call_tool`, so capturing T3's provider client object is insufficient. Extend the incumbent pending dynamic-call entry to retain the original invocation's binding/evidence and resolve a closed original-call forwarding operation there; do not add another connection registry. The target and enrolled source authority must be host-owned. Ordinary model arguments and generic `McpAppCallToolInput` must not gain authority through `_meta`.
3. **Verify at the existing App/Control ingress.** The current COO principal/Unix App peer is insufficient to attest T3 origin. Extend only the actual enrolled connection/profile owner once it can establish that the source is the native host authorized to make these statements. The App must verify that authority and compare command, selected target, principal binding, mission and capability generation before constructing the closed CeoIngress frame. An ordinary COO caller carrying identical metadata must be refused as a native origin.
4. **Freeze under the original operation.** Keep the existing selected-child command and target as the sole dispatch identity. Store the validated requester binding through that operation's existing owner before effect. Replay returns the original receipt; changed native call/run/connection or changed command/target/principal is a conflict. A lost response reads the original command; it does not dispatch another child. No second queue, route, alias, retry owner or source-intent table is needed.
5. **Retain truthful return semantics.** WorkerBroker execution keeps its real workspace, artifact, validation and seal evidence. Its requester may be T3 only when the new source proof is actually installed. Delivery to a native session is separate from native parent consumption. The already qualified API-principal acknowledgment must remain a separate family.

The prerequisite equality facts already exist: `selected_child_status` exposes original command/target before claim; [coo_principal_mandate.py](https://github.com/mastermindx-market-intelligence/Mastermind/blob/395fa9820a733e6d3263b4164f00a7849e5a35b6/control_plane/coo_principal_mandate.py), blob `2a482c48cde5ae8047c21d82a6708a40c714dede`, exposes the actual principal-binding digest and mission/authority generation. These are comparison inputs, not new grants.

## Capability negotiation and qualification

Native-origin dispatch remains unavailable until both the actual provider host-tool composition and the Control connection's origin-attestation authority are proven. The frozen `native-dynamic-tools-bindings.patch`, SHA256 `8a876d72d98f48ffa689f2b5145faed7e824806c03d1a9f010573402744c1c43`, preserves the generator's pinned stable baseline and adds only the source-supported experimental input. Ten focused client/schema tests, package typecheck, scoped lint and exact patch application pass. This is typed codec proof, not a real provider callback or native backend run. Do not bypass the typed client, broaden every experimental field, or claim installed support from source negotiation alone. A shared or interrupted initialization must preserve the original connection's actual capability ownership; an `Already initialized` response is not a fresh capability acknowledgment.

Required tests must enter the real provider callback, actual captured MCP forwarder, authenticated App ingress and canonical selected-child service. Prove the same original command reaches WorkerBroker custody once and its result returns to its original requester family. Negative cases: external OAuth client masquerading as native; correct-looking metadata under an ordinary COO principal; foreign native thread/turn/call; settled or ambiguous background context; native descendant without context proof; switched endpoint/connection; changed target/principal/capability generation; concurrent identical and conflicting requests; original lost response; old-connection replay after revocation; cancellation while forwarding; complete original result readback; API ACK without any native-consumption claim. Unsupported protocol negotiation must make zero dispatch calls.

No native service, credential, signer, event, provider worker, fork ref or live profile was changed. Fork publication remains ungranted for the two inspected pull-only identities. Publication, isolated qualification and activation remain separate from source readiness, and the existing app/profile/uncertain-effect holds remain in force.
