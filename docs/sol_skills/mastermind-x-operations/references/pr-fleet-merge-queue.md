# PR, CI and protected delivery

Use the target repository's current AGENTS.md and delivery owner from the verified protected pin. Mastermind, Macro and Terminal have different enrolled admission paths. This reference diagnoses their source/evidence states; it does not establish a new queue controller or waive a required check, review, security hold or uncertain effect.

## Recover the original PR

Read the exact head and receiving ref, draft/base state, complete relevant discussion and actual reviews, pending effects and admission state. Preserve the original branch and stack. Historical authorship alone is not a live-writer lock; a current writer or unresolved operation is not cleared by age.

A requested reviewer is not a submitted review. A source self-check is not a formal approval. Where formal approval is actually mandatory, verify the authorized non-author login, all authors/coauthors, prior reviews and exact head. Never self-approve, impersonate, duplicate an uncertain review or invent a named-seat restriction.

Use bounded comparisons and qualify completeness. GitHub comparison/file pages can be capped; a truncated diff cannot prove that a source is incorporated or that no overlap exists. Preserve parent contributions and acceptance evidence before retargeting or closing a stacked PR.

## Read checks as evidence

Read the check's name/app, exact source, tested merge/tree, run/attempt, conclusion and complete decisive output. RUNNING or queued is not failure or success. Workflow success alone does not establish code-scanning clearance, required aggregate success, real-path proof or merge acceptance.

For a failed check, start with its actual summary/annotations and the original completed job log. Use an authorized run-log archive only when necessary to fill a concrete evidence gap. Do not replay a denied read through another account/tool. Record missing evidence accurately; do not infer success from empty logs.

Distinguish source/test failure, expected refusal, setup/download failure, rate limit and uncertain external effects. An attempt count does not make a security alert a false positive. Preserve assertions and required contexts; fix source defects rather than bypassing them.

A transient dependency download can justify one bounded failed-job recovery only after the original run/attempt, source and every affected effect are reconciled and the actual retry path is permitted. Check for another pending retry first. Preserve successful original evidence and retry only the qualified failure/dependents. Do not create empty commits or whole-workflow restarts merely to evade a rerun refusal, and do not retry an unclassified failure. An explicit safety or permission denial ends that action; this recovery clause grants no cross-account, transport or carrier replay.

For pytest E2BIG caused by oversized parameter IDs, qualify the actual environment and original failure. Short explicit parameter IDs can repair the transport size while preserving the payload and assertions. A newer local dependency that hides the failure is not a reproduction of the hosted environment.

## Compose actual conflicts

1. Pin the original head, receiving source and merge base. Inspect actual overlapping source and evidence, not only GitHub's cached mergeability flag.
2. Use the existing source operation and approved authoring route. For GitHub-native work, retain exact preimages and a nonforce expected-head update. For host-local work, retain installed workspace custody.
3. Resolve each semantic conflict while preserving accepted receiving behavior and unique branch work. Whole-file or marker-regex replacement is not a general repair. Adopt a receiver file wholesale only when complete comparison proves that no required branch contribution is lost.
4. Preserve registry source/hash pairs and the meaning of unknown, failed, unavailable and missing states. Run the relevant consumer validation; compiling a registry or collecting zero tests does not prove its contents.
5. Qualify the integration method actually used. A local merge with preserved ancestry and a later squash have different merge bases. Use an isolated, read-only prediction of the intended composition when needed, and label it a prediction.
6. Reuse old proof only where the acceptance contract and material inputs still match. Changed captured behavior requires the incumbent capture/real-path owner. Keep old identities and dates; do not splice or restamp artifacts as a new run.
7. Publish one coherent update with current custody and an exact expected head. If it races, stop and reconcile the actual ref/effect before further work. Never force-update shared history, discard a live workspace or move to a new carrier to evade a refusal.

A conflict can persist despite green tests. Diagnose the actual source overlap; do not assume every conflict is timing-only. Other open PRs are not automatically live writers or a reason to wait for an empty fleet. Check material overlapping activity and use the incumbent integration/admission owner.

## Admit once and verify without mutation

For Mastermind, after current source, required checks, applicable review and hold gates are satisfied, the normal owner uses one exact-head auto/squash request:

    gh pr merge <number> --repo mastermindx-market-intelligence/Mastermind --auto --squash --match-head-commit <full-head-sha>

This command is an action, not a status probe. Do not repeat it to obtain an already-queued message. Read the actual auto-merge request, native queue entry/timeline and current head through the authorized read interface. An auto request can clear when the PR enters the queue; AUTO=null alone does not prove absence. A queued PR is not merged.

Macro follows its existing MOG Arm-Last contract; an auto-merge shortcut can have different effects and must not substitute for that owner. Terminal follows its own current controller/native-queue contract. Do not copy one repository's commands into another.

Do not use admin merge, protection bypass, generic close/reopen eviction or branch replacement. If an existing queued head needs source repair, use the target owner's current documented control path, with the original request/effect reconciled first. A terminal eviction may require a new admission, but only after its cause, current controls and original request are settled; do not blindly re-arm.

Verify acceptance from canonical merged state, mergedAt, merge commit and actual parent/tree evidence as required. Child-to-parent integration is not a protected-master merge and must not be counted twice. Deployment and live-product acceptance remain separate unless the mission includes and proves them.

## Keep observations bounded

Inspect a new completed controller/run when it resolves a named next action. Do not build a new watcher, poll an unchanged state indefinitely, override refresh capacity or call a chat process durable execution. While a lane waits for its existing executor, advance another authorized lane. Persist a compact source-linked frontier at material milestones, retaining uncertain effects and the exact next action.
