4. To memory, save only durable pointers (org name, hierarchy, governing-doc paths, integration state) — never copy repo-doc paragraphs into memory; the repo can change and a stale copy contradicts the pin rule.
5. **Origin-canon rule (Meta-CEO ruling 2026-11-08):** this skill's canonical copy lives at `docs/sol_skills/mastermind-x-operations/` on protected `master` in the Mastermind repo. Version bumps ship as reviewed lane PRs (announced in the exec thread; Meta-CEO promotes/ratifies as single writer); profile homes sync by pulling from origin — never hand-edit a sibling profile's copy and never treat any per-profile clone as newer than origin.

## Standing invariants (the contract; full detail is in AGENTS.md)
- **Paper-only.** Reasoning agents propose; deterministic engines own sizing, caps, settlement and release gates. Never auto-execute broker trades and never treat research as trade authority.
- **GitHub origin is truth.** Never push directly to `master`, never force-push shared branches, never deploy an arbitrary working directory. Ship reversible work as one coherent PR through the protected queue and finish it to exact merge readback — a Draft is not delivery.
- **Secrets.** Credentials live only in the OS credential store / `gh` keyring. Never write plaintext passwords, tokens or recovery codes to transcripts, prompts, logs, source, memory or handoffs.
- **Company memory lives in Macro's `agentos/`** — decisions (`DEC-*`), discoveries (`DSC-*`), handoffs ship as Macro PRs. Never create a second Agent OS store, a local decisions mirror, or a new plan registry. Ship them API-only per `references/macro-agentos-shipping.md` — never clone macro for a one-file record.
- **Honesty rules.** Surface contradictions between governance layers instead of routing around them; report failed approaches and nulls; a job is complete only when its named acceptance evidence exists — not because code was written or tests could not observe the change.

## Lane PR rules (editing `~/Mastermind`)
- Measure the blast radius before cutting the branch: grep the exact symbols (unit names, env names, channel ids) across the tree first — production code AND every package's test tree: other packages' tests re-encode roster-derived identities in golden lists and fixtures (harness doctor/e2e tests assert secretary's roster shape), so a roster change reds a package you never touched. Names can be dual-use — a Slack-transport unit name may ALSO be a runtime role profile wired through dozens of files; collapse only the transport plane and leave the role plane (e.g. `native_dialogue_consumer.ROLES`) untouched, so the logical roles survive behind the single identity.
- Roster law: identity and config values live in `roster.json`, never as code constants — new modules import the roster helpers (`channel_names()`, `default_roster()`) and re-run its fail-closed guard instead of writing identity rules of their own.
- Read the on-disk file before any config rewrite and patch only the block being changed — full-file rewrites diverge from the real rows (names drift from your draft) and get refused or clobber content the draft didn't know about.
- Test fixtures that write a secrets env file must satisfy `load_secrets`' full contract — it refuses files without a real-length, non-placeholder `HERMES_GATEWAY_TOKEN` (0600); a Slack-pair-only fixture makes the doctor report credential gaps and the suite red. Mirror the real file's shape, don't minimize it.
- **Extending a closed catalog (seats, roster-like sets):** grep for one existing member across code, tests, AND prose docs before writing — every surface enumerating the set must move together, and prose surfaces (e.g. `docs/hermes/EXECUTIVE_TEAM_CONTEXT.md`) have NO test guard unless a doc-guard test exists at your pin. Full procedure, coupling map, and byte-budget constraint: `references/hermes-leadership-catalog.md`.
- Verify suite reds against baseline: accepted pre-existing LOCAL failures are the `America/Cancun` tzdata wall-clock artifact in `test_routines` and the harness stack-boot test that binds `127.0.0.2` (macOS refuses the alias with Errno 49; Linux CI passes). Any OTHER red must reproduce on the pristine tree before it counts as pre-existing — `git stash`, rerun that exact test, `git stash pop`. Two stash pitfalls: untracked test files left behind fail against reverted code (not evidence), and a failing run can mutate tracked fixtures (mode bits on generated stubs), which blocks the pop — `git checkout --` the mutated file, then pop.
- Claim a PR green only from the suite CI actually runs: the harness CI jobs exercise all five integration packages, so run that same multi-package set locally before pushing — a green run scoped to the package you touched hides cross-package reds (see the blast-radius rule above).
- Triage a PR's merge state from the check rollup, never the summary flag: `mergeStateStatus` BLOCKED/UNSTABLE frequently means required jobs are still `IN_PROGRESS`, not failing — pull `gh pr view <n> --json statusCheckRollup` and treat IN_PROGRESS-with-no-conclusion as "cooking", not red. The Hermes offline stack jobs (3.12/3.13) run 10+ minutes; corroborate with the run's `createdAt` vs the current time before declaring a PR blocked, and re-read after the longest job's window before escalating or "fixing" anything.
- Stage paths explicitly — the worktree carries untracked sibling checkouts (e.g. a `macro/` dir) that `git add -A` would swallow.
- Ship docs-only records (enrollment records, durable notes) from a separate worktree cut fresh from `origin/master` — `git worktree add -b <branch> <path> origin/master` — never from the active lane checkout, so an open PR's branch is never disturbed. A PR stacked on your branch head inherits your amendments as same-line conflicts — after pushing a new head, steer the stacked child to rebase onto it before it pushes (details in `references/hermes-leadership-catalog.md`).
- **CodeQL code-scanning alerts on a PR** are a separate gate from the CodeQL workflow: the workflow can show `pass`/`skipping` while the 3-second `CodeQL` check fails on open alerts. Enumerate with `gh api repos/<o>/<r>/code-scanning/alerts?ref=refs/pull/<n>/head&state=open` — alerts re-number and re-point to the latest analysis commit as sinks shift, so re-enumerate after every push. Inline suppression: a trailing `# lgtm[<rule-id>]` comment works only when it is the ENTIRE comment content and sits on the single-line sink — `# lgtm[x] # codeql[x]` is one Python comment with trailing text and NEVER parses; the `# codeql[x]` form did not bind on GitHub's bundle; multi-line call sinks (e.g. `unittest.mock.patch.dict(os.environ, {...})` flagged as `py/clear-text-storage-sensitive-data`) don't bind pragmas at all. After two failed annotation attempts, dismiss via `gh api -X PATCH repos/<o>/<r>/code-scanning/alerts/<n> -f state=dismissed -f dismissed_reason="used in tests" -f dismissed_comment="…"` — reason enum uses spaces ("false positive", "used in tests"), comment hard-capped at 280 chars; pair the dismissal with a runtime `assert TOKEN not in rendered` guard on the real sinks so it's defensible.
- **Racing carrier on a shared PR branch**: verify the true head with `gh pr view --json headRefOid` before every push; local `git fetch origin <branch>` can return STALE tips mid-race (full-40-char-SHA fetch works, short SHA refused). Never force-push your history over theirs — fetch their head by full SHA, `git checkout -B fixbase <sha>`, cherry-pick/re-merge on top, then push (fast-forward when possible; else force-with-lease keyed to the ls-remote SHA). A carrier push cancels your in-progress CI runs (a `cancelled` run's shard failures are moot). Leave a PR comment asking them to rebase over your head; if they compose your commits into theirs, keep stacking on their head. `gh pr create` from a worktree checkout mis-detects the pushed branch even after `git push -u origin <branch>` — always pass `--head <branch>`.
- **Merge-queue and protected-branch delivery:** the repo is squash-only (rebase and merge-commit disallowed repo-wide), carrier head branches reject even admin pushes — deliver fixes as stacked PRs, never direct push — and the default-branch queue cannot be bypassed even with `--admin` (checks + queue admission is the only path onto master). A queued PR freezes its head branch; evict with `gh pr close` (nothing else works). A squash-merged conflict resolution does NOT clear the textual conflict — relocate your additions until the contested region is byte-identical to the other side, Before pushing, gate on a SQUASH-EQUIVALENT probe — `X=$(git commit-tree HEAD^{tree} -p <carrier-head>)`, then `git merge-tree --write-tree origin/master $X` (two refs; a third is a usage error that mimics "conflict") — because merging master into the fix branch makes a plain merge-tree on HEAD report a false clean (GitHub's squash discards that ancestry); and converge to plain master only when the queue is EMPTY (convergence-target law in the reference). Queue admission is verified by re-running the same merge command: `! ... is already queued to merge` is the confirmed-enqueued readback — the REST `merges` endpoint 404s regardless of preview headers, so don't use it to check queue state. Queue mechanics, the full delivery cycle, the CI log-forensics ladder, E2BIG-class parametrize failures, and read-only watcher delegation: `references/pr-fleet-merge-queue.md`.
