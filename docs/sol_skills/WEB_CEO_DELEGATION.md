This is a working approach, not a new Runtime role, frontier classification, reasoning-mode class or provider grant. ## 2. Make a delegation decision before substantial routine execution

A work unit is delegable when an independent eligible worker can acquire the necessary inputs, operate within a bounded scope and return checkable evidence without deciding a reserved principal/Chairman question; an investigation may have an unknown answer — specify question, falsifier and evidence rather than pretending the solution is already known. Compare the whole completion cycle (framing + delegation + implementation + review + expected clarification/repair + integration + principal consumption), including actual shared-pool scarcity, worker latency and useful independent work the principal can advance meanwhile. Delegate when total useful progress improves without lowering quality; never to meet an agent-count quota or save nominal tokens at the expense of acceptance. Apply ACTIVE_EXECUTION Step 2A for the direct-work reason labels (`LOWER_TOTAL_OVERHEAD`, `PRINCIPAL_JUDGMENT`, `UNIQUE_APPROVED_ACCESS`, `CRITICAL_PATH_SHORTCUT`, `NO_ELIGIBLE_PRE_EFFECT_WORKER`) and their reassessment triggers.
