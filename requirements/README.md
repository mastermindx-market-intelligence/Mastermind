# Hash-locked test-gate environments (RWE-P0)

This directory holds per-platform, hash-pinned `pip` lockfiles for the
**repository test-gate environment only** -- the pilot scope of
`research/REPRODUCIBLE_WORKER_ENVIRONMENTS_MASTERPLAN_V1.md` §5-6 (macro
repo). Nothing here changes the existing `pip install -e ".[dev]"` path used
by `.github/workflows/ci.yml` today; these locks are consumed exclusively by
the new `scripts/rwe_env.py` task interface and the shadow CI job in
`.github/workflows/rwe-shadow.yml`.

## What a lock is

Each `gate-<os>-<arch>-py312.lock` is generated by `pip-compile
--generate-hashes` from the repository's `pyproject.toml` (`dev` extra). It
pins every package to an exact version with per-artifact `--hash=sha256:...`
entries, so `pip install --require-hashes --only-binary=:all: -r <lock>`
either installs byte-identical wheels or refuses outright -- there is no
silent drift between two installs of the same lock. Each lock's header
records the platform, the interpreter it was compiled for, the source
`pyproject.toml` sha256 at mint time, and the exact regeneration command.

Current locks:

- `gate-macos-arm64-py312.lock` -- darwin/arm64, CPython 3.12 (Homebrew
  `/opt/homebrew/bin/python3.12`).
- `gate-linux-x86_64-py312.lock` -- linux/x86_64, CPython 3.12 (hosted-CI
  tool-cache interpreter). Minted by the bootstrap run of
  `.github/workflows/rwe-shadow.yml` (its `linux-lock` artifact) and
  committed here. If this file is ever removed, the workflow's bootstrap
  step mints and uploads a fresh one again automatically.

## How to regenerate

`python scripts/rwe_env.py lock` prints the exact `pip-compile` command for
whatever platform you are running on -- it never runs the command for you,
because minting a new lock is a deliberate, reviewed act (it hits PyPI over
the network and can take several minutes: pip-tools hashes every
distributable wheel/sdist for the resolved version across every supported
platform tag, not just the current one). Typical invocation from the repo
root:

```
pip-compile --quiet --generate-hashes --extra dev \
    --output-file requirements/gate-macos-arm64-py312.lock pyproject.toml
```

Regenerate whenever `pyproject.toml`'s dependencies change, or when picking
up a security fix. The lock's header sha256 lets anyone check whether a lock
is stale relative to the `pyproject.toml` that produced it.

## Using a lock

See `docs/RWE_RUNBOOK.md` for the full realize/gate walkthrough. Short
version:

```
python scripts/rwe_env.py realize --dest /path/to/venv
python scripts/rwe_env.py gate --env /path/to/venv
```
